# swarm-files — файлы к задачам на MUSPELHEIM

Хранилище байтов для файлов к задачам (#638). Почему здесь, а не в Supabase, —
[решение владельца](../docs/decisions/2026-09-30-task-files-on-muspelheim.md): экономия на
хранилище, цена — файлы недоступны, пока у сервера нет света или сети.

## Как устроено

```
браузер ──POST /tasks/:id/files──▶ swarm-api ── права (canViewTask), строка task_files: uploading
   │                                   │
   │◀──────── upload_url (подпись Ed25519, 15 мин, лимит = размер файла) ─┘
   │
   └──PUT байты──▶ Funnel :10000/swarm-files ──▶ swarm-files (127.0.0.1:8031) ──▶ C:\projects\swarm-files\data\<uuid>
   │
   └──POST …/complete──▶ swarm-api ──HEAD──▶ swarm-files: размер сошёлся → ready
```

- Сервис базы не знает и прав не проверяет — только подпись ссылки (`_shared/files-token.ts`).
  На сервере лежит лишь открытый ключ: утечка с MUSPELHEIM не даёт выпустить ни одной ссылки.
- Объект пишется один раз (повторный PUT — 409), больше лимита из ссылки — 413, и частичный
  файл не остаётся. Скачивание — с `nosniff` и `Content-Security-Policy: sandbox`: даже открытый
  в браузере файл не выполнит скрипт. В браузере открываются только PDF и картинки.
- Имя файла на диске — uuid; настоящее имя живёт в `task_files` и приходит в ссылке на скачивание.

## Раскатка (по «да» владельца, в окно 23:00–06:59)

1. Миграция `20260930090000_task_files.sql` и функция `swarm-api` — обычной ночной раскаткой.
2. Кнопка **«Ключ файлов задач»** (`files-signing-key.yml`) — пара ключей, закрытый уходит в
   секреты функций вместе с `FILES_BASE_URL`, открытый печатается в сводке прогона.
3. `FILES_PUBLIC_KEY=<из сводки> scripts/swarm-files.sh key` — открытый ключ на сервер.
4. `scripts/swarm-files.sh up` — клон `main`, сборка, запуск (порт только на localhost).
5. `scripts/swarm-files.sh publish` — путь `/swarm-files` на Funnel-порту 10000 (соседние
   пути порта, например `/qr`, не трогаются; сверить `tailscale serve status` до и после).
6. `scripts/swarm-files.sh status` — контейнер жив, `…/swarm-files/health` снаружи отвечает 200.

Ротация ключа — шаги 2–4 заново: старые ссылки гаснут, когда сервер получит новый открытый ключ.

## Лимиты

`TASK_FILES_MAX_MB` (50) и `TASK_FILES_MAX_COUNT` (10) — в секретах функций. Сервис своего
лимита не держит: он берёт его из подписанной ссылки, поэтому правится одно место.

## Чего нет

- **Бэкапа файлов.** Ночной «PG Docker Backup» снимает только базы — задача #652.
- Физического удаления: «Убрать» архивирует строку, байты остаются на диске.
