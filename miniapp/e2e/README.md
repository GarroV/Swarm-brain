# Смоук мобильного интерфейса

Ручной набор для проверки того, что ломалось живьём и не ловится type-check'ом: жесты списка
(скролл против тапа), доступность разделов, проекты, встречи, компактные фильтры. Гоняется
локально — CI по Actions заморожен до 01.09.2026 (см. `docs/BACKLOG.md`).

## Зачем именно браузер

Баг, с которого началась работа, воспроизводится **только** реальным touch-жестом: при
вертикальном скролле браузер забирает жест себе и присылает `pointercancel`, а не `pointerup`.
Юнит-тест на React-обработчиках такого не покажет — поэтому проверки идут touch-событиями через
CDP (`Input.dispatchTouchEvent`), а не `page.mouse` и не синтетическими React-событиями.

## Запуск

```bash
cd miniapp
npx next dev -p 3111      # в отдельном терминале: DEV_MODE-моки, прод не задействован
node e2e/mobile-nav.mjs
```

Набор **сам поднимает Chrome** на временном профиле и закрывает его в конце. Так сделано не от
любви к лишним процессам: у долгоживущего инстанса ломается ввод — после нескольких прогонов
(особенно после группы с десктопным вьюпортом, где `hasTouch=false`) `Input.dispatchTouchEvent`
начинает висеть до таймаута на любом жесте, и лечится это только перезапуском браузера. Поймано
на себе: 42/42, 42/42, затем «touch timeout» на первом свайпе.

Выход `0` — всё зелёное; `1` — падение проверки или ошибка в консоли страницы (ошибки консоли
считаются падением: молчаливый `pageerror` в проде выглядит как «просто ничего не произошло»);
`2` — браузер не принимает касания (актуально только при подключении к внешнему инстансу).

## Переменные

| Переменная | Дефолт | Зачем |
|---|---|---|
| `SWARM_E2E_URL` | `http://localhost:3111/` | адрес приложения |
| `SWARM_E2E_HEADED` | не задана | `=1` — видимое окно, когда хочется смотреть глазами |
| `SWARM_E2E_CHROME` | `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` | путь к браузеру |
| `SWARM_E2E_CDP` | не задана | подключиться к УЖЕ запущенному браузеру вместо своего (напр. `http://127.0.0.1:9333`) |

`puppeteer-core` в зависимостях miniapp **не** держим: `e2e/lib.mjs` берёт его из проекта, если он
есть, иначе из кэша `~/.npm/_npx`. Нет ни там, ни там — `npm i -D puppeteer-core`.

## Наборы

| Файл | Что проверяет |
|---|---|
| `mobile-nav.mjs` | каркас: жесты списка, табы, поиск и уведомления, проекты, встречи, плотность, десктоп (43 проверки) |

## Что проверяется (mobile-nav, 43 проверки)

| Группа | Проверки |
|---|---|
| Жесты строки | список длиннее экрана (иначе проверка скролла ничего не проверяет); вертикальный свайп скроллит и не открывает задачу; тап открывает; горизонтальный свайп открывает шторку и не открывает задачу; тап при открытой шторке её закрывает |
| Каркас | набор табов (Задачи · Проекты · Встречи · Ещё); дом — задачи; поиск и колокольчик уведомлений доступны с каждого таба; поиск доходит до ответа; все пункты «Ещё» на месте; настройки открываются; миграция старых значений `roy_tab` (`search`→Задачи, `book`→Ещё) |
| Проекты | список с прогрессом; вход в проект; быстрое добавление создаёт задачу именно в проекте |
| Встречи | заголовок выше очереди вычитки; даты без ISO (и в списке, и в вычитке); ни одной открытой кнопки удаления в строках (всё через свайп); тап по черновику открывает вычитку и из неё есть выход; вертикальный свайп не открывает встречу; тап открывает; правка названия/тезисов и выбор «Общее/Личное» у несогласованной на месте |
| Плотность | управление до первой строки ≤165px (было 199); тач-цель чекбокса ≥38×44 (было 19×19); один FAB на экране; меню охвата содержит линзу, группировку и админ-тумблер; созданная задача без срока видна сразу |
| Десктоп | дашборд-дом на месте, мобильный таб-бар скрыт |

## Ввод текста — только настоящей клавиатурой

Синтетический `input` обновляет состояние React, но путь автосохранения карточки задачи на нём
не срабатывал: правка молча терялась, а проверка была бы «зелёной». Поэтому `deep-flows`
печатает через `page.keyboard` — так же, как это делает палец.

## Правила, по которым он написан

- **Ждать условие, а не миллисекунды.** Фиксированные паузы давали плавающие падения на
  исправном продукте (возврат из вычитки не успевал за 1200мс) — для таких мест есть `waitFor`.
- **Подготовку данных задавать явно.** Вид списка выставляется через `roy_tasks_view` перед
  прогоном: на дефолте «Мои/Сегодня» в моках одна строка, и проверка «скроллится ли список»
  проходила бы зелёной, ничего не проверив.
- **Не проверять «кнопки нет в DOM», если она просто скрыта.** Кнопки свайпа физически есть —
  проверяется, что сверху в их точке лежит контент строки (`elementFromPoint`).
