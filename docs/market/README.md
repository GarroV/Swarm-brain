# «Анализ рынка»: как собирается страна

Раздел показывает рынок быстрого питания страны по образцу хорватского отчёта:
карту сетей, открытия и закрытия, пицца-конкурентов, доставку, выручки
операторов и реестр точек. Устройство экрана и таблиц описано в
[ARCHITECTURE §Анализ рынка](../ARCHITECTURE.md#анализ-рынка), решения владельца
— в
[decisions/2026-10-02-market-follow-reference-visual.md](../decisions/2026-10-02-market-follow-reference-visual.md).

Этот файл про другое: как довести новую страну до того же уровня и сделать так,
чтобы через год её можно было обновить без раскопок.

Данные ручных источников и внутренние выгрузки Dodo в репозиторий не попадают:
репозиторий публичный.

Ручная запись проверяется тем же чистым разборщиком, что экран:
`_shared/market/editorial-view.ts` (веб реэкспортирует его из
`lib/marketEditorial.ts`). Если строка или присланное поле после разбора
исчезнет, `market_set_block` и импорт отказывают с путём к ошибке; старое
содержимое остаётся в базе. Корректные альтернативные имена оценок и платформы
без годов выручки поддерживаются. Год входа `pizza_table.entry` передаётся
строкой, закрытие в `events.kind` — `exit`; полный формат и примеры —
`market_template`. Для `market_set_price` обязателен `item_type` из общего для
записи и матрицы цен перечня `_shared/market/price-types.ts`: `margherita`,
`pepperoni`, `ham_mushroom`, `premium`. Неизвестный или отсутствующий тип
отказывается до запроса курса и записи цены (#1132).

## Порядок работы по стране

1. **Разведка.** Сети страны (международные и локальные от 3 точек, пекарни
   отдельно), покрытие OpenStreetMap по каждой сети, локаторы сетей с JSON,
   реестр юрлиц и доступ к отчётности, доставка, цены, события 2021+. Результат
   — `research/<CC>.md` и `<CC>/sources.json` во workbench.
2. **Конфиг.** `countries/<CC>.ts`: сети с `osmBrands`, юрлица с рег. номерами,
   источники. У каждого источника — `url`, `note` (что именно берём) и `checked`
   (дата сверки), если это не очевидно из адаптера. Пересобрать SOURCES.md.
3. **Автоматика сначала.** Всё, что берётся детерминированно, — адаптером по
   расписанию: OSM, API Dodo, реестры с открытыми данными или API. Новый адаптер
   — `adapters/<id>.ts` с `about` и тестом на фикстуре.
4. **Модель — только где без неё никак** (решение владельца: ключ OpenAI один,
   расход минимальный). Поиск локальных сетей и дат открытия, разбор отчёта без
   машинного формата, тексты ручной части. Результат модели сохраняется и
   повторно не запрашивается, пока не изменился вход; попадает в очередь
   кандидатов, человек принимает.
5. **Ручная часть** — в Claude Desktop через коннектор Swarm: `market_template`
   → `market_status <CC>` → запись по разделам (`market_set_block`,
   `market_set_company_year`, `market_upsert_location`, `market_upsert_chain`,
   `market_set_price`, `market_add_fact`). Источник у каждой записи обязателен,
   на экране — сразу. Сборщики при этом продолжают работать и проверенное руками
   не трогают.
6. **Сверка.** Прогнать `parity.sql` и сравнить строку страны с Хорватией
   (таблица ниже); проверить экран на стенде в обеих темах и на телефоне. Где
   страница беднее — либо дособрать, либо записать причину в таблицу «Дыры».

## Страны на Overture Maps (ES, PL, LT, CY, HU, MD, BY, GE, AM, AZ)

Решение владельца: только автоматика, вся Европа. Публичный Overpass на больших
странах падает по памяти, поэтому у этих стран в конфиге `mapSource: "overture"`
и `bbox` (запад, юг, восток, север), а источник карты — адаптер `overture`
вместо `osm-overpass` (`dueAdapters` строку `osm-overpass` у такой страны не
запускает). Адаптер берёт последний релиз Overture (parquet в S3, DuckDB под
Deno), заведения общепита и пекарни страны в bbox без закрытых, точка — центр
bbox объекта, `osm_id` = id места в Overture. Сети из конфига (Dodo и
международные, `osmBrands`/`osmNames`, суффикс страны в бренде допускается)
ложатся на свои ключи; остальные сети адаптер находит сам: бренд от 3 точек, без
бренда — от 5 точек в 3 населённых пунктах, до 40 сетей, сегмент по названию и
категории. Найденные сети уходят в нагрузке полем `chains` (`DiscoveredChain`),
сервер заводит их в реестре сетей. Dodo берётся из API Dodo, из Overture
пропускается. Юрлица и отчётность у этих стран не собираются (`companies: []`).
Для PL, HU, MD, BY у Dodo выручка приходит в злотых, форинтах, леях и
белорусских рублях: злотый и форинт — по месячному курсу ЕЦБ, MDL и BYN — по
курсам национальных банков (см. «Курсы валют вне ЕЦБ»). Запуск локально:
`deno run -A scripts/market/run.ts --country LT --source overture --dry-run`.

### Грузия, Армения, Азербайджан, Кыргызстан, Таджикистан (разведка 03.11.2026)

GE, AM, AZ — на Overture (по 136–323 точки, местные сети находятся сами; в
конфиг добавлены только международные и крупные сети, чьи варианты написания в
Overture расходятся: Papa John's, Wendy's, Dunkin', Tashir Pizza). KG и TJ — на
**OSM**: Overture даёт там 41 и 4 точки против 2198 и 1025 заведений с именем в
OSM; у локальных сетей тега brand нет, поэтому `osmNames` (кириллица и
латиница), общие названия («Столовая», «Ошхона», «Чайхана») сетью не считаем. В
Таджикистане сетей почти нет (KFC, TajBurger, SFC, Шоколадница). Валюта выручки
Dodo — GEL, AMD, AZN, KGS, TJS: ЕЦБ курса не публикует, евро-колонка выручки
пустая (как у MDL и BYN). Юрлица не собираем. Запуск:
`deno run -A scripts/market/run.ts --country GE --dry-run`.

### Имена брендов и дубли Overture

McCafé / McCafe в конфигурациях ES, PL, HU — альтернативные имена `mcdonalds`
(#896), а не отдельная сеть. Дубли внутри одного пакета проходят тот же
`samePlace`, что сопоставление источников: близость 25 м или совпадающий адрес в
пределах существующего допуска 5 км. Это устраняет завышение числа точек при
разъехавшихся координатах одного адреса (#1113, только часть про дубли). Прежние
пороги обнаружения (3 брендированных точки либо 5 точек в 3 населённых пунктах
без бренда) считаются после дедупа: несколько записей одного места не создают
фиктивную сеть. Общие имена без `brand` — ровно «кофейня», «пиццерия», «кафе»,
«столовая», `pizzeria`, `kebab` после существующей нормализации — отсекаются до
объединения групп (#1134). Они не могут попасть в брендированную группу с тем же
именем. Совпадение с конфигом проверяется первым; явный бренд сохраняется. Поиск
не использует префикс или подстроку: `Pizzeria Gino`, `Bistro Lux` и именованные
сети остаются. Пороги и сегменты этой правкой не меняются.

Фирменные магазины производителей не сеть общепита (#1134, решение владельца
07.11.2026: «магазины кондитерских выкидываем»). Категория Overture их не выдаёт
— у них та же `casual_eatery`, что у обычных кафе, — поэтому отсев по названию
или бренду, до обнаружения сетей и после проверки конфига: форма юрлица
заглавными (`ОАО`, `ЗАО`, `ООО`, `ОДО`, `АО`), «кондитерская фабрика», либо
запись в `manufacturerShops` конфига страны (фрагмент названия или бренда →
причина; сейчас в `BY.ts`: «Красный пищевик», «Коммунарка», «Слодыч»). Такие
заведения не попадают ни точками, ни найденной сетью. Пекарни и кафе с обычными
названиями остаются. Новая фабрика без формы юрлица в названии — одна строка в
`manufacturerShops`. Правило заведено только для Беларуси; остальные страны не
затронуты.

McCafé — не сеть и не вторая точка McDonald's, а пометка на точке `mcdonalds`
(решение владельца 07.11.2026): в `mkt_locations.format` стоит `with McCafé`, на
экране — «с McCafé» / "with McCafé" (карта, реестр, подсказка таймлайна; в
классификации формата для трендов пометка не участвует). Сборщик Overture
склеивает McCafé и McDonald's в одну точку, если они ближе 25 м, на одном адресе
(допуск 5 км) или ближе 50 м, пока номера домов не спорят (`MCCAFE_PAIR_M`);
остаётся строка McDonald's, пометка не теряется. Одинокий McCafé остаётся точкой
`mcdonalds` с той же пометкой. `market-ingest` пишет `format` у новых машинных
точек и обновляет его у совпавших: ставит пометку, снимает, если McCafé в ответе
больше нет; чужой формат (снимок, рука) не трогает. Data-only миграция
[`20261107230000_market_mccafe_flag.sql`](../../supabase/migrations/20261107230000_market_mccafe_flag.sql)
переводит уже накопленное: парный McCafé открытой машинной точки удаляется, а у
McDonald's появляется пометка; остальные McCafé получают пометку; шесть точных
дублей (ES Burger King CC Diversia, HU Pizza Hut Könyves Kálmán körút 12 и
Pünkösdfürdő utca 52, KG Mubarak, RO KFC Bulevardul Traian 5, SI Žito Slovenska
cesta 58) теряют более позднюю строку. Строку, на которую ссылаются
`mkt_ratings` или `mkt_candidates`, миграция не удаляет — пара пропускается.
Повторный запуск ничего не меняет.

Остальные пункты #1113 — качество брендов, пороги обнаружения и граница CY —
этой правкой не решаются.

Старые автоматические `mccafe` исправляет data-only миграция
[`20261106183721_market_mccafe.sql`](../../supabase/migrations/20261106183721_market_mccafe.sql):
отдельные и исторические точки переходят к `mcdonalds` с сохранением ID и полей;
живой непроверенный машинный двойник без дат и ручных пометок удаляется, если
каноническая точка уже есть по тому же правилу места. При неожиданных ручных
метаданных сети, ценах/других ссылках или отсутствии канонической сети миграция
отказывает целиком вместо потери данных. Повторный запуск ничего не меняет.
Проверка — `mccafe-migration.db.test.ts` на изолированной БД; прод эта ветка не
меняет.

Ложную BY-сеть `chain-кофеиня` исправляет отдельная data-only миграция
[`20261106215609_market_by_generic_chain.sql`](../../supabase/migrations/20261106215609_market_by_generic_chain.sql).
Она удаляет только восемь зафиксированных UUID непроверенных машинных точек и их
сеть: до удаления сравниваются полный состав и хеши бизнес-полей JSONB с полной
точностью чисел (`extra_float_digits=3`). Исключены лишь временные метки
свежести источника; `missing_weeks` входит в CAS. Любые ручные поля, изменение
снимка или связи с ценами, компаниями, рейтингами, источниками, редакционными
блоками, кандидатами и фактами останавливают миграцию целиком. На время проверки
и удаления записи рынка защищены от конкурентной записи табличными блокировками
с `lock_timeout=5s`. Настройки точности чисел и ожидания блокировок вызывающей
транзакции возвращаются перед успешным выходом, включая no-op; при ошибке их
возвращает rollback/savepoint. Другие сети, страны, фирменные магазины и ручная
курация не исправляются. Отсутствующая сеть — no-op, повторный запуск безопасен.
Проверка — `overture-generic-migration.db.test.ts`; публичный автоматический
снимок Overture сохранён в тестовой фикстуре.
`overture-generic-consumer.db.test.ts` дополнительно вызывает настоящий
`loadCountry` через изолированный Supabase до и после SQL: сеть и восемь точек
пропадают из ответа, остальные сети и страны сохраняются. Клиент читает только
REST API тестового контура, без операций аутентификации.

Две BY-сети, найденные из таких магазинов (`chain-кондитерская` — 31 точка,
`chain-коммунарка` — 14), удаляет data-only миграция
[`20261107120000_market_by_manufacturer_shops.sql`](../../supabase/migrations/20261107120000_market_by_manufacturer_shops.sql)
по той же схеме, что миграция выше: хеши бизнес-полей сети и каждой точки (CAS),
отказ целиком при ручных полях и ссылках (цены, компании, рейтинги, источники,
редакционные блоки, кандидаты, факты), блокировки с `lock_timeout=5s`, удаление
только после проверки обеих сетей, отсутствующая сеть — no-op. Если сборщик до
наката успел обновить точки (`missing_weeks`), снимок разойдётся и миграция
откажет — тогда снимок перечитывается с прода.

## Dodo: что даёт публичный API

`https://publicapi.dodois.io/<cc>/api/v1/`, без ключа. Есть для HR, RO, EE, RS,
SI, BG, ME, ES, PL, LT, CY, HU, MD, BY, GE, AM, AZ, KG, TJ.

- `unitinfo/all` — пиццерии: адрес, координаты, `BeginDateWork`.
  **`BeginDateWork` не всегда дата открытия**: в Хорватии API даёт 24.04.2023, а
  пиццерия открылась 22.03.2024 (журнал вычитки эталона). Уточнённая дата
  кладётся в ручную часть, блок `location_dates`.
- `FinancialMetrics` — выручка только за прошлый месяц, тот же месяц год назад и
  итоги года. **Помесячной истории выручки задним числом нет**: она копится
  еженедельным прогоном с момента подключения страны.
- `orders/countBySource/<y>/<m>/<d>` — заказы за день по каналам (сайт,
  приложение, ресторан, агрегатор, киоск) за любую прошлую дату. История заказов
  догружается один раз: `run.ts --source dodo-publicapi --since 2021-01-01`.

Суммы по каналам (средний чек по каналам, блок «операции Dodo» эталона) есть
только во внутренних выгрузках Dodo IS — их для страны даёт владелец.

## Курсы валют вне ЕЦБ

Единственный модуль — `supabase/functions/_shared/market/fx.ts` (им пользуются
сборщик Dodo и ручной ввод). Курс — «единиц валюты за 1 €», официальный курс EUR
национального банка, без кросса через доллар. Месяц — среднее дневных курсов;
год — среднее по 1, 8, 15 и 22 числу каждого месяца (у банков с диапазонным API
— по всем дням); день — курс на дату или последний опубликованный до неё (не
дальше недели).

источник цены и в `note` выручки. Курс не получен — запись отказывает с

обращения к банку. Выручка Dodo: курс месяца идёт в `rates` нагрузки, сам курс и
банк печатаются в журнале прогона (колонки для них в `mkt_dodo_monthly` нет).
