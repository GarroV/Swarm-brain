# Приёмка и выпуск Scriba push

Статус: подготовка в ветке `GarroV/scriba-push-2416`. Production не изменялся.
Связано: GarroV/backlog#2416 и#2415. Это не отчёт о завершённой раскатке.

## Состав

- `20261128010000_scriba_push_delivery.sql`: outbox, условный забор, устойчивое
  подтверждение, lease/CAS повторов, внутренний cron.
- `20261128020000_calendar_push.sql`: watch lifecycle, dirty queue, планы,
  будущие пропуски и транзакционная отмена pending jobs.
- `_shared/scriba-signals.ts`, `scriba-dispatch/`: доставка сигнала и ACK.
- `calendar-push/`, `_shared/calendar-push-*.ts`: Google webhook и планирование.
- `meeting-invite` / `meeting-calendar`: targeted `{id}`, затем `{id,started:true}`;
  прежние grant_token и проверки meeting-claim сохранены.
- Оркестратор: внутренний listener8091, без invite/calendar polling.
- `scripts/scriba-prod/configure-push.py`: по умолчанию проверка конфигурации;
  `--apply` — отдельный шаг согласованного выпуска, не запускать при подготовке.

`started_at` означает терминальный результат dispatch: устойчиво созданный
контейнер или завершённый штатный отказ. Повтор до него разрешён только тому же
агенту; Docker name по id задания не позволяет создать второй контейнер.
Уже выполненная заявка встречи также терминальна, даже если контейнер завершён.

## Настройка будущего выпуска

На VPS общий SCRIBA_SIGNAL_SECRET находится вне git, одинаков у edge worker,
оркестратора и Vault (`scriba_signal_secret`). URL в Vault:
`scriba_functions_url=http://supabase-envoy:8000/functions/v1`.
Edge env: `SCRIBA_SIGNAL_URL=http://scriba-signals:8091/signal`,
`GOOGLE_CALENDAR_PUSH_URL=https://api.swarm-team.app/functions/v1/calendar-push`.
Секреты не передавать через argv и не выводить. Скрипт не перезаписывает
несовпадающие существующие секреты и не перезапускает службы.

Оркестратор и edge runtime соединяются через `swarm_default`; оркестратор имеет
alias `scriba-signals`. Egress proxy подключается к этой сети для внутреннего
API. Контейнеры встреч остаются в отдельных изолированных сетях. Порты listener
на хост не публикуются. Внутренний Envoy использует прежнюю авторизацию функций;
readonly запрос без токена до изменения конфигурации вернул401.

Cron `scriba-push-delivery` каждую минуту проверяет due-состояние в базе и только
при наличии работы вызывает внутренние функции. Пустой тик не идёт в Cloudflare.
Outbox lease90с, HTTP delivery30с, максимум3 параллельных сигнала за один проход.
Повтор начинается с5с и растёт до5мин, ограничен сроком приглашения.

Порядок после разрешения выпуска: проверить отсутствие активных встреч;
миграции → подготовить общую конфигурацию → функции → оркестратор. Старый
оркестратор с polling и новый targeted API несовместимы: переключать согласованно.
Автоматически менять production или включать freeze этим документом нельзя.

## Проверка после переключения

1. Ручное приглашение и задержка до входа бота.
2. Остановленный бот, постановка приглашения, восстановление: доставка из базы.
3. Двойной сигнал: один контейнер/одна встреча. Неверный секрет:401;
   listener не доступен извне VPS.
4. Настоящие Google watch notification и renewal: изменение, перенос, удаление;
   выключение автозапуска отменяет pending jobs и снимает канал.
5. Сохранились пропуски D015, arrival watchdog и нотисы участникам.
6. За сутки после выпуска сравнить Cloudflare Analytics с прежним фоном.

Живые Google watch/Meet и суточный профиль ещё не подтверждены. Результаты
изолированных проверок записываются отдельно и не заменяют эту приёмку.
