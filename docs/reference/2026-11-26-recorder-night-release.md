## Подготовленное переключение

В `supabase/functions/_shared/recorder-release.ts` номер 42 и контрольная сумма
архива меняются вместе. Этот модуль используют `swarm-recorder-version` и
`swarm-recorder-setup`: функция версий и установщик получают один и тот же
подтверждённый объект Storage. Изменение manifest само по себе не раскатывает
функции и не заменяет работающее приложение пользователя.

Целевые проверки переключения 26.11.2026 прошли:
`deno test -A supabase/functions/swarm-recorder-setup/script_test.ts` — 7 passed,
0 failed; `deno check` для `swarm-recorder-version/index.ts` и
`swarm-recorder-setup/index.ts` — успешно. Полный набор рекордера повторно не
запускался; подтверждённые проверки опубликованного архива используются повторно.

## Что остаётся для подтверждения production

1. Дождаться зелёных проверок PR переключения, слить его в разрешённом окне.
2. Выполнить штатную раскатку обеих функций из чистого актуального main по
   `docs/DEPLOY.md`, сохраняя проверки времени, активности и исходника.
3. Реальным GET подтвердить `swarm-recorder-version`: `build=42`, точные URL и
   SHA256; проверить ответ установщика и доступность выдаваемого архива.
4. Записать фактические ответы и результат проверки. Только после этого
   считать переключение production подтверждённым.

Работающий рекордер вручную не заменяется и не перезапускается. Существующий
запрет автообновления во время записи сохраняется. Доступность обновления не
подтверждает обновление всех офлайн-клиентов.
