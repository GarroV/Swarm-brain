# Веб-интерфейс «Рой» — Архитектура

> ⚠️ **Терминология (важно):** это **веб-интерфейс** — обычный сайт/PWA в браузере (`swarm-brain.pages.dev`), НЕ «Mini App». Вход как **Telegram Mini App внутри Telegram отключён** (~2026-07-15, коммит `53bd3ae` — бот ведёт на PWA). Слова «Mini App» ниже по тексту — это (а) историческое имя папки `miniapp/` и (б) спящий путь `initData`/`tma`, который ещё есть в коде, но точки входа не имеет (на удаление — см. `docs/BACKLOG.md`). **Живой вход — Telegram Login Widget → JWT-cookie в браузере.** Поверхностей у продукта три: веб-интерфейс, Telegram-бот, MCP.
>
> Статус: фронтенд реализован (2026-06-01), в проде на Cloudflare Pages (авто-деплой с `main`).

## Реализованный стек

```
Telegram Mini App (⚠️ СПЯЩИЙ — вход отключён; живой путь — Login Widget ниже)
        │
        │  Authorization: tma <initData>
        ▼
swarm-api  (Supabase Edge Function)
        │  - верифицирует initData (Telegram HMAC)
        │  - резолвит telegram_id → group_id
        │  - REST CRUD для задач
        ▼
_shared/tasks/db.ts  (общий движок)
        │
        ▼
Supabase DB (service_role_key, фильтр по group_id)
```

Режим: **поллинг** (фронтенд запрашивает данные сам). Realtime, RLS и Supabase Auth bridge не нужны.

## Аутентификация — два контекста

| Контекст | Способ | Поток |
|----------|--------|-------|
| Telegram Mini App **(⚠️ СПЯЩИЙ — вход отключён)** | `Authorization: tma <initData>` | код остался, но точки входа нет (Mini App выключен ~2026-07-15); живой путь — только строка ниже |
| Браузер / PWA (вариант B+) | httpOnly cookie `roj_session` (JWT) | `/login` → Telegram Login Widget → CF Function `auth/telegram` проверяет подпись → JWT в httpOnly cookie → прокси `/api/[[path]]` перекладывает cookie в `Authorization: Bearer` → swarm-api проверяет JWT |

**Почему прокси (B+):** miniapp — статика на Cloudflare Pages (нет Next API routes/middleware). httpOnly-cookie недоступна JS (защита от XSS) и не уходит cross-origin на `*.supabase.co`, поэтому CF Pages Function `functions/api/[[path]].ts` форвардит запросы на swarm-api server-side, перекладывая cookie → `Bearer`. JWT: HS256, секрет `WEB_JWT_SECRET` (общий у CF и Supabase). Login Widget подписывает данные секретом `SHA256(bot_token)` (иначе, чем Mini App).

Авторизация в обоих случаях одинакова: `telegram_id` → `allowed_users` → `group_id`. Виджет лишь подтверждает личность; доступ по-прежнему гейтится белым списком.

**`recorder_token` веб-интерфейс НЕ использует.** Персональный токен рекордера (`recorder_token_hash`, `/recordertoken`) — только для desktop-agent (`meeting-claim`/`meeting-ingest`, auth через `_shared/agent-auth.ts`). Веб-интерфейс ходит через браузерный JWT (`Bearer`) (спящий путь `tma`/`initData` — тоже не рекордерный токен) — никогда через токен рекордера.

## Безопасность

- `group_id` берётся **только** из проверенной личности (initData/JWT → telegram_id → allowed_users). Из тела запроса не принимается.
- Каждая операция с задачами скоупится по `group_id` — пользователь не может видеть или менять задачи другого воркспейса.
- Приватные задачи (`is_private`) видны только владельцу/админу; в командный бот не попадают.
- `service_role_key` только внутри swarm-api, фронтенду не передаётся.
- Веб-сессия: JWT в httpOnly Secure SameSite=Lax cookie (недоступен JS). SW не кэширует API.

### Модуль задач (Рой)
Дефолтный вид — **«Список»** в стиле macOS Reminders. Смарт-списки (рельс/чипы, ось время-статус): **Сегодня · Ближайшие · Все · Готовые**. Верхний переключатель-линза (ось «чьи задачи»): **Мои · Команда · Все**, где **«Команда» = ОБЩИЕ задачи: не приватные и без конкретного исполнителя** (решение владельца 2026-08-19: «командная задача = общая, у которой нет определённого юзера»), а **«Все» = мои + командные** (владелец 2026-08-20: «линза "все" показывает свои задачи и задачи команды, чужие задачи не показывает»). Личные задачи коллег не показываются НИ под одной из трёх позиций — только под админским тумблером «Все сотрудники» (внутренняя линза `staff`). Гард тумблера — и в UI (`showAllStaff`), и в `useReminderTasks` (`allStaff && me.is_admin`): состояние переживает потерю админства в `localStorage`, поэтому проверка не может жить только в разметке. «По рынкам» и «Все сотрудники» — **не линзы, а независимые тумблеры-модификаторы**: группируют результат ТЕКУЩЕЙ линзы, а не подменяют охват (`useReminderTasks`; раньше «По рынкам» была 4-й позицией линзы и всегда тянула чужие задачи — исправлено 2026-08-19). Десктоп и мобайл (`RoyTasksScreen`) делят логику через `useReminderTasks` + `TaskRow` + `SmartListNav`; на десктопе смарт-списки — левый рельс, на мобайле — чипы. Виды List / Timeline / Sprint / Projects работают поверх того же `swarm-api` контракта (счётчики и линза считаются на клиенте из общего `fetchTasks`). Канбан остался только в «Спринте». Приватные задачи видны в miniapp только владельцу (фильтрация на бэкенде). PWA устанавливается на macOS: Safari → Поделиться → «Добавить в Dock».

### Десктоп-главный экран (`RoyDashboard`) — 3 колонки

**Где:** `RoyApp.tsx` рендерит `RoyDashboard` только когда `isDashboard` = desktop (`lg+`) + активна вкладка `search` + push-стек пуст. На узких экранах (`< lg`) домашняя вкладка — `SearchScreen`. Контракт named-export `RoyDashboard` не менять (его импортит `RoyApp`).

**Навигация мобайла — четыре корневых таба (2026-08-22).** Таб-бар: **Задачи · Проекты · Встречи · Ещё** (набор — решение владельца, [ADR](decisions/2026-08-22-mobile-nav.md)). Дом мобильного — **Задачи**, не «Поиск». **Поиск перестал быть табом**: иконка `SearchBtn` в шапке каждого корневого экрана → push-роут `ask` (тот же `SearchScreen` с «Назад» вместо лого) → `openAnswer`; формулировка входа одна во всех точках (владелец 2026-08-22: «у нас поиск в вебе один»). **База** — пункт «Ещё» → push-роут `base` (тот же `RoyBaseScreen` с «Назад»). **«Ещё»** — корневой таб: профиль, База, Команда, Настройки, Карта системы, Админ (админу); до этого вход в них был **только** из шапки «Поиска», т.е. с одного экрана из четырёх. `RoyTab` сохраняет `search`/`book` как ДЕСКТОПНЫЕ разделы; при восстановлении из `sessionStorage` на мобайле они мигрируют (`search` → `task`, `book` → `more`) — иначе живая сессия после деплоя попадала бы на экран, которого нет в баре.

**Встречи на мобайле (2026-08-22).** Очередь черновиков `AgentReviewQueue` («На вычитке») — **под** заголовком экрана (висела выше `h1` и читалась как отдельный безымянный экран); её счётчик дублируется **бейджем на табе «Встречи»** (`RoyTabBar badges`), чтобы неразобранное было видно, не заходя в раздел. Строка встречи на мобайле — в `SwipeRow`: действия «Изменить»/«Удалить» уехали в свайп (тот же жест, что у задач; две кнопки 36×36 вплотную в строке были и мелкой целью, и риском случайного удаления). На десктопе действия остались на виду — там мышь. Формат даты в очереди приведён к общему («12 июн.» вместо ISO-среза `2026-06-12`). Органы управления встречей на её экране не тронуты: правка названия/тезисов/стран, выбор «Общее/Личное» и «Сохранить в базу» — у несогласованной; у согласованной выбора хранилища нет (решение владельца 2026-08-21, коммит `0f1d55b`).

**Мелочи мобильного каркаса, устранённые тем же заходом (2026-08-22).** ① Фидбек: `FeedbackFab` («?») больше не рендерится на мобайле — он стоял вторым FAB под «+» и спорил с главным действием экрана; вместо него пункт «Оставить фидбек» в «Ещё» (`FeedbackDialog` — тот же диалог без своей кнопки). На десктопе FAB остался. ② `entryPreview` (`roy/entry.ts`) больше не повторяет текст записи: заголовок берётся из первой строки и обрезается до 80 символов с «…», поэтому строгое `line !== title` не отсекало исходную строку — карточка «Базы» печатала обрезанный текст жирным и тут же его целиком серым. Сравнение идёт по началу строки без хвостового «…». ③ Созданная задача больше не «пропадает»: `NewTask` проверяет её тем же правилом, которым живёт список (`matchesLens` + `matchesList` — предикат списка теперь экспортируется из `lib/smartLists.ts`), и при промахе открывает вид, где задача видна (`openTasks`). До этого задача без срока уводила пользователя в «Сегодня», где её нет.

**Навигация десктопа — dashboard-центрично (без сайдбара):** левого сайдбара нет. Дашборд — десктоп-дом; его собственная шапка даёт лого и аватар → «Ещё» (карта системы/настройки/команда/админ). На секции (таб ≠ `search`) сверху — тонкая строка **«← Главная»** (`setTab("search")`); push-экраны имеют свой «Назад». Мобайл — нижний `RoyTabBar` (без изменений).

#### Экран `meetAdmin` — master-detail ревью встреч

**Файл:** `miniapp/src/components/roy/screens/MeetAdminScreen.tsx`

Три колонки (desktop):
- **Слева (300px):** объединённый список = `fetchAgentMeetings("awaiting_review")` (черновики desktop-agent, первыми) + `fetchMeetings({confirmed:false})` (неподтверждённые Granola/Read.ai). Источники объединены — это «встречи, требующие решения». **Только СВОИ — у всех, включая админа** (own-scoped): чужое непубликованное приватно, в нём не копаемся. ⚠️ Эта строка стояла здесь с 2026-07, но в API ветка `?all=true` для админа оставалась ЖИВОЙ до 2026-08-20 — админ открывал чужой черновик с полным транскриптом (проверено на проде). Гард вынесен в `_shared/meeting-access.ts` и покрыт тестами. Сверху одна плашка «требуют решения: N». Приглядеть, у кого копится бэклог, админ может **агрегатом без контента** — блок «На вычитке по участникам» в `AdminScreen` (`GET /admin/review-counts`). (Раньше тут были два путающих счётчика «на согласовании»/«черновиков» + админ-режим «Все/Личные/Общие» по всему воркспейсу — убраны как «копание в чужом».)
- **Центр (flex):** детали выбранного — заголовок, источник, дата, **участники** (`Participants` ← `m.attendees`/`metadata.attendees`, если есть; чип «Участники (N)» в одну строку + выпадашка-портал со списком), саммари/тезисы, контент. Шапки секций «Тезисы»/«Транскрипт» (заголовок + кнопки «Переобработать»/«Править»/«Копировать») — **`sticky` с непрозрачным фоном**: на длинных тезисах кнопки не уезжают вверх при скролле (жалоба владельца 2026-08-19; полупрозрачный фон не годится — под шапкой читался проезжающий текст). Для entry: **inline-правка СОДЕРЖАНИЯ** (`ContentEditor` → `patchMeeting(id,{content})`). Для agent-черновика: **inline-правка НАЗВАНИЯ и ТЕЗИСОВ** прямо на ревью (карандаш у заголовка → `renameAgentMeeting`; «Править» у тезисов → `MarkdownTextarea` — иконочный тулбар форматирования B/заголовок/список по выделению + высокое поле → `patchAgentMeetingDraft`); **«Переобработать»** — пересобрать тезисы текущим промптом (`resummarizeAgentMeeting`); **«Копировать»** у транскрипта. Изменения отражаются в списке через `onAgentUpdated`. На экране уже опубликованной встречи (`MeetingDetail`) тоже есть «Переобработать» (`resummarizeMeetingEntry` → `POST /meetings/:id/resummarize`).
- **Справа в режиме «Все встречи» (без выбранной) — блок ФИЛЬТРОВ** (`MeetingsFilters`, логика в `screens/meetingsFilter.ts`), под ним статистика (`MeetingsStats`). Владелец 2026-08-21: «заменить блок со странами и кол-вом встреч на блок фильтров». Фильтры: поиск по названию · период (всё/неделя/месяц/квартал/произвольный диапазон дат) · страны · источник · кто добавил · хранилище (Общее/Личное) · статус (Согласовано/На согласовании). Чипы несут количество, и счётчики считаются по ВСЕМ встречам, а не по отфильтрованным — иначе после первого клика у остальных фильтров нули и непонятно, куда делись данные. Шапка показывает «Найдено N из M» + «Сбросить». Статистика внизу считается уже по отфильтрованному срезу.
- **Задачи из встречи** (`TasksFromMeeting`, обобщён на `text`+`meetingId?`+`resetKey`) — в правой панели **для entry И agent-черновика** (когда `draft_notes_md` готов): `extractTasksPreview(text)` без создания → правка/удаление → добавить Себе|В общие (`createTask`). entry → привязка `meeting_id=entry.id`; agent → задачи автономные (записи ещё нет до публикации).
- **Справа (220px):** действия — Segmented **«Общее/Личное»** (дефолт Общее) → «Согласовать/Опубликовать»; «Отклонить»; для entry — **«Не встреча → в заметки»** (`patchMeeting(id,{entry_type:"note"})`). Обновление списка/`selected` — через `onEntryUpdated`. Ошибки операций → тост.

**API-операции:**
| Действие | Entry (неподтв. встреча) | AgentMeeting (черновик) |
|----------|--------------------------|-------------------------|
| Согласовать (Общее/Личное) | `patchMeeting(id, {confirmed:true, is_private})` | `publishAgentMeeting(id, "workspace"\|"personal")` |
| Править содержание | `patchMeeting(id, {content})` | название → `renameAgentMeeting(id,title)`; тезисы → `patchAgentMeetingDraft(id,md)` (инлайн на ревью) |
| Реклассифицировать | `patchMeeting(id, {entry_type:"note"})` → уходит из очереди | — |
| Сгенерировать задачи | `extractTasksPreview(content)` → `createTask({meeting_id, is_private})` | `extractTasksPreview(draft_notes_md)` → `createTask({is_private})` (автономно) |
| Отклонить | `deleteMeeting(id)` (с confirm) | `deleteAgentMeeting(id)` (с confirm) |

> Бэкенд: `PATCH /meetings/:id` принимает `content`/`is_private`(+`owner_id`)/`entry_type` (swarm-api); `POST /tasks/extract { save:false }` возвращает предложения без создания.
