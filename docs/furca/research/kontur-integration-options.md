# Контур.Толк: как забирать встречи — проработка (30.09.2026)

Продолжение исследования T110 ([kontur-talk-api.md](kontur-talk-api.md)). Повод — вопрос владельца
30.09.2026: «а это, мы контур в итоге не распознаем?» → «проработай». Вопрос Q009 остаётся открытым:
ниже то, что нужно, чтобы на него ответить, и что делаем после ответа.

## Что есть сейчас

- **Бот scriba в Толк не ходит.** Ссылка Толка распознаётся (`platform: "kontur"`), но сервер сразу
  отказывает: `400 unsupported_platform`, под полем «Бот пока ходит только в Google Meet — Контур.Толк и Zoom
  не поддерживаются». Встреча Толка из календаря попадает в «пропущенные» (`_shared/calendar-missed.ts`,
  «Kontur.Talk»): человек видит, что бот не придёт.
- **bumblebee Толк уже пишет.** Рекордер на Mac ловит звонок в любом приложении. Прод, воркспейс `cee`,
  последние 60 дней: из встреч, опознанных по комнате, **12 — в Толке, 29 — в Meet** (ключи `kontur:…` и
  `meet:…`). Ещё 110 записей опознаны по событию календаря — площадку по ним не видно, значит встреч в
  Толке больше двенадцати.
- **Пробел — встречи Толка, где bumblebee ни у кого не включён.** Их в базе нет вовсе, посчитать их по
  нашим данным нельзя.

## Три пути

| | A. Talk API (без бота) | B. Браузерный бот (T111) | C. Как сейчас |
|---|---|---|---|
| Как | Толк сам пишет и расшифровывает, Swarm забирает готовую запись по вебхуку | scriba заходит в звонок Толка, как в Meet | bumblebee на Mac |
| Стенограмма | Толка: говорящие привязаны к профилям, пословные тайм-коды | наша (Whisper), говорящие по плиткам | наша (Whisper) |
| Условие | кто-то нажал «Записать» (или автозапись, см. ниже) | бота пустили в звонок | у участника включён bumblebee |
| Что нужно от людей | админ пространства выпускает ключ | ничего | ставят bumblebee |
| Работа | новая функция-приёмник + сопоставление участников, ~2–3 дня | новый адаптер площадки: вход, лобби, антибот, звук; блок размером с Meet (недели) | 0 |
| Риск | ключ видит записи **всего пространства** (см. «Приватность») | Толк может требовать входа в аккаунт для комнат организации; антибот | пробел остаётся |

**Рекомендация — A.** Данные лучше наших (говорящие с именами из Толка), работы в разы меньше, бот не
нужен. B имеет смысл, только если после запуска A окажется, что «Записать» регулярно не жмут, а автозапись
включить нельзя.

## Новая находка: автозапись через API

В официальной спецификации Talk API у встреч календаря Толка есть флаг **`enableAutoRecording`**
(«Включить автоматическую запись встречи»): его принимают `POST /api/EmailCalendar/{email}` (создать встречу)
и `PUT /api/EmailCalendar/{email}/{eventId}` (изменить), права `application.calendar.write`. Значит,
условие «кто-то нажал Записать» можно снять и без бота: либо админ включает автозапись в настройках
пространства (если такая настройка есть — в спецификации её нет, смотреть в админке), либо Swarm ставит флаг
встречам тех, кто это разрешил. Оговорка: это календарь **Толка** (встречи, созданные через Толк или его
интеграцию с почтой). Встречу, заведённую в Google-календаре с вставленной руками ссылкой на Толк, флаг не
покроет — это проверяется только на живом пространстве.

## Как будет устроен путь A

1. **Ключ.** Админ пространства: «Управление» → «API-ключи» → «Добавить», права «Записи» (чтение) и
   «Отчётность» (чтение) плюс вебхуки. Значение показывается один час — сразу в секреты функций
   (`KONTUR_TALK_API_KEY`, `KONTUR_TALK_BASE_URL` — адрес пространства). В репозиторий и в чат не попадает.
2. **Вебхук.** Новая функция `kontur-webhook` (по образцу `read-ai-webhook`): регистрируется на
   `transcriptionReady`, проходит двухшаговую активацию (`activationKey` → `POST /api/Webhooks/{key}/activate`).
   Создание вебхука ограничено 10 в день — регистрация разовая, из кнопки Actions.
3. **Забрать запись.** `GET /api/recordings/v2/{recordingKey}/summary` — стенограмма, пересказ и протокол
   одним вызовом; участники — `GET /api/Domain/recordings/{recordingKey}/participants`.
4. **Чья встреча.** Импортируем запись, только если среди участников есть человек из воркспейса (e-mail в
   `allowed_users`). Остальные записи пространства не трогаем и не храним.
5. **Встреча в Swarm.** Ключ `kontur:<комната>:<дата>` — тот же, что у bumblebee, чтобы запись Толка и
   запись рекордера того же звонка слились в одну, а не стали двумя встречами. Здесь нужна сверка с живыми
   дырами дедупа #168 и #181. Стенограмма Толка идёт в тот же конвейер тезисов, что и наша (Whisper
   пропускаем), встреча ложится в «На вычитке», как любая другая.
6. **Страховка.** Если вебхук молчит — ежечасный опрос `GET /api/Domain/recordings` за последние сутки.

## Приватность

Ключ пространства видит записи **всех** встреч организации, а не только команды. Если пространство Толка
— общее на компанию, это главный вопрос, и решать его не нам, а владельцу вместе с админом: брать ли ключ
с доступом ко всей организации ради записей команды. Фильтр из п. 4 гарантирует, что чужие встречи в Swarm
не попадут, но сам доступ у ключа останется.

## Что нужно от владельца (Q009)

1. Чьё пространство Толка — только команды или всей компании? Кто в нём админ?
2. Готовы ли выпустить ключ с правами «Записи» и «Отчётность» (п. 1), учитывая приватность выше?
3. Какой тариф: доступны ли на нём API записей и вебхуки (в спецификации — «если не нашли прав, возможно
   они недоступны для вашего тарифа»)?
4. Есть ли в админке автозапись для всего пространства? Если есть — включать ли её.
5. Жмут ли в команде «Записать» в Толке. Если автозапись есть, этот вопрос снимается.

Ответы на 1–3 решают, строим ли A. Ответы на 4–5 решают, нужен ли когда-нибудь B.

## Решение 30.09.2026: браузерный бот под корпоративным аккаунтом (D037, D038)

Владелец выбрал бота. Толк корпоративный: гостю встречи по умолчанию закрыты, поэтому бот входит **под
своим аккаунтом пространства**. Что говорит об этом спецификация Talk API (разбор 30.09.2026):

- **Комната** (`PUT /api/Rooms/{roomName}`, `TalkRoomParams`): `allowAnonymous` + `anonymousAccessExpirationDate`
  — пускать ли анонимных гостей и до какой даты; `enableLobby` — «вход по запросу» (участник стучится,
  модератор пускает); модераторы — `moderatorKeys`. Отсюда: гость без аккаунта в закрытую комнату не
  попадёт вовсе, а участник пространства входит сразу или стучится, если у комнаты включён вход по запросу.
  Стук бот уже умеет обрабатывать (Meet, `meet-adapter/admission.ts`).
- **Аккаунт бота** — обычный пользователь пространства. Админ заводит его в интерфейсе или через
  `POST /api/Users` (`application.profiles.write`, поля `login`, `email`, имя). Пароля в API нет: вход
  идёт через механизм пространства (Контур ID или корпоративный SSO), значит бот входит в веб-клиент один
  раз руками, а состояние входа живёт на MUSPELHEIM — как `google-state.json` для Meet.
- **Обход без аккаунта** технически есть: Swarm перед встречей сам ставит комнате `allowAnonymous` с
  коротким `anonymousAccessExpirationDate` (права `application.rooms.write`) — то же «сделать публичной»,
  только автоматом. Не берём: комната на это время открыта любому, у кого есть ссылка, и нужен ключ
  админа с правом менять все комнаты.
- **Готовых ботов под Толк нет** (GitHub, 30.09.2026: только CLI/парсеры записей через API, напр.
  `mdemyanov/ktalk-cli`); Recall.ai/Vexa/Attendee Толк не поддерживают. Адаптер пишем свой.

**Что нужно, чтобы начать:** аккаунт бота в пространстве (и место в тарифе под него), понимание, как он
входит (логин-пароль Контур ID, SMS, SSO), и одна тестовая комната, куда его можно позвать. Без аккаунта
веб-клиент Толка изнутри не посмотреть — а адаптер строится именно по его живой разметке (вход, стук,
говорящие, «остался один»), как было с Meet.

**Что строим** (T111, блок meet-adapter по тому же интерфейсу площадки): разбор ссылки Толка → вход под
аккаунтом → стук и ожидание → звук и говорящие → выход, когда остался один; на сервере снять отказ
`unsupported_platform` для `kontur` в `/meeting-invites` и в раздаче календаря.
