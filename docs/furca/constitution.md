# Принципы проекта — `scriba`

Бот-участник видеовстреч для Swarm Brain · 2026-09-17 · **Статус: ждёт утверждения владельцем на гейте**

> Принципы не меняются по ходу стройки. Когда приоритеты конфликтуют, агент смотрит сюда.
> Решения владельца — в [decisions.md](decisions.md), они сильнее этого файла.

## Принципы качества

Пять правил, отсортированы по силе: при конфликте побеждает тот, что выше.

1. **Громкий отказ важнее тихой работы.** `scriba`, записавший тишину, хуже `scriba`, который честно
   не записал. Проект уже оплатил целый класс молчаливых сбоев (#171, #175, #178, #150), и главная
   грабля этого стека — ровно такая: Playwright по умолчанию добавляет `--mute-audio`, и звук молча
   не пишется, не выдав ни одной ошибки. Поэтому **каждое состояние, где бот мог бы промолчать,
   обязано иметь сигнал**: не впустили, ссылка не распозналась, владелец не определился, звука нет,
   контейнер умер.

2. **Существующий конвейер неприкосновенен.** `scriba` — новый **источник** записи, а не новый
   конвейер. `meeting-process`, тезисы, очередь вычитки, публикация не переписываются. Правки общих
   эндпоинтов (`meeting-current`, `-claim`, `-ingest`, `-heartbeat`) обязаны быть обратносовместимы:
   `bumblebee` не знает о новых полях и не должен о них узнать. У этих модулей есть действующий
   потребитель на машинах живых людей — регресс бьёт по ним, а не по нам.

3. **Приватность не расширяется ни на шаг.** Бот действует **от имени человека**, а не от себя:
   `claim_owner` и `owner_id` — всегда живой пользователь. Бот не может записать встречу «ничью»
   (не определился владелец → не заходит) и не может назвать владельцем человека из чужого
   воркспейса. Вся новая власть сосредоточена в одной функции подмены личности — не размазывается
   по местам, где её потом забудут проверить.

4. **Проверки — не на живых данных.** У продукта ежедневные пользователи. Замеры и прогоны идут на
   чтение и на встречах, созданных для проверки; изменения схемы — только добавлением, с планом
   отката. Встречи с правленными человеком тезисами (`notes_edited_at`) — стоп-сигнал, их не трогаем
   ни при каких замерах.

5. **Хрупкое живёт за одной границей.** Вёрстка Meet меняется без предупреждения — это не риск, а
   постоянное свойство. Всё, что знает о вёрстке, лежит **только** в адаптере площадки
   (`join` / `waitAdmitted` / `activeSpeaker` / `isAlone` / `leave`). Остальной код о площадках не знает,
   поэтому поломка вёрстки чинится в одном файле, а не по всему боту.

## Стандарт тестирования

- **TDD для нового поведения:** сначала падающий тест, потом код. Особенно для чистых функций —
  разбор ссылки на звонок, определение площадки, сведение таймлайна говорящих с сегментами.
- **Покрытие — относительное:** не ниже, чем на предыдущей приёмке. Абсолютный порог держим
  ориентиром, но сам по себе он блок не заворачивает: он подталкивает писать тесты без утверждений
  ради процента.
- **Обязательные виды:**
  | Вид | На что |
  |---|---|
  | Юнит | разбор ссылок, площадка по хосту, сведение таймлайна с сегментами (перекрытия, дыры, пустой таймлайн → мягкая деградация) |
  | Безопасность (**блокирующие**) | токен `kind: "recorder"` НЕ может передать `on_behalf_of`; бот не может указать человека из чужого воркспейса; токен бота без `on_behalf_of` не даёт прав |
  | Регресс | `bumblebee` продолжает работать после правок общих эндпоинтов |
  | Живой прогон | реальная встреча: зашёл → впустили → записал → `claim` → `ingest` → тезисы с именами |

- **Главное правило, которое сильнее любого порога покрытия: проверка, которая не падает на сломанном
  входе, — не проверка.** Каждую новую проверку прогнать на заведомо испорченной копии и убедиться,
  что она **падает и внятно говорит почему**. И убедиться, что порча вообще применилась, — иначе
  «отрицательный прогон» зелёный по ошибке.
  **Для этого продукта это не формальность, а главный тест:** смоук записи звука обязан падать на
  тишине. Если он зелёный при выключенном звуке — у нас нет проверки записи вообще.

## Документация как часть готовности

Изменение не готово, пока доки не приведены в соответствие **тем же коммитом**. Для этого проекта:

- `docs/ARCHITECTURE.md` и `docs/QUICK_REF.md` — флоу, эндпоинты, сессии, таблицы, env-переменные.
  Сверять с кодом, не по памяти.
- Спека блока в `docs/furca/blocks/<имя>.md` — ведёт агент блока, вместе с кодом.
- `CHANGELOG.md` **вручную не ведём** — он генерируется из git-истории. Поэтому conventional commits
  (`feat/fix/refactor/docs/test/chore/perf/ci`) — не стиль, а источник истины.
- Новая env-переменная, новый эндпоинт, новая колонка → строка в инвентаре тем же коммитом.

## Правила безопасности

- **Секреты не попадают в git.** Значения — в `.env` (в `.gitignore`), в документации только имена.
  `.env.example` с именами и безопасными значениями обязателен: без него контур не поднять ни в другой
  сессии, ни другому человеку.
- **Токен бота живёт в секретах контейнера**, не на машинах людей, и **сам по себе не даёт прав** —
  он обязан указать, за кого действует.
- **Расширение авторизации проходит security-review.** Это самая чувствительная часть работы:
  подмена личности даёт коду право действовать от имени человека.
- **Репозиторий публичный.** Отсюда два следствия, которые легко забыть: в коде, доках и задачах не
  появляется ничего, чего нельзя показать посторонним (адреса площадки, внутренние идентификаторы,
  имена и почты коллег в примерах); **находка по безопасности идёт в приватный advisory, а не в issue.**
- **Чужой код — по лицензии.** Из Vexa (Apache-2.0) заимствовать можно с атрибуцией; из Attendee
  (Elastic License 2.0) — **нельзя**, перенимаем только приёмы. Репозиторий публичный и без файла
  лицензии, поэтому цена ошибки здесь выше обычного.
- **Запись живых людей.** `scriba` присутствует в списке участников под своим именем — это и есть
  раскрытие. Скрытая запись не делается ни при каких настройках.

## Демонстрационный режим

**Неприменимо в обычном смысле: у `scriba` нет интерфейса** — это служба, её поверхности (уведомление
в Telegram и очередь вычитки) принадлежат Swarm и уже существуют.

Что из этого раздела всё-таки обязательно: **записи `scriba` не попадают в демо-данные Swarm.**
Демо изолировано и живёт на своём наборе; настоящая встреча живых людей не может оказаться в витрине.
