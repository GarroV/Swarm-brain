# Живой прогон T004 — чек-лист

Бот `scriba` идёт на настоящую встречу Google Meet, которую владелец создал сам (D004), по
ручному приглашению (D017). Всё крутится на **стенде MUSPELHEIM** — локальный Supabase и функции
с ветки; прод не участвует. Этот документ: как поднять стенд, что владелец делает руками, что
диспетчер смотрит, чтобы отметить каждый пункт готовности MVP из [spec.md](spec.md) («Что считается
готовым MVP»).

## Стенд

| что | где |
| --- | --- |
| управление (с Мака) | `scripts/scriba-live.sh up \| down \| wipe \| status` |
| позвать бота | `scripts/scriba-live.sh invite https://meet.google.com/xxx-yyyy-zzz` |
| живой лог оркестратора и бота | `scripts/scriba-live.sh logs` (строки `[meet]`, `[meeting]` — это бот в контейнере) |
| «Telegram» владельца | `scripts/scriba-live.sh notices` — поддельный Telegram, строка JSON на сообщение |
| встречи и очередь вычитки | `scripts/scriba-live.sh meetings` |
| веб | `http://100.64.116.67:4425`, вход — ссылка из `scripts/scriba-live.sh login-url` |
| функции | `http://100.64.116.67:4424/functions/v1/<имя>`, здоровье — `/health` |
| Supabase | API `:4420`, база `:4421` (project_id `scriba-live`) |
| на сервере | `C:\projects\scriba-live\repo` — клон ветки из origin, `state\` — данные вне git |

Устройство: [scripts/scriba-live/](../../scripts/scriba-live/) — `compose.yml` (функции, веб,
оркестратор), `stand.ps1` (серверная половина), `functions-host.ts` (настоящие edge-функции
процессами Deno за одним портом + поддельный Telegram + cron `meeting-process`), `web-host.ts`
(собранный miniapp + то, что в проде делает Cloudflare Pages Function), `seed.ts`.

Сид: воркспейс `scriba-live`, владелец встречи `7100000001` (`live_owner`, в вебе — он),
служебный агент `scriba` с токеном стенда. Уведомления владельцу пишутся в
`state\telegram.jsonl` — настоящим людям не уходит ничего.

**Живая транскрибация.** Без ключа OpenAI распознавание поддельное: реплики «Поддельная
реплика N» по длине части, тезисы-заглушка. Звук при этом настоящий и лежит в Storage стенда, а
таймлайн говорящих — настоящий, от бота. Чтобы проверить пункт «реплики подписаны именами» по
настоящей речи, нужен живой ключ: владелец кладёт его в `C:\projects\scriba-live\state\openai.key`
на MUSPELHEIM (одна строка, файл вне git) и зовёт `scripts/scriba-live.sh up`. Откуда ключ — решает
владелец: прод-ключ Swarm общий с двумя ботами (см. память `openai-key-shared-across-projects`),
отдельный ключ под стенд безопаснее.

**Сон машины.** На 28.09 MUSPELHEIM на сети (AC), тайм-ауты экрана и сна — «никогда» (0) и на
AC, и на батарее; `muspelheim-infra` #16/#17 закрыты. Для прогона достаточно не отключать
питание.

## Порядок прогона

Владельцу нужен второй человек (или второе устройство со вторым Google-аккаунтом) — для
пунктов «имена говорящих» и «остался один».

### Прогон А — вход и запись (главный)

1. Владелец: создаёт встречу в Google Meet, заходит сам. Второй человек заходит тоже.
2. Диспетчер: `scripts/scriba-live.sh invite <ссылка>` и держит открытым `scripts/scriba-live.sh logs`.
3. Бот стучится как `scriba`. Владелец **впускает**.
4. Двое говорят по очереди 3–5 минут: сначала один (≥30 с), потом другой (≥30 с), потом вперемешку.
   Владелец запоминает, кто когда говорил.
5. В DevTools своего Chrome владелец запускает проверку атрибута (ниже) — одна минута.
6. Оба выходят из встречи. Бот остаётся один и через 2 минуты выходит сам.
7. Диспетчер: `scripts/scriba-live.sh meetings`, затем веб → очередь вычитки.

### Прогон Б — отказ у двери

Та же или новая встреча. `invite` ещё раз, владелец **отклоняет** (Deny).

### Прогон В — никто не отвечает у двери (необязательно)

`invite`, владелец не нажимает ничего. Бот шлёт «жду у двери» и уходит после лимита
(90 с до первого «жду у двери», ещё 3 мин до второго, затем выход — около 4,5 мин). Длинный — можно пропустить, если время дорого.

## Проверка `data-audio-level` (имя говорящего)

Бот берёт говорящего только из атрибута `data-audio-level` на плитках `[data-participant-id]`
(`bot/src/meet-adapter/dom.ts`). Нет атрибута в сегодняшней вёрстке — развилка владельцу (T004).
Проверяем с двух сторон в прогоне А, пока двое говорят:

1. **Со стороны бота** (главное): в `logs` НЕ должно быть строки `СИГНАЛА ГОВОРЯЩЕГО НЕТ`, а после
   встречи `meetings` показывает `speakers > 0`. Строка есть или `speakers = 0` при говорящих
   людях → атрибута в гостевой вёрстке нет.
2. **Со стороны владельца** (подтверждение, если со стороны бота пусто): в Chrome на вкладке
   Meet — DevTools → Console, вставить и смотреть таблицу, пока кто-то говорит:

   ```js
   setInterval(() => console.table([...document.querySelectorAll('[data-participant-id]')].map((t) => ({
     name: (t.getAttribute('aria-label') || t.querySelector('span.notranslate')?.textContent || '').slice(0, 30),
     level: (t.matches('[data-audio-level]') ? t : t.querySelector('[data-audio-level]'))?.getAttribute('data-audio-level') ?? 'НЕТ',
   }))), 2000)
   ```

   Колонка `level` меняется у говорящего — атрибут есть. Везде `НЕТ` — атрибута нет и у хоста.
   Остановить: перезагрузить вкладку.
