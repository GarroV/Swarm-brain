# Блок: container

## Назначение

Окружение, в котором `scriba` живёт одну встречу: виртуальный экран, виртуальная звуковая карта,
браузер и ffmpeg. Отдельный блок, потому что это единственное место, где водятся грабли окружения, а
не логики, — и где прячется главный риск проекта: звук, который молча не пишется.

Одна встреча = один контейнер: PulseAudio-sink и дисплей глобальны, два бота в одном контейнере
запишут друг друга.

## API-контракт

Готовое окружение для `meet-adapter`:

- `DISPLAY=:99` (Xvfb), Chromium в **headed**-режиме;
- PulseAudio с null-sink, `XDG_RUNTIME_DIR` выставлен, `--exit-idle-time=-1`, `set-default-sink` сделан,
  monitor-source **проверен**, а не предположен;
- Chromium запускается с `ignoreDefaultArgs: ['--mute-audio']`;
- `ffmpeg` в `PATH`, пишет с `<sink>.monitor` в m4a/AAC, режет по `segment_time` под лимит 25 МБ,
  `reset_timestamps` включён явно.

## Зависимости

Продуктовых нет. Внешнее: `mcr.microsoft.com/playwright:v1.63.0-noble` (Xvfb и PulseAudio ставим сами),
ffmpeg, Docker в WSL2.

## Definition of Done блока

| этап | пункт |
| --- | --- |
| 1 | образ собирается, контейнер поднимается и гасится |
| 1 | 🔴 **смоук записи звука падает на тишине** и внятно говорит почему — без этого проверки записи нет вообще |
| 1 | смоук прогнан на **испорченной копии** (звук выключен намеренно) и покраснел; проверено, что порча применилась |
| 1 | части записи ≤25 МБ и каждая открывается самостоятельно |
| 1 | два контейнера одновременно не слышат друг друга (проверено запуском двух) |
| 1 | потребление памяти замерено и записано; видео заглушено штатной настройкой Meet |
| 1 | `.env.example` с именами переменных лежит в репозитории |

## Статус

ready_for_review · 2026-09-19 (все пять задач сошлись живым прогоном)

### Где стоим

Каркас блока в коде готов и покрыт юнит-тестами (63/63 зелёные, ~200 мс).
Живой прогон `smoke.sh` на Docker прошёл целиком — четыре шага сошлись как
задумано:

- 1/4 звучащая страница — pass, max_volume −5.6 dB;
- 2/4 чужой default sink (порча снаружи через `pactl load-module` + новый
  `set-default-sink`) — покраснел, `inspectAudioEnvironment` выдал ровно то
  сообщение: «sink по умолчанию — «elsewhere», а не «scriba»: Chromium
  заиграет мимо записи, и в файле будет тишина»; порча откатывается trap'ом;
- 3/4 молчащая страница — покраснела, max_volume −91 dB;
- 4/4 пара контейнеров под `profiles=pair` с одинаковым именем sink'а
  (имя одинаковое намеренно — изоляция обязана держаться границей
  контейнера, а не разными именами): A слышит свой tone (−5.6 dB),
  B — свою тишину (−91 dB).

Итоговая строка: «смоук ловит звук, краснеет на чужом default sink и на
тишине, изоляция контейнеров держится».

### Что было по дороге

Первый живой прогон 2026-09-19 нашёл, что шаг 2/4 «Chromium с
`--mute-audio` через `SCRIBA_SMOKE_FORCE_MUTE=1`» проходил со звуком
−4.6 dB вместо ожидаемого отказа. Причина установлена запуском Chromium
и осмотром живых args через `ps`: **в Playwright v1.63 на Linux
`--mute-audio` в дефолтных аргументах Chromium отсутствует**. Значит
`ignoreDefaultArgs: ['--mute-audio']` в `browser.ts` — не «единственная
строка, отделяющая запись от тишины», а страховка на будущее (если
Playwright когда-нибудь этот флаг добавит).

Развилка закрыта в этом же заходе: `ignoreDefaultArgs` оставлен как
дешёвая страховка (комментарий переписан честно), шаг 2/4 смоука
переработан вокруг реальной грабли из спеки «Chromium заиграет мимо
записи». Ручка `SCRIBA_SMOKE_FORCE_MUTE` тоже оставлена в
`.env.example` как страховка — smoke-audio.ts её всё ещё читает.

### Что закрыто фактически

- T040 (образ собирается, контейнер поднимается и гасится) — да, время
  подъёма < 1 c, уборка `docker compose down -v` чистая;
- T041 (null-sink, `XDG_RUNTIME_DIR`, `set-default-sink`, monitor-source
  проверен) — самопроверка `verify-environment.ts` проходит на старте;
  реальная защита от «звука мимо» подтверждена шагом 2/4 порчей;
- T042 (Chromium с `ignoreDefaultArgs: ['--mute-audio']`, звук в sink) —
  шаг 1/4 pass, звук попадает в sink;
- T043 (смоук падает на тишине, порча подтверждена) — шаг 3/4 fail на
  молчащей странице, шаг 2/4 fail на испорченном default sink;
- T044 (нарезка ≤25 МБ, каждая часть открывается) — 4 части по 13-14 КБ,
  ffprobe читает каждую;
- T045 (два контейнера не слышат друг друга) — шаг 4/4 pair.
