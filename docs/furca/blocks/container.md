# Блок: container

## Назначение

Окружение, в котором `scriba` живёт одну встречу: виртуальный экран, виртуальная звуковая карта,
браузер и ffmpeg. Отдельный блок, потому что это единственное место, где водятся грабли окружения, а
не логики, — и где прячется главный риск проекта: звук, который молча не пишется.

Одна встреча = один контейнер: PulseAudio-sink и дисплей глобальны, два бота в одном контейнере
запишут друг друга.

## API-контракт

Готовое окружение для `meet-adapter`:

- `DISPLAY=:99` (Xvfb), Chromium в **headed**-режиме;
- PulseAudio с null-sink, `XDG_RUNTIME_DIR` выставлен, `--exit-idle-time=-1`, `set-default-sink` сделан,
  monitor-source **проверен**, а не предположен;
- Chromium запускается с `ignoreDefaultArgs: ['--mute-audio']`;
- `ffmpeg` в `PATH`, пишет с `<sink>.monitor` в m4a/AAC, режет по `segment_time` под лимит 25 МБ,
  `reset_timestamps` включён явно.

## Зависимости

Продуктовых нет. Внешнее: `mcr.microsoft.com/playwright:v1.63.0-noble` (Xvfb и PulseAudio ставим сами),
ffmpeg, Docker в WSL2.

### Где стоим

Каркас блока принят 2026-09-19 (смоук записи, нарезка, пара контейнеров). Сейчас —
изоляция контейнера встречи: он открывает чужую страницу звонка и считается недоверенным.
Сделано в коде и запушено в `fix/container-isolation`:

- потолок одновременных встреч `SCRIBA_MAX_MEETINGS` (4) в оркестраторе: сверх него
  отказ до подъёма контейнера, триггер доносит его человеку (`start_failed`); запуски
  бронируют место до `track`, чтобы приглашение и календарь разом потолок не проскочили;
- потолки контейнера: память 2 ГБ без свопа, 2 ядра, 1024 процесса/потока
  (`src/container/isolation.ts`, переменные `SCRIBA_CONTAINER_*`);
- том записей свой у каждого человека (`<project>-recordings-<person>`): не на запуск,
  потому что осиротевшую запись подбирает следующий запуск того же человека;
- песочница Chromium включена (`chromiumSandbox: true`; без него Playwright сам
  добавляет `--no-sandbox`), `--no-sandbox` снаружи запрещён; контейнер под профилем
  seccomp `src/container/seccomp-chromium.json` (профиль Docker по умолчанию +
  `clone`/`setns`/`unshare`) и `no-new-privileges`; смоук записи проверяет песочницу
  по `chrome://sandbox`.

### Что проверено и как (MUSPELHEIM, стенд `scriba-isolate`)

- до правки: `chrome://sandbox` — «NOT adequately sandboxed», и даже с флагом
  песочницы в `browser.ts` Playwright дописывал `--no-sandbox`; под профилем Docker
  по умолчанию `unshare -Ur` отказывает, Chromium с песочницей не стартует;
  `HostConfig` без Memory/NanoCpus/PidsLimit; юнит-тесты изоляции красные;
- после: `smoke.sh` зелёный целиком (4/4) под песочницей и потолками;
  `chrome://sandbox` — «adequately sandboxed»; `HostConfig` Memory=2147483648,
  NanoCpus=2e9, Pids=1024; пик смоука 317 МБ и 158 процессов;
- порча: песочница выключена в копии `browser.ts` — смоук красный с отчётом
  `chrome://sandbox`; контейнер без профиля seccomp — Chromium не стартует, смоук красный.
