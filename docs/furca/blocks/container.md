# Блок: container

## Назначение

Окружение, в котором `scriba` живёт одну встречу: виртуальный экран, виртуальная звуковая карта,
браузер и ffmpeg. Отдельный блок, потому что это единственное место, где водятся грабли окружения, а
не логики, — и где прячется главный риск проекта: звук, который молча не пишется.

Одна встреча = один контейнер: PulseAudio-sink и дисплей глобальны, два бота в одном контейнере
запишут друг друга.

## Контракт

Готовое окружение для `meet-adapter`:

- `DISPLAY=:99` (Xvfb), Chromium в **headed**-режиме;
- PulseAudio с null-sink, `XDG_RUNTIME_DIR` выставлен, `--exit-idle-time=-1`, `set-default-sink` сделан,
  monitor-source **проверен**, а не предположен;
- Chromium запускается с `ignoreDefaultArgs: ['--mute-audio']`;
- `ffmpeg` в `PATH`, пишет с `<sink>.monitor` в m4a/AAC, режет по `segment_time` под лимит 25 МБ,
  `reset_timestamps` включён явно.

## Зависимости

Продуктовых нет. Внешнее: `mcr.microsoft.com/playwright:v1.63.0-noble` (Xvfb и PulseAudio ставим сами),
ffmpeg, Docker в WSL2.

## Готовность блока

| этап | пункт |
| --- | --- |
| 1 | образ собирается, контейнер поднимается и гасится |
| 1 | 🔴 **смоук записи звука падает на тишине** и внятно говорит почему — без этого проверки записи нет вообще |
| 1 | смоук прогнан на **испорченной копии** (звук выключен намеренно) и покраснел; проверено, что порча применилась |
| 1 | части записи ≤25 МБ и каждая открывается самостоятельно |
| 1 | два контейнера одновременно не слышат друг друга (проверено запуском двух) |
| 1 | потребление памяти замерено и записано; видео заглушено штатной настройкой Meet |
| 1 | `.env.example` с именами переменных лежит в репозитории |
