**Главный итог: затея подтверждена чужой практикой, но два её опорных предположения оказались неверны.**
Продукты этого класса существуют и работают (Vexa, Attendee, MyMeet.ai, Recall.ai), рецепт воспроизводим.
При этом спека ошибалась в том, как бот попадает в Meet, и знала лишь один из двух способов записать звук.

## Готовые решения

**Vexa** ([vexa-ai/vexa](https://github.com/vexa-ai/vexa), **Apache-2.0**) — ближайший работающий аналог с
открытым кодом. Прочитан код входа в Meet. Берём: порядок селекторов, **пиннинг локали** (`?hl=en` +
`--lang=en-US`) — без него текстовые селекторы ломаются у пользователя с другим языком интерфейса;
двухпроходную классификацию «пустили / отказал хост / reCAPTCHA» с окном 120 с на решение капчи
человеком; синтетические движения мыши, потому что тулбар Meet автоскрывается. Лицензия позволяет
заимствовать код при атрибуции.

**Attendee** (**Elastic License 2.0**) — у него ровно тот рецепт, что предполагала спека: PulseAudio
null-sink + ffmpeg. Полезные приёмы: пауза записи мьютом, деградация видео при превышении размера,
`faststart`-постобработка, и штатная функция самого Meet «Incoming video → Audio only» вместо
самодельного глушения видео. **Код оттуда не берём:** ELv2 — не свободная лицензия, а наш репозиторий
публичный и без файла лицензии (проверено: `visibility: PUBLIC`, `licenseInfo: null`). Перенимаем приёмы,
не строки.

**[screenappai/meeting-bot](https://github.com/screenappai/meeting-bot)** (174★, пуш 28.08.2026) — живой
прод-репозиторий почти с нашим стеком: рабочий рецепт PulseAudio (`XDG_RUNTIME_DIR`,
`--exit-idle-time=-1`, поллинг готовности, обязательный `set-default-sink`, самопроверка monitor-source)
и **headed**-Chromium поверх Xvfb вместо headless.

**Официальные пути, которые снимают целые классы проблем:**

- **Zoom Meeting SDK for Linux** ([meetingsdk-headless-linux-sample](https://github.com/zoom/meetingsdk-headless-linux-sample))
  — нативный, без браузера и без селекторов. Кандидат на этап 5 вместо веб-клиента.
- **Google Meet Media API** — Developer Preview и требует, чтобы **все** участники были в программе.
  Для внешних встреч неприменимо сегодня.
- **Контур.Толк REST API** с модулем `Recordings` (`POST /api/Recordings/start`) — но только для
  пространства, которым мы администрируем; для чужих встреч гостем не работает.

Чего **не нашлось**: готового бота-участника для Контур.Толк. Направление это подтверждает исходное
решение владельца строить своё — покупные продукты Толк не покрывают.

## Рынок и референсы

**Как бот попадает в Meet — здесь спека ошибалась.** По документации Workspace анонимный участник
входит без ручного допуска **только** при совпадении двух условий: он есть в календарном приглашении
(или его позвал из звонка человек из организации-хоста) **и** идут первые 15 минут встречи. Иначе дверь
открывает человек. В Workspace for Education анонимный вход закрыт полностью с 2020 года. Спека же
рассчитывала на «по ссылке, имя + Ask to join» (§6) — в этом режиме «стою у двери» перестаёт быть
редким отказом и становится обычным состоянием.

**Наш сценарий уже делают чужими руками:** MyMeet.ai заходит в Контур.Толк браузерным ботом (имя
«mymeet.ai», подключение 2–3 минуты, выход через 5 минут без участников). Затея воспроизводима.

**«Кто говорит» — индустрия не выбирает один способ, а комбинирует** список участников и календарь с
диаризацией по звуку. Ценный референс честности: Vexa при наложении речи помечает говорящего как
неизвестного (~4–7% строк) вместо того, чтобы угадывать. Это ровно тот подход, который в Swarm уже
принят как принцип — громкий отказ вместо тихой неправды.

**Согласие на запись.** Бот виден в списке участников — это само по себе раскрытие, и оно лучше
скрытого локального захвата (архитектура Granola: пишет с устройства человека, в звонке не видно
ничего). Индустрия использует пять паттернов раскрытия (голос, чат, баннер, письмо со ссылкой,
лендинг). Отдельно отмечен, но **не проверен по первоисточнику**, иск по биометрии голоса против
Fireflies (Illinois BIPA) — станет важен, только если пойдём в диаризацию по голосовым отпечаткам.

**Дедупликация не решена даже у профильного игрока:** у Recall.ai она работает внутри одного
воркспейса и одной календарной платформы. То есть наша проблема дублей — не наша недоработка, а
свойство класса задач.

## Стек и версии

- **Playwright 1.63.0** (Chromium 153.0.8010.12), образ `mcr.microsoft.com/playwright:v1.63.0-noble`.
  **Xvfb и PulseAudio в образе НЕТ** — проверено по сырому Dockerfile, ставим сами.
- 🔴 **Главная грабля: `chromium.launch()` по умолчанию добавляет `--mute-audio`.** Без
  `ignoreDefaultArgs: ['--mute-audio']` null-sink будет писать **тишину, не выдав ни одной ошибки**.
  Это в точности тот класс молчаливых сбоев, за который проект уже платил (#171, #175, #178, #150).
- **ffmpeg:** у muxer'а `segment` **нет** опции нарезки по размеру в байтах — резать под лимит 25 МБ
  надо через `segment_time`, пересчитанный из известного битрейта AAC. `individual_header_trailer`
  включён по умолчанию (части открываются самостоятельно), `reset_timestamps` — **нет**, включать руками.
- **Node.js 20 мёртв** (EOL 30.04.2026 по официальному расписанию) → берём **Node 24 LTS**.
- **Трюк «вырезать `m=video` из SDP» не работает с Chromium M138** (июнь 2025), у нас 153 — путь мёртвый.
  Экономия памяти делается штатной настройкой Meet «Audio only» и флагами, а не правкой SDP.
- **dockerode** для управления контейнерами (прецедент — `github/dependabot-action`). Открытый вопрос:
  на какой стороне границы Windows/WSL2 живёт оркестратор.
- **Селекторы Meet:** сходящаяся практика всех найденных ботов — `aria-label`/`role` вместо классов,
  с поправкой на локаль и типографику (фигурный апостроф).

**Бот-детект — подтверждено из первых рук:** Google банит по флагу `--ignore-certificate-errors` и по
**датацентровым IP**; различает «нечеловеческие» клики (`isTrusted=false`) и требует ввода уровня ОС
(xdotool). Неожиданное следствие для нас: **домашний интернет MUSPELHEIM здесь преимущество**, а не
только риск — бытовой IP не попадает под датацентровые блокировки.

## Развилки для брейншторма

1. **Как захватывать звук.** Варианты: (а) PulseAudio-микс всех участников + таймлайн говорящих из
   DOM — как в спеке §4.3 и у Attendee; (б) тап аудиоэлемента **каждого участника** через Web Audio API
   прямо в странице — как у Vexa, даёт раздельные дорожки по людям.
   **Рекомендация: (а) на первый заход, (б) — кандидат на следующий.** Микс ложится в существующий
   контракт `meeting-ingest` (m4a-части ≤25 МБ) без его переделки, то есть даёт работающего бота
   быстрее всего. Вариант (б) решает «кто говорит» радикальнее (настоящие дорожки вместо угадывания по
   вёрстке), но отдаёт PCM, который надо кодировать, умножает объём на число участников и требует
   менять контракт приёма. Выбирать его до того, как замер покажет цену разметки, — это платить за
   точность, которой, возможно, хватает и так.

2. **Как бот попадает в Meet.** Варианты: (а) собственный Google-аккаунт бота, добавляемый в
   календарные приглашения; (б) гость по ссылке с ручным допуском каждый раз.
   **Рекомендация: (а).** Исследование показало, что (б) — не рабочий режим, а постоянное ожидание у
   двери: без приглашения автовхода нет вовсе. Требует решения владельца: завести аккаунт и определить,
   кто добавляет бота в приглашения — человек руками или автоматика по календарю. **Блокирует этап 1.**

3. **Где живёт токен бота.** Варианты: (а) отдельная таблица служебных агентов; (б) служебная строка в
   `allowed_users`.
   **Рекомендация: (а).** `allowed_users` — таблица **людей**: по ней считаются список команды,
   рассылки и статистика. Служебная строка в ней сделает бота «сотрудником» во всех этих выборках
   молча, и находить это придётся по одному месту за раз.

4. **Куда бот шлёт heartbeat.** Варианты: (а) в свою запись; (б) в строку человека, от имени которого
   работает.
   **Рекомендация: (а).** Поля `recorder_last_*` читает watchdog «оборванная запись» и панель ON AIR.
   Запись туда от бота означает, что система будет считать, будто у человека работает рекордер, — и
   погасит настоящий сигнал о проблеме. Это прямое производство молчаливого сбоя.

5. **Как бот раскрывает себя участникам.** Варианты: (а) говорящее имя в списке участников
   («Swarm Notetaker»); (б) плюс сообщение в чат звонка; (в) ничего сверх присутствия.
   **Рекомендация: (а).** Для внутренних встреч команды имя в списке — достаточное и самое тихое
   раскрытие, оно ничего не ломает в ходе разговора. Вариант (б) стоит держать как настройку на случай
   встреч с внешними людьми, а (в) отвергнуть: бот, которого не отличить от человека, — это то, за что
   судятся.

6. **Контур.Толк, когда дойдём (этап 4).** Варианты: (а) браузерный бот, как в Meet; (б) официальный
   Talk API `Recordings`.
   **Рекомендация: (а) как основной путь, но проверить (б) до стройки этапа.** API снимает всю
   хрупкость вёрстки, но работает только в пространстве, которым мы администрируем, — а значит
   покрывает лишь часть встреч. Проверка дешёвая и может сэкономить целый адаптер.

7. **Zoom, когда дойдём (этап 5).** Варианты: (а) веб-клиент под Playwright; (б) нативный Meeting SDK
   for Linux.
   **Рекомендация: (б).** Официальный SDK снимает класс поломок по селекторам целиком; цена — второй
   способ записи в кодовой базе.

8. **Где живёт оркестратор.** Варианты: (а) внутри WSL2 рядом с Docker; (б) на стороне Windows.
   **Рекомендация: (а).** Управление контейнерами через сокет Docker без пересечения границы
   Windows/WSL2 — меньше движущихся частей и меньше мест, где всё встанет незаметно.
