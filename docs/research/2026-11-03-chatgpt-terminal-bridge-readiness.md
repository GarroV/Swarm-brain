## Проверенный сценарий

Личные настройки Swarm → ChatGPT → «Получить команду установки» → копирование в
Терминал → проверка SHA-256 → установка отдельного stdio-моста → запись штатным CLI
в MCP-конфиг → перезапуск ChatGPT. Получение статуса и отдельный отзыв доступны в карточке.
Дополнительный веб-OAuth остаётся отдельным способом подключения.

Реальный встроенный CLI `/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex`
(`0.165.0-alpha.1.2`) установил и повторно установил сервер в изолированном тестовом
профиле. Сохранены чужой MCP-сервер, прочие настройки и подготовленный конфиг Claude.
Токен отсутствует в TOML/аргументах CLI, его файл имеет режим 0600. Официальный MCP SDK
загрузил command/args из этого установленного конфига, запустил launcher, получил
67 инструментов и выполнил whoami синтетического сотрудника. Это проверка настоящего
stdio→HTTP соединения; вызов моделью в личном GUI аккаунта сотрудника здесь не заявляется.

На настоящих API и БД выделенного стенда MUSPELHEIM проверены:

- одновременная пригодность отдельных токенов Claude и ChatGPT;
- перевыпуск ChatGPT: новый токен годен, старый отвергнут, Claude продолжает отвечать;
- отзыв ChatGPT не отзывает Claude;
- обновление собственного lastSeen после вызова клиента;
- отзыв ChatGPT триггером при смене роли; DB-suite дополнительно проверяет смену
  пространства и удаление пользователя. DB-suite работает транзакцией с rollback;
- тестовый пользователь после прогона возвращён к исходным роли и полям токенов.

Chrome for Testing, desktop/mobile, light/dark: выдача команды из карточки, настоящее
копирование в системный буфер, whoami, обновление lastSeen и отключение. API и UI работали
без подмены ответов. Использовался только синтетический сотрудник отдельного стенда.
При проверке исправлено чтение статуса из внутривкладочного кэша: для этого endpoint
явный no-store должен обходить requestCache, иначе обновление не видело обращение клиента.
