## Дополнительная проверка настоящей сессией Codex

По уточнению владельца проверку выполняет агент, а не владелец. Запущены настоящие
сессии `codex exec` (CLI 0.165.0, существующий вход через ChatGPT) с отдельным OAuth-доступом
к выделенному стенду. Конфигурация MCP передана только этим процессам; постоянные
настройки Codex и Claude не менялись. Разрешены только восемь инструментов задач этого
синтетического пространства. Модель действительно вызывала MCP, а не имитировала ответы.

Фактически выполнены: `whoami`, создание задачи, чтение, изменение названия и статуса
на `in_progress`, создание и чтение комментария. Проверка удалений прошла в два этапа:
первые вызовы получили от сервера `confirmation_required / executed=false`, последующие
вызовы после отдельного подтверждения удалили комментарий и задачу. Попытки изменить
задачу другого пространства и прочитать её комментарии получили отказ; в общем списке
этой задачи не было. Итоговые проверки второй сессии — все пять успешны, `error` пустой.

Состояние независимо проверено через API: своя задача даёт 404, название задачи другого
пространства не изменилось. Чужая тестовая фикстура удалена своим тестовым сотрудником,
временное OAuth-подключение отозвано. Журналы и временный драйвер проверки сохранены вне
репозитория в `~/Documents/workbench/private/swarm-mcp-native-agent/`; cookie/access/refresh
из итогового файла состояния удалены. Не публиковать сырые журналы: они содержат короткие
токены подтверждения.

Обнаруженное ограничение клиента: `approval_policy=never` блокирует destructive-инструменты
ещё до обращения к серверу, даже если пользователь разрешил тест. Для проверки применён
документированный `--approve-for-me`, ограниченный процессом и синтетическими объектами;
автоматическое согласование пропустило запросы, после чего проверен собственный серверный
двухшаговый механизм. Это настройка тестового клиента, не изменение защиты Swarm.

Отдельно проверена возможность управлять ChatGPT: инструмент Computer Use отказал в доступе
к `com.openai.codex` по собственному правилу безопасности; последующая инициализация
нативного браузерного транспорта завершилась `Sky Computer Use native pipe startup failed`.
Это не сообщение об отсутствующем разрешении macOS и не основание просить владельца искать
приложение «Computer Use» в системном меню. Подключённых браузеров инструмент не показал.
Поиск SwarmBrain в подключённом каталоге плагинов вернул пустой результат; инструмента
регистрации произвольного MCP в этом каталоге нет.

### Повторить подготовку

Собрать веб `npm ci` и `npm run build` в `miniapp/`. Передать исходники и экспорт на
MUSPELHEIM (без `.git`, node_modules, `.next` и private):

```sh
COPYFILE_DISABLE=1 tar -czf /tmp/swarm-chatgpt-source.tgz --exclude=node_modules --exclude=.next --exclude='._*' \
  supabase miniapp/functions miniapp/src miniapp/out deno.json deno.lock scripts
ssh muspelheim 'if not exist C:\projects\swarm-mcp-chatgpt-stand\source mkdir C:\projects\swarm-mcp-chatgpt-stand\source'
scp /tmp/swarm-chatgpt-source.tgz muspelheim:C:/projects/swarm-mcp-chatgpt-stand/source.tgz
ssh muspelheim 'tar -xzf C:/projects/swarm-mcp-chatgpt-stand/source.tgz -C C:/projects/swarm-mcp-chatgpt-stand/source'
ssh muspelheim 'powershell -NoProfile -File C:/projects/swarm-mcp-chatgpt-stand/source/scripts/mcp-chatgpt-stand.ps1 -Action Prepare'
ssh muspelheim 'powershell -NoProfile -File C:/projects/swarm-mcp-chatgpt-stand/source/scripts/mcp-chatgpt-stand.ps1 -Action Start'
```

`Prepare` затрагивает только выделенную БД; `Start` — только выделенные контейнеры.
Не выполнять во время чужого прогона именно этого выделенного стенда.

## Проверка безопасности и ограничения

AITriage portable 1.13.0 запущен на MUSPELHEIM; официальный SHA256 проверен, системная
установка не менялась. Все четыре сканера готовы. Raw-сравнение baseline/candidate:
18 → 27 результатов; новых error нет. Девять новых ENTR-04 warning срабатывают на имя
ChatGPT в названиях/импортах/инструкции и вручную признаны ложными срабатываниями.
Это сырой скан с ручным разбором разницы, **не** полный вердикт SecureCoder.

Remote-запуск тестового Deno-контейнера встречал esm.sh HTTP 520 при скачивании зависимостей.
DB-suite фактически выполнен Deno на Mac против отдельной удалённой БД через туннель;
продуктовые процессы и база работали на MUSPELHEIM. Локальные продуктовые серверы и Docker
на Mac не запускались.

Официальный SDK, настоящая сессия Codex и собственная браузерная часть проверены; реальное добавление сервера
через корпоративный интерфейс ChatGPT ещё требует совместной приёмки. Приватный
loopback-стенд недоступен облачному ChatGPT. Для такого прогона нужен согласованный
публичный HTTPS-адрес именно тестового контура либо [Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)
и разрешение рабочего пространства. Tunnel позволяет оставить стенд приватным, но требует
Platform tunnel ID и runtime API key с соответствующими правами; в окружении этой сессии
ни того, ни другого не было. Вход Codex через ChatGPT не является таким Platform API key.
Публикация такого адреса и создание подключения в аккаунте ChatGPT в этой подготовке
не выполнялись. Продовая раскатка остаётся отдельным действием с владельцем.
