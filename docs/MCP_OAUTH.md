# Подключение ChatGPT к SwarmBrain

Сотрудник подключает SwarmBrain в ChatGPT и работает со знаниями, задачами и встречами
в пределах своего пространства и существующих прав. Свой доступ он видит и отключает
в личных настройках Swarm. Карточка Claude Desktop остаётся рядом и использует свой токен.

**Статус: на проде с 30.10.2026, выпуск `efcf9020`.** OAuth и вызов `whoami` из облака
OpenAI проверены на публичном адресе; [отчёт выкладки](research/2026-10-30-chatgpt-mcp-deploy.md).
Создание коннектора непосредственно в браузерном ChatGPT пока не проверено.
Решение и граница раскатки —
[30.10.2026](decisions/2026-10-30-chatgpt-mcp.md). Пример сценария — Modius, задача #1084.

## Пользовательский путь

1. Открыть Swarm → личные настройки → ChatGPT, скопировать адрес MCP.
2. В браузерном ChatGPT открыть Plugins → Add custom MCP server. В интерфейсе с Apps /
   Connectors найти добавление собственного MCP. Вставить адрес, выбрать OAuth, создать
   и установить подключение. Возможность зависит от политики рабочего пространства.
3. Войти в Swarm обычным способом и пройти обязательный второй шаг. Экран согласия
   показывает приложение, адрес возврата, сотрудника и пространство. Разрешить доступ.
4. В чате выбрать SwarmBrain и спросить: «Покажи, кто я в SwarmBrain».
5. В карточке Swarm проверить последнее обращение. Само согласие до первого обращения
   отображается как ожидание. «Отключить» прекращает доступ выбранного приложения.

Терминал не нужен. Публикация в общем каталоге не требуется для пользовательского MCP.
Если добавление запрещено, доступ разрешает администратор рабочего пространства ChatGPT.
Названия меню зависят от доступного интерфейса; ограничения тарифов здесь не фиксируются.

## Поверхности и сквозной вход

| Поверхность | Назначение | Реализация |
|---|---|---|
| Личные настройки → ChatGPT | Инструкция, адрес, приложения, отзыв | `ChatGptSection`, `ConnectorsSection` |
| Главная с `?mcp_oauth=<request>` | Согласие после обычного входа и второго шага | `McpOAuthConsent`, `app/page.tsx` |
| OAuth на домене веба | Discovery, регистрация, код, токены, отзыв | Pages Functions → `swarm-oauth` |
| MCP на домене API | Те же инструменты для разных клиентов | `swarm-mcp` |

Issuer — `WEB_BASE_URL`, ресурс — `SWARM_PUBLIC_URL/functions/v1/swarm-mcp`.
Непрозрачный запрос согласия передаётся в URL, но код и токены там не сохраняются.
Одноразовый код возвращается только на точно зарегистрированный callback клиента.
PKCE S256 связывает код с подключающим клиентом; `resource` связывает токен с MCP.

## Публичные маршруты

| Метод и путь на домене веба | Ответ |
|---|---|
| `GET /.well-known/oauth-authorization-server` | Issuer, endpoints, PKCE S256, DCR, grants |
| `GET /.well-known/oauth-protected-resource` | Адрес MCP и issuer |
| `POST /oauth/register` | Регистрация публичного OAuth-клиента без client secret |
| `GET /oauth/authorize` | Проверка параметров, короткий запрос согласия, переход в Swarm |
| `POST /oauth/token` | Обмен кода либо refresh, новая пара токенов |
| `POST /oauth/revoke` | Отзыв; неизвестный токен не раскрывается |

Pages проксирует эти пути в `swarm-oauth`, используя `SWARM_API_URL` для выбора
контура, и не передаёт пользовательскую cookie или Authorization. Redirect не следует
на сервере. Секреты в ответах не кэшируются.

## Маршруты личной сессии

| Метод и путь относительно `/api` | Назначение |
|---|---|
| `GET /mcp/oauth/authorize?request=<id>` | Приложение, callback host, пространство, срок запроса |
| `POST /mcp/oauth/authorize` | `{requestId,accept}` → `{redirectUrl}` |
| `GET /mcp/connections` | `{mcpUrl,connections}` текущего сотрудника и пространства |
| `DELETE /mcp/connections/:id` | Отзыв своего подключения |

Маршруты стоят после существующих auth, second-step и maintenance gates; демо и
короткие обменные сессии не принимаются. Cookie-прокси дополнительно требует совпадение
Origin при изменении OAuth-настроек. Личность и пространство не берутся из тела запроса.

## Совместимость MCP

Без токена и с негодным OAuth Bearer MCP отвечает HTTP 401 и `WWW-Authenticate` с
явным адресом метаданных на домене веба. Это запускает вход в ChatGPT. Установленный
Claude с `smcp_` сохраняет прежнее рукопожатие и диагностические JSON-RPC ошибки.
GET с заголовком авторизации отвечает 405: сервер использует POST и не держит SSE-сессию.
Проверка личности, видимости, подтверждение опасных действий и журнал общие для клиентов.

OAuth-подключение хранится отдельно от `allowed_users.claude_mcp_token_hash`.
Карта `clientKind` в интерфейсе определяется callback host и служит только для подписи
статуса; это не удостоверение подлинности приложения.

## Хранение и отзыв

Миграция `20261030150000_mcp_oauth.sql` создаёт шесть закрытых таблиц:

| Таблица | Данные |
|---|---|
| `mcp_oauth_clients` | Имя клиента и точный список callback URI |
| `mcp_oauth_requests` | Запрос согласия, PKCE, resource, scope; срок 10 минут |
| `mcp_oauth_connections` | Сотрудник, пространство, приложение, callback, последнее обращение; максимум 30 дней |
| `mcp_oauth_codes` | Хэш одноразового кода; срок 5 минут |
| `mcp_oauth_tokens` | Хэши access/refresh, вид, срок и отметка расходования |
| `mcp_oauth_rate_buckets` | Атомарные счётчики публичных запросов |

Access живёт до часа, refresh ротируется и не продлевает исходные 30 дней подключения.
Повтор использованного кода/refresh с правильным клиентом и параметрами отзывает всё
подключение. Ошибочный PKCE не отзывает чужой доступ. Смена роли/пространства отзывает
подключения триггером, удаление сотрудника — каскадом; MCP проверяет членство заново.
Токены, коды и обновление проверяются SQL RPC с блокировками строк и одной транзакцией.
RLS и явные REVOKE закрывают таблицы/RPC от anon и authenticated; служебные операции
разрешены service_role. Устаревшие записи очищаются ограниченными порциями при запросах.

Публичные ответы об ошибке авторизации после проверки клиента и callback возвращают
`error`, исходный `state` и `iss` на зарегистрированный callback. Ошибочный callback
никогда не используется для редиректа. Service worker пропускает OAuth, discovery и
навигацию с `mcp_oauth` напрямую в сеть, без Cache Storage или офлайн-подмены.

## Развёртывание и проверка

Нужны миграция `20261030150000_mcp_oauth.sql`, функция `swarm-oauth`, обновлённые
`swarm-api` и `swarm-mcp`, затем веб с OAuth-прокси. `WEB_BASE_URL` должен точно совпадать
с публичным issuer, `SWARM_PUBLIC_URL` — с доменом API; localhost HTTP разрешён только
для изолированного стенда. Старые экземпляры MCP продолжают принимать статический токен
Claude; OAuth проверяется после согласованного обновления всех частей.

Удалённый стенд и результаты проверок — [отчёт приёмки](research/2026-10-30-chatgpt-mcp-readiness.md).
Раскатка на прод выполняется отдельно с владельцем и в установленное ночное окно.

## Источники и термины

- [OpenAI: custom MCP](https://developers.openai.com/api/docs/guides/custom-mcp-server)
- [OpenAI: OAuth](https://developers.openai.com/plugins/build/auth)
- Issuer — сервер, выдающий доступ; resource — конкретный MCP, которому этот доступ подходит.
- DCR — регистрация OAuth-клиента при подключении; PKCE — защита обмена одноразового кода.
