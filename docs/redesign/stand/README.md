# Стенд редизайна — как открыть, проверить и отдать коллегам

Живой прототип нового интерфейса Swarm: настоящая вёрстка и настоящее поведение на
вымышленных данных. Бэкенда нет, ничего не сохраняется, перезагрузка возвращает
исходное состояние. Это черновик для обсуждения, а не продукт.

## Открыть у себя

```sh
open docs/redesign/stand/index.html            # прямо файлом
python3 -m http.server 8787 --bind 127.0.0.1 --directory docs/redesign/stand   # по адресу
```

## Отдать коллегам

**https://garrov.github.io/Swarm-brain/** — GitHub Pages из ветки `stand`.

```sh
sh docs/redesign/stand/publish.sh
```

Скрипт сам прогоняет `check.js` (красную вёрстку наружу не катим), собирает ветку
`stand` **только** из стенда и перезаписывает её целиком. Ветка `stand` — витрина, а не
история: хранить в ней что-либо бессмысленно, следующая раскатка сотрёт. Исходник живёт
здесь, в `docs/redesign/stand`, на рабочей ветке.

Стенд закрыт от поисковиков (`noindex` + `robots.txt`), но ссылку откроет любой, кто её
получил: репозиторий публичный. Ничего, что нельзя показывать наружу, в данные стенда
класть нельзя — они лежат в `js/data.js` открытым текстом.

## Проверить

```sh
node docs/redesign/stand/check.js         # обычный прогон: обязан быть зелёным
node docs/redesign/stand/check.js break   # негативный: каждое правило обязано упасть
```

Прогон щёлкает по стенду как человек и **сверяет** результат: плотность, обрезки,
выравнивание, число колонок, поведение кнопок. Снимки складывает в
`/tmp/swarm-stand-shots`. Новое правило считается правилом только после того, как
доказано, что на нарочно сломанной вёрстке оно падает.
