# Критический разбор стенда против продукта

Сверено 20.09.2026 с `origin/main` (8540037). Источники правды: `miniapp/src/lib/smartLists.ts`,
`lib/meetingsFilters.ts`, `lib/feedbackCategories.ts`, `components/roy/ui.tsx`,
`components/tasks/*`, `components/AdminScreen.tsx`, `components/SettingsScreen.tsx`.

## Что было не так

1. **Стенд собран тремя слоями обёрток.** Каждое дополнение оборачивало предыдущий экран и
   правило готовую разметку строковыми заменами и регулярками. Работает, но любое следующее
   изменение ломает предыдущее молча. Это главная причина переписать основу, а не дописать
   четвёртый слой.
2. **Словарь статусов не совпадал с продуктом.** В стенде `todo/doing/wait/done`, в продукте —
   `open / in_progress / done` (`STATUS_META`), а «Ждёт» не существует вовсе. Фильтр статусов в
   продукте — мультивыбор ПОВЕРХ оси времени, по умолчанию «открыта + в работе».
3. **Приоритеты выдуманы.** В стенде `P1/P2`, в продукте — `high / med / low` (`PRI_COLOR`).
4. **Данных было девять задач и шесть встреч.** На такой выборке не видно ни линз, ни
   группировки по рынкам, ни фильтров: любой срез выглядит одинаково.
5. **Действия были декоративными.** Кнопки открывали модалку, но ничего не меняли: задача не
   создавалась, фильтры-чипы не фильтровали, комментарий не добавлялся, статус не менялся.
6. **Фильтры встреч были тремя заглушками.** В продукте это шесть осей: строка поиска, период
   (всё / неделя / месяц / квартал / произвольный), страны, источники, люди, хранилище
   (общее / личное), статус (подтверждена / ожидает).
7. **Категории фидбека были выдуманы.** В продукте их одиннадцать и они зафиксированы кодами:
   bumblebee, встречи, поиск, задачи, база знаний, дайджест, вход, интеграции, Claude/MCP,
   интерфейс, другое.
8. **Целых поверхностей не было.** Очередь вычитки агентских встреч (`MeetAdminScreen` — 1752
   строки, самый большой экран продукта), сбор задач из встречи, таймлайн, пул инициатив
   спринта с диалогом приёмки, редактор меток, выбор страны, профиль пользователя в админке с
   привязкой email, рассылка, команды установки рекордера, генерация дайджеста, подключение
   Google и Granola, выход из аккаунта.

## Что сделано вместо этого

Стенд переписан на явную основу: данные → хранилище состояния → экраны. Ни одной строковой
правки чужой разметки. Действия меняют состояние и перерисовывают экран, фильтры считают по
данным, а не по подписям. Данных заведено столько, чтобы срезы отличались друг от друга.

Файлы: `stand/js/data.js` (тестовые данные), `store.js` (состояние и действия),
`ui.js` (атомы), `screens-*.js` (экраны), `detail.js` (правая панель), `app.js` (каркас).
Проверка — `node docs/redesign/stand/check.js`, негативный прогон — `check.js break`.
