## Что показала сверка с продом (факты, 21.09.2026)

- **Приоритет** — не выдуман: `tasks.priority` есть в схеме, в мобильном Roy
  (`NewTask.tsx` — Segmented high/med/low, `TaskDetail.tsx` — PriDot, `TaskRow.tsx` —
  отметка у high, `smartLists.ts` — сортировка). Но в ДЕСКТОПНОЙ модалке
  (`TaskModal.tsx`) поля приоритета нет, и в проде он заполнен у 6 задач из 481
  (high 2, med 3, low 1). Вывод: постоянного места в панели не заслуживает.
- **Роли** — в проде их ДВЕ разных: роль человека (`users.role`, правится админом
  свободным текстом в `AdminScreen.tsx`, подписывается словарём `ROLE_LABELS` в
  `TeamScreen.tsx`) и роль задачи (`tasks.task_role`). Набор в обоих случаях зашит в
  код: `marketing / bd / rnd`. Поле роли задачи в модалке СКРЫТО флагом
  `SHOW_TASK_ROLE = false` («данные продолжают сохраняться на уже размеченных»),
  размечено 76 задач из 481. **Админки набора ролей нет ни для той, ни для другой.**
- **Метки = «Списки»** — в проде `task_labels` показываются как «Списки»/«Lists»
  (`TaskModal.tsx`, `LabelEditor.tsx` — имя + пиктограмма). Они ЛИЧНЫЕ, и выбор списка
  делает задачу личной: `if (labelIds.length > 0 && !task.is_private) patch.is_private = true`.
- **Быстрые чипы** — `TaskQuickActions.tsx` в строке задачи:
  СРОК / ПИНГ / ЦИКЛИЧНОСТЬ (только у задачи со сроком) / ИСПОЛНИТЕЛЬ / РЫНОК / СПИСКИ,
  каждый выбор патчит задачу оптимистично.
