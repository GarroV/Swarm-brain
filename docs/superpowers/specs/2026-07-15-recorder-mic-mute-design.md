# Рекордер: ручной мьют своей микрофонной дорожки

> Дизайн-спека. Дата: 2026-07-15. Ветка: `sandbox_vas`. Компонент: `recorder/` (macOS, Swift).

## 1. Проблема

Рекордер пишет две дорожки: системный звук (собеседники) и микрофон (я). Микрофон
захватывается напрямую с устройства ввода ОС через `AVAudioRecorder` (`AudioRecorder.swift`).
Когда пользователь жмёт **Mute в самом созвоне** (Zoom/Meet/Teams/Контур), это софтовый мьют
*внутри того приложения* — оно перестаёт слать звук в звонок, но микрофон-устройство ОС
продолжает выдавать сигнал. Наш рекордер — отдельный процесс, поэтому продолжает писать
полный звук с микрофона даже при «выключенном» микрофоне в созвоне.

### Что технически невозможно (зафиксировано, не переоткрывать)

Надёжно **детектировать состояние кнопки Mute в стороннем созвоне нельзя**: это состояние живёт
внутри процесса Zoom/Meet/Teams, публичного API прочитать его снаружи нет. Косвенно тоже не
отличить — софтовый мьют не освобождает микрофон, `CallDetector.othersUsingMic` всё равно видит
приложение. Отвергнутые пути: device-level mute (`kAudioDevicePropertyMute`) покрывает только
аппаратный мьют и часто не репортится встроенным микрофоном; эвристика по тишине путает молчание
с мьютом; чтение UI-кнопки через Accessibility API хрупко и не работает для браузерных созвонов.

## 2. Решение

Ручной мьют **своей** дорожки, управляемый пользователем в рекордере (не синхронизируется с
кнопкой в созвоне — её состояние недоступно). Два способа включить/выключить:

1. **Тумблер в плавающем виджете** — клик по иконке микрофона.
2. **Пункт меню статус-бара** — «🔇 Заглушить мой микрофон» / «🎤 Включить мой микрофон».

Глобального хоткея нет (осознанное решение — убирает Carbon-обёртку и её грани).

### Семантика мьюта

- Мьют влияет **только на микрофонную дорожку**. Системная дорожка (собеседники/коллеги)
  пишется всегда — как сейчас.
- Запись всегда **стартует размьюченной**. Поведение по умолчанию не меняется.
- При мьюте текущий mic-сегмент закрывается; замьюченный промежуток **отсутствует** в моей
  дорожке — в стенограмме меня в нём не будет. При размьюте открывается новый mic-сегмент.
- Тайминги остаются выровненными с системной дорожкой (см. §3).
- **Авто-стоп и детект конца звонка не затрагиваются** — они смотрят на системную дорожку и
  чужой микрофон (`CallDetector`), а не на нашу запись. Мьют своей дорожки на них не влияет.

## 3. Почему это ложится в существующую архитектуру без изменения сервера

Контракт загрузки **уже** принимает несколько mic-частей с offset'ами:
`SwarmClient.uploadAudio(mic: [AudioPart])` шлёт манифест `mic_parts` = `[{name, offset}]`; сервер
(`meeting-ingest/index.ts:148`) собирает части и сводит по offset'ам. Это тот же механизм, что уже
работает для **системной** дорожки при пересборках тапа (`systemSegments` + `Segmenter.segmentTrack`,
композиция offset'ов на `Segmenter.swift:45`). Мьют = «закрыть текущий mic-сегмент, при размьюте
открыть новый» — симметрично системной дорожке.

**Модель времени (сохраняется как есть):**
- `micStartOffset` = (uptime первого реального mic-сэмпла) − (uptime первого системного сэмпла).
  Отправляется в **claim** (`AppDelegate.performSend` → `ClaimRequest.micStartOffset`), сервер
  применяет его ко **всей** mic-дорожке как глобальный сдвиг mic↔system.
- Base-offset каждого mic-сегмента = (uptime старта сегмента) − (uptime первого mic-сэмпла).
  Первый сегмент → 0.
- Итоговое место куска на общей ленте (на сервере):
  `whisper_ts + segBaseOffset + micStartOffset = whisper_ts + (segStart − sysFirst)`. ✓ Корректно.

**Сервер не трогаем вообще.**

## 4. Изменения (только клиент, Swift)

### 4.1 `AudioRecorder.swift`

- Новое состояние:
  - `private var micMuted = false`
  - `private var micSegments: [(url: URL, offset: Double)] = []` — закрытые сегменты своей дорожки.
  - `private var micSegIndex = 0` — счётчик файлов.
  - `micFirstSampleUptime` (уже есть) — база для `micStartOffset`; ставится на первом реальном
    сэмпле **первого** сегмента.
  - `private var currentMicSegStartUptime: Double?` — старт текущего активного сегмента.
- Именование файлов сегментов: производим от переданного `micURL`, вставляя индекс перед
  расширением: `…-mic0.m4a`, `…-mic1.m4a`, … Первый сегмент = индекс 0.
- `Result`: `mic: URL?` + `micStartOffset: Double?` → **`micSegments: [(url: URL, offset: Double)]`**
  (0…N сегментов; offset относительно первого mic-сэмпла) + `micStartOffset: Double?` (без изменений).
- Новый метод `func setMicMuted(_ muted: Bool)`:
  - **Мьют** (`true`, был размьючен, идёт запись): `micRecorder.stop()`; если файл > 1024 байт —
    добавить `(url, offset = currentMicSegStartUptime − micFirstSampleUptime)` в `micSegments`
    (первый сегмент → offset 0). `micRecorder = nil`, `micActive = false`, `micMuted = true`.
  - **Размьют** (`false`, был замьючен, идёт запись): создать новый `AVAudioRecorder` в файл
    `…-mic<N>.m4a` (N = ++micSegIndex), `record()`; на успехе — `currentMicSegStartUptime = uptime`,
    и если `micFirstSampleUptime == nil` (запись фактически началась замьюченной) — выставить его
    сейчас. `micMuted = false`, `micActive = true`. Best-effort: сбой → остаёмся без mic (как сейчас).
- `func isMicMuted() -> Bool` — для UI.
- `start(...)`: инициализирует первый сегмент как сейчас (индекс 0), `micSegIndex = 0`,
  `micMuted = false`, `micSegments = []`, `currentMicSegStartUptime` на успешном `record()`.
- `stop()`: если mic активен — закрыть текущий сегмент (добавить в `micSegments` как при мьюте);
  собрать `micStartOffset = micFirstSampleUptime − systemFirst` (только если есть хоть один
  mic-сегмент и оба якоря известны). Вернуть `micSegments` в `Result`.
- `currentMicLevel()`: при мьюте `micRecorder == nil` → уже возвращает 0 (полоса плоская). Не менять.

### 4.2 `RecorderWidget.swift`

- `micIndicator` делаем кликабельным (`NSClickGestureRecognizer`, как `recMark` на `:138`).
- `var onToggleMic: (() -> Void)?`
- `func setMicMuted(_ muted: Bool)`:
  - Замьючен: иконка `mic.slash.fill`, tint серый (`NSColor(white:1,alpha:0.5)`), пульс выключен,
    амбер-полоса плоская (level meter даёт 0 сам). Tooltip: «Мой микрофон заглушён — нажмите,
    чтобы включить».
  - Размьючен: `mic.fill`, красный, пульс включён. Tooltip: «Мой микрофон пишется — нажмите,
    чтобы заглушить».
- `showRecording(...)`: сбрасывать в размьюченное состояние (запись всегда стартует размьюченной).

### 4.3 `UploadQueue.swift`

- `PendingUpload`: `micPath: String?` → **`micSegments: [Segment]`** (переиспользуем существующий
  `Segment{path, offset}`). `micStartOffset` остаётся.
- **Толерантный декод (не терять записи в очереди на момент апдейта):** кастомный `init(from:)` —
  читать `micSegments` если есть; иначе fallback на старый `micPath` → один `Segment(path, offset:0)`.
  Кодировать всегда в `micSegments`.
- `enqueue(...)`: принимать `micSegments: [(url, offset)]` вместо `micURL`/`micStartOffset`-одиночки;
  переносить несколько mic-файлов (`mic0.m4a`, `mic1.m4a`, …), сохранять их offset'ы.
  `micStartOffset` по-прежнему кладём в meta.
- `upload(...)`: `micParts = try await Segmenter.segmentTrack(micSegs)` вместо
  `Segmenter.segment(micURL)` — offset'ы композируются (`Segmenter.swift:45`), нарезка по 25 МБ
  работает как для системной дорожки. Чистка промежуточных файлов — по аналогии с sys.

### 4.4 `AppDelegate.swift`

- `performSend` (`:890`): `enqueue(..., micSegments: p.res.micSegments, ...)` вместо `micURL: p.res.mic`.
  `micStartOffset` в `ClaimRequest` (`:871`/`:881`) — без изменений.
- Defer-cleanup при `decision=defer` (`:909`): вместо `if let m = p.res.mic` — цикл по
  `p.res.micSegments`.
- Виджет: `widget.onToggleMic = { [weak self] in self?.toggleMicMute() }`.
- Новый `toggleMicMute()`: `recorder.setMicMuted(!recorder.isMicMuted())`, затем
  `widget.setMicMuted(recorder.isMicMuted())` и `rebuildMenu()`.
- Меню статус-бара (блок recording, рядом с «Остановить и отправить» `:376`): пункт
  «🔇 Заглушить мой микрофон» / «🎤 Включить мой микрофон» (заголовок по `recorder.isMicMuted()`),
  action → `toggleMicMute()`.
- `LiveNotesPanel` (Granola-режим): вне scope v1 — тумблер живёт в виджете-пилюле и меню. Если
  пользователь в блокноте — мьютит через меню статус-бара. (Возможное расширение — §7.)

## 5. Поток данных (мьют посреди записи)

```
start           → mic0 пишется, micFirstSampleUptime=t0, currentSegStart=t0
[мьют в t1]     → mic0.stop(); micSegments=[(mic0, 0)]; micRecorder=nil
[размьют в t2]  → mic1 пишется; currentSegStart=t2
[стоп в t3]     → mic1.stop(); micSegments=[(mic0,0), (mic1, t2−t0)]
                  micStartOffset = t0 − sysFirst
enqueue         → переносит mic0.m4a, mic1.m4a + offset'ы в pending/
upload          → segmentTrack → mic_parts=[{mic0,0},{mic1,t2−t0}] (+ нарезка по 25МБ)
claim           → micStartOffset=t0−sysFirst
сервер          → mic0 в [t0..t1], mic1 в [t2..t3] на общей ленте; [t1..t2] меня нет ✓
```

## 6. Граничные случаи

- **Мьют сразу после старта, файл mic0 < 1024 байт** → сегмент пропускается (как сейчас `size>1024`).
- **Запись фактически началась замьюченной** (мьютнул до первого сэмпла) → `micFirstSampleUptime`
  выставляется на первом размьюте; `micStartOffset` = этот момент − sysFirst; первый сегмент offset 0.
- **Мьют на всю встречу** → `micSegments` пуст → `mic=[]` → сервер использует только систему
  (существующее best-effort поведение, `mic=nil`).
- **Нет доступа к микрофону** → как сейчас: mic не стартует, тумблер визуально доступен, но
  сегментов нет; `micSegments` пуст. (Тумблер при отсутствии mic — можно дизейблить; минорно.)
- **Апдейт приложения с pending-записью старого формата** (`micPath`) → толерантный декод
  (§4.3) не теряет её.
- **Мьют во время авто-стопа / зависшего HAL-teardown** → мьют только финализирует mic-сегмент,
  на системный стоп не влияет; порядок в `stop()` сохраняется.

## 7. Вне scope v1 (не делаем)

- Синхронизация с кнопкой Mute в созвоне (технически невозможно, §1).
- Глобальный хоткей (осознанно отвергнут).
- Тумблер внутри `LiveNotesPanel` (блокнот) — пока только виджет-пилюля и меню.
- Device-level mute listener, эвристика по тишине, Accessibility-чтение UI.
- Индикация мьюта в heartbeat / на сервере.

## 8. Тестирование

- **`--selftest`** (расширить): старт → `setMicMuted(true)` посреди → `setMicMuted(false)` →
  `stop()` → проверить, что `Result.micSegments` содержит 2 сегмента с монотонно растущими,
  корректными offset (второй ≈ длительность паузы + первого сегмента) и `micStartOffset` задан.
- **Ручной e2e** на реальном созвоне (правило «Test yourself» — прогнать самому): записать
  встречу, замьютить ~30с посреди, отправить, дождаться стенограммы; проверить, что в замьюченном
  промежутке моих реплик нет и после размьюта я корректно выровнен относительно собеседника.
- **Сборка**: `swift build` в `recorder/` зелёный. Сервер не трогаем → `deno check` не требуется.
- **Регрессия**: обычная запись без мьюта → `micSegments` из одного сегмента (offset 0), поведение
  и тайминги идентичны текущим; старый pending-формат декодится.
