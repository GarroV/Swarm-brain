# «Анализ рынка» через MCP: шаблон отчёта и инструменты

Решение владельца 03.10.2026 ([decisions](../../decisions/2026-10-02-market-follow-reference-visual.md#03102026--ручная-часть-через-mcp-а-не-файлами)): «давай сделаем шаблон такого отчета, и сделаем инструменты для работы с этим шаблоном, у нас же есть мсп»; «чтобы в будущем в раздел "карта" можно было заложить через мсп новую информацию. или там раздел "оценки", тоже чтобы все подтягивалось»; «я хочу чтобы можно было через клод десктоп через коннекторы подгрузить или поправить информацию».

## Что получает владелец

В Claude Desktop, через уже подключённый коннектор Swarm, можно:

- спросить «что не заполнено по Болгарии» и получить список по разделам экрана;
- внести или поправить данные любого раздела — карта, деньги, оценки, цены, события, сводка, доставка и остальные блоки эталона — обычной просьбой: «добавь выручку Сънфудс за 2024 год, вот отчёт»;
- увидеть результат на экране «Анализ рынка» сразу, без файлов, токенов и кнопки импорта.

Автоматика (OSM, API Dodo, реестры) работает как раньше. MCP закрывает то, что автоматика не берёт.

## Ручное и автоматическое вместе

Владелец: «но при этом чтобы информация в то же время сама собиралась». Поэтому MCP — второй вход в те же таблицы, а не замена сбора:

- автоматические сборщики продолжают ходить по расписанию и пишут в те же строки;
- запись через MCP получает проверку `confirmed` — автоматика её не перетирает и не удаляет (OSM удаляет только свои непроверенные точки), а новое, чего в ручной записи нет, дописывает сама;
- `market_status` показывает по каждому разделу, что приходит само, а что держится на ручном вводе и сколько ему дней, — видно, где ручное устарело.

## Шаблон отчёта

Шаблон — это перечень разделов экрана и того, что их питает. Живёт в коде, в одном месте (`_shared/market/template.ts`), и собирается из уже существующего: блоки ручной части — из `EDITORIAL_BLOCKS` (`_shared/market/editorial.ts`), к ним добавляются точки, сети, финансы юрлиц, цены. На каждый раздел: название, откуда данные (авто / вручную), какие поля, пример заполнения, правило источника.

Тот же шаблон отдаёт инструмент `market_template` — модель в Desktop читает его и знает, что и в какой форме писать. Отдельный документ-инструкция дублировать его не будет.

## Инструменты MCP (модуль `swarm-mcp/market.ts`)

| Инструмент | Что делает |
|---|---|
| `market_template` | разделы, поля, примеры, правила источника |
| `market_status` `country` | по каждому разделу: заполнен ли, сколько записей, дата последнего обновления и чем (авто / MCP / снимок) |
| `market_get` `country`, `section`, фильтры | что записано сейчас: блок целиком, юрлица с годами, точки сети или города (с лимитом) |
| `market_set_block` `country`, `block`, `payload`, `source` | записать блок ручной части целиком (сводка, события, оценки, доставка, таблица пиццерий, корзина, факты…); форма проверяется по `EDITORIAL_BLOCKS` |
| `market_set_company_year` `country`, `chain`, `company`, `reg_id`, `year`, `revenue`, `currency`, `employees?`, `source`, `note?` | выручка юрлица за год; валюта с фиксированным курсом (BGN, HRK) пересчитывается в евро, иначе — только EUR |
| `market_upsert_location` `country`, `chain`, адрес, город, координаты, `opened?`, `closed?`, `source` | добавить или поправить точку на карте; закрытие — дата закрытия, не удаление |
| `market_upsert_chain` `country`, `key`, `name`, тип (пицца / пекарня / прочее) | завести сеть, которой ещё нет в стране |
| `market_set_price` `country`, `chain`, позиция, цена, `source` | цена позиции сети |

Правила для всех записей:

- **Источник обязателен** — ссылка или явная пометка («внутренняя выгрузка Dodo»). Без него запись отклоняется с понятной причиной.
- **Прибыль не принимается** нигде (правило раздела: прибыль/убыток не показываем) — поле с прибылью отклоняется, как в импорте.
- Ответ на запись возвращает, что было и что стало, — поправка делается повторной записью.
- Записи через MCP помечаются `source_kind = 'manual'`, проверка `confirmed`, автор — telegram id. Автоматика проверенные вручную записи не перетирает (действующее правило).
- Каждая запись отмечается в «Источниках и свежести» как ручной источник «MCP» с датой — экран честно показывает возраст ручных данных; дата сборки в баннере остаётся датой автоматики.

## Доступ

- Чтение (`market_template`, `market_status`, `market_get`) — тем, кто видит страну на вебе (`canSeeCountry` по `allowed_markets` воркспейса).
- Запись — только админу (та же проверка, что у импорта снимка и решений по находкам).
- Личность — из токена MCP, как у всех инструментов (`withCallerIdentity`).

## Что с импортом снимка

Остаётся как разовая массовая заливка (так зашла Хорватия), но из обычной работы уходит: README раздела описывает работу через Desktop. Уже сверенные выручки Болгарии вносятся первым живым прогоном `market_set_company_year`.

## Проверка

- Ядро (данные, которые читают как факт): тесты базы на каждую запись — форма, обязательный источник, отказ по прибыли, отказ не-админу, пересчёт валюты, «было/стало»; каждый тест прогнан и на сломанной копии.
- Живой прогон после раскатки: внести через MCP выручки Болгарии, сверить строками в базе и экраном.

## Раскатка

Функции `swarm-mcp` — кнопкой раскатки в ночное окно и по «да» владельца. Миграция не нужна: `source_kind = 'manual'` и режим `manual` у источников уже есть в схеме.
