# Дизайн: словарь имён собственных для тезисов встреч («лёгкое ядро»)

- **Дата:** 2026-07-30
- **Ветка:** `worktree-meeting-naming` (worktree-изоляция), слив в `main` через merge
- **Статус:** одобрен владельцем (объём: лёгкое ядро)
- **Триггер:** тезисы встреч коверкают имена собственные (бренды, названия пиццерий, города)

---

## 1. Проблема

Тезисы встреч (`draft_notes_md`) выдают уверенно-неверные имена собственные. Пример с реальной встречи прода `098380b7-0a9c-43bd-98ce-1a5abf020819` («Dodo Pizza Serbia», source `desktop-agent`/рекордер):

| В тезисах (неверно) | Должно быть |
|---|---|
| `Volt` / `Volt Drive` | **Wolt** / **Wolt Drive** (финский агрегатор доставки, работает в Сербии) |
| `Billbride 1/2` | **Београд 1/2** (пиццерия по названию города + номер) |
| `Noveside 1` | **Нови Сад 1** (пиццерия по названию города + номер) |

Это не критичный баг, а **полировка доверия**: система выглядит так, будто «знает», а на деле подставляет знакомое английское слово вместо реального бренда/места. `Volt` особенно коварен — выглядит корректно и проходит вычитку незамеченным (в отличие от явно-кривого `Billbride`).

## 2. Корневая причина (диагностика на реальных данных)

Нейминг ломается в **два независимых шага**:

1. **Whisper (`whisper-1`, транскрибация)** решает, что язык русский, и пишет имена фонетикой «как услышал». В сырой стенограмме встречи `098380b7` буквально: «вольт», «вольт-драйв», «билбрайд 1», «билбрайд 2», «новейсайд 1». Это акустическая ошибка — до конца не лечится, но словарь-подсказка (`prompt`) снижает частоту.

2. **LLM тезисов (`gpt-5.6-terra`)** берёт эту кириллическую фонетику и **по своей инициативе транслитерирует её в латиницу**: «вольт» → `Volt`, «билбрайд» → `Billbride`, «новейсайд» → `Noveside`. В промпте `TEZISY_CORE` нигде не сказано «переводи названия на английский» — модель делает это сама («бренды принято латиницей») и делает уверенно-неправильно. **Это главный и легко-чинимый источник недоверия.**

Проблема специфична для **рекордерного пути (Whisper)**. Заметки Granola/Read.ai приходят с уже написанными названиями (в granola-заметке тот же Volt был корректным).

## 3. Область (объём: лёгкое ядро)

**Делаем:**
- Правило в промпте тезисов: не выдумывать латиницу; приоритет словаря; неизвестное — оставлять как в стенограмме.
- Маленький сид-словарь **в коде** (не в БД).
- Whisper-хинт `prompt` каноническими именами (best-effort).
- Юнит-тесты на чистые функции словаря + проверка на реальной встрече.

**НЕ делаем сейчас (осознанно отложено, YAGNI):**
- Таблица `meeting_glossary` в БД.
- Веб-админка редактирования.
- Авто-детектор кандидатов + инбокс подтверждения.
- Regex-пост-обработка тезисов (полагаемся на LLM-нормализацию).
- Бэкфилл-переобработка старых встреч массово (только точечная проверка на `098380b7`).

Причина: владелец обозначил проблему как полировку доверия, а не критичный баг; официального списка названий нет; набор имён мал и меняется редко. Если словарь начнёт часто меняться руками — вернёмся к БД+админке отдельной задачей.

## 4. Дизайн

### 4.1 Новый модуль `supabase/functions/_shared/glossary.ts`

Единый источник правды (DRY), по образцу `tezisy-prompt.ts` / `feedback-categories.ts`.

```ts
export interface GlossaryEntry {
  canonical: string;   // как писать в тезисах
  aliases: string[];   // whisper-искажения / варианты (lowercase, для подсказки LLM)
  note?: string;       // короткий контекст для модели
}

export const MEETING_GLOSSARY: GlossaryEntry[] = [ /* сид ниже */ ];

// Блок для промпта тезисов (LLM-нормализация — основной рычаг).
export function glossaryPromptBlock(entries?: GlossaryEntry[]): string;

// Строка канонических имён для Whisper-параметра `prompt` (best-effort, ≤ ~200 токенов).
export function glossaryWhisperHint(entries?: GlossaryEntry[]): string;
```

### 4.2 Сид словаря

| `canonical` | `aliases` | `note` |
|---|---|---|
| `Wolt` | `вольт`, `volt` | агрегатор доставки |
| `Wolt Drive` | `вольт-драйв`, `вольт драйв`, `volt drive` | курьеры по запросу от Wolt |
| `Београд` | `билбрайд` | город; пиццерии называются «Београд ‹номер›» |
| `Нови Сад` | `новейсайд`, `нови сайд` | город; пиццерии называются «Нови Сад ‹номер›» |
| `Dodo` | `додо` | бренд |

Открытый вопрос к ревью: `Нови Сад` vs `Нови Београд` для «новейсайд» — уточнить у владельца при сверке. LG/Samsung в стенограмме вышли верно — записей не заводим.

Форма канона: топонимы — кириллицей ровно как их пишет владелец (`Београд`, `Нови Сад`); глобальные бренды — латиницей (`Wolt`, `Dodo`). Тезисы остаются на русском.

### 4.3 Промпт тезисов `tezisy-prompt.ts`

`TEZISY_CORE` остаётся ядром. Компонуем итоговый промпт со словарём в одном месте так, чтобы все 3 потребителя подхватили одинаково (DRY):

- Добавляется **блок словаря** (`glossaryPromptBlock()`).
- Добавляется **правило об именах собственных** (примерный текст):

  > ИМЕНА СОБСТВЕННЫЕ (бренды, названия пиццерий, города, продукты): НЕ придумывай английское/латинское написание. Если название есть в СЛОВАРЕ выше — пиши строго по словарю, ДАЖЕ если кажется, что знаешь бренд лучше (в речи «вольт» → пиши Wolt, НЕ Volt). Если названия нет в словаре — оставь его КАК В СТЕНОГРАММЕ (кириллицей), не транслитерируй наугад. Номер при названии пиццерии сохраняй: «билбрайд 2» → «Београд 2».

Точки инъекции (все используют `TEZISY_CORE` сегодня — после правки подхватят словарь):
- `_shared/meeting-processor.ts:51` (рекордер; здесь же добавляется спец-хвост про «НЕТ_ТЕЗИСОВ» — не ломаем).
- `swarm-bot/handlers/granola.ts:15`.
- `read-ai-webhook/index.ts:261`.

Реализация: экспортировать из `tezisy-prompt.ts` готовую композицию (напр. `TEZISY_PROMPT`, включающую ядро + блок словаря + правило), заменить `TEZISY_CORE` на неё в 3 местах. `meeting-processor` продолжает добавлять свой хвост поверх.

### 4.4 Whisper-хинт

В `_shared/meeting-processor.ts` функция `transcribeAudio` (строка ~109): добавить `form.append("prompt", glossaryWhisperHint())`. Ограничения: Whisper `prompt` ≤ 224 токена — наш хинт заведомо меньше. Влияет только на рекордерный путь (единственный, где Whisper вообще участвует).

## 5. Тестирование и проверка

Согласно правилам проекта (проверка на реальном окружении ДО раскатки на команду):

1. **Юнит-тесты** `glossary.test.ts`: `glossaryPromptBlock()` содержит canonical + aliases всех записей; `glossaryWhisperHint()` — все canonical, в пределах бюджета токенов; записи валидны (непустой canonical, aliases в lowercase).
2. **`deno check`** затронутых функций (pre-commit хук + вручную).
3. **Scratch-прогон без мутации прода:** одноразовый скрипт зовёт OpenAI с новым скомпонованным промптом + реальный текст стенограммы `098380b7`; глазами сверить, что в тезисах `Wolt`/`Wolt Drive`/`Београд N`/`Нови Сад N`, а не `Volt`/`Billbride`/`Noveside`.
4. **Смоук на проде точечно:** деплой `meeting-process`/`meeting-ingest` + `swarm-bot` + `read-ai-webhook`; переобработать **одну** встречу `098380b7`; сверить `draft_notes_md`.
5. **На команду не катим**, пока п.3–4 не подтвердят результат.

## 6. Риски и смягчение

- **LLM игнорирует словарь на редких репликах.** Смягчение: явное правило + приоритет словаря в промпте; если проверка покажет пропуски — точечная regex-пост-обработка как отдельный шаг (сейчас не делаем).
- **Whisper-`prompt` даёт побочные эффекты (эхо/стиль).** Список имён — безопасный и штатный кейс; ограничен объёмом.
- **Неверный канон в сиде** (заменим одно кривое написание на другое). Смягчение: сид сверяется с владельцем на ревью spec; спорные (`Нови Сад`?) помечены.
- **Дрифт документации.** Обновить `docs/QUICK_REF.md` (строка про промпт тезисов) и `docs/ARCHITECTURE.md` (§Флоу встреч) тем же изменением.
