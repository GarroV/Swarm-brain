# Project Space v2 — дерево задач (skill-tree), react-flow

> Дата: 2026-08-01 · Статус: направление утверждено владельцем · Ветка: `feat/project-tree`
> Заменяет рукописный canvas-«облако» из v1 (`useProjectCanvas`) на настоящее дерево задач.

## 1. Обзор

**Что строим.** Вкладка «Проекты» в экране задач: сетка карточек-проектов → провал в **дерево задач** в стилистике деревьев навыков из игр. Корень дерева = проект; к нему привязываются задачи; к задачам — подзадачи (любая вложенность). Непривязанные идеи лежат в «бэклоге» сбоку и перетаскиваются в дерево.

**Почему меняем v1.** v1 рисовал плоское «облако» (хаб + два кольца) рукописным canvas — визуально бедно, текст мылился, нет иерархии подзадач. Владелец отверг. Решение (утверждено): перейти на **react-flow (@xyflow/react)** — индустриальный стандарт нод-графов (37.9k⭐): кастомные HTML/SVG-узлы (чёткий текст, богатый стиль, анимации), анимированные связи, пан/зум/миникарта из коробки. Раскладку дерева считает **d3-hierarchy**. Анимации — **Framer Motion** + CSS.

**Эстетика — «Тёплый тех-HUD» (направление A, утверждено).** Тёплый графит `#1A1714` + янтарная схемная сетка; узлы-модули (карточки) с гравированной рамкой; светящиеся янтарные жилы-связи с бегущим пунктиром; состояние читается цветом (бэклог = камень пунктиром; привязано = янтарь+свечение; done = зелёный+галочка). Технологично, но не вычурно; строго по цветовой политике бренда (`globals.css`).

**Вне скоупа сейчас:** таймлайн/спринт не трогаем; миникарту react-flow — опционально; совместное редактирование real-time — нет.

## 2. Поверхности

| Поверхность | Тех | Назначение |
|---|---|---|
| Вкладка «Проекты» (`TasksScreen`) | React | Хостит сетку и дерево (без изменений точки входа) |
| `ProjectsGrid` | React | Сетка карточек-проектов (оставляем как есть из v1) |
| `ProjectTree` (новый) | react-flow + d3-hierarchy | Дерево проекта: корень→задачи→подзадачи + панель бэклога |
| Кастомные узлы `TaskNode`/`RootNode` | React (HTML/SVG, warm-HUD) | Отрисовка узла: заголовок, статус, кнопки |
| `TaskModal` (существующий) | React | Открытие/правка задачи по клику на узел |

## 3. Модель данных

### Изменение `tasks` (аддитивно, безопасно)
- **`parent_id uuid`** — nullable FK → `tasks(id)` ON DELETE SET NULL. Родитель-задача для подзадачи.
- `project_id`, `project_linked` — уже есть (v1). Семантика в дереве:

| Состояние | project_id | project_linked | parent_id |
|---|---|---|---|
| Бэклог (не в дереве) | set | `false` | null |
| Привязана к корню-проекту | set | `true` | null |
| Подзадача задачи X | set | `true` | X (X тоже в дереве) |

- **Инвариант:** `parent_id` непустой ⇒ `project_linked=true` и родитель того же `project_id`. Отвязка задачи от дерева (`project_linked=false`) каскадно отвязывает её поддерево (или переводит детей в бэклог) — см. §4.
- **Защита от циклов:** нельзя сделать задачу подзадачей своего же потомка (проверка на бэкенде при PATCH `parent_id`).

Миграция: `ALTER TABLE tasks ADD COLUMN parent_id uuid REFERENCES tasks(id) ON DELETE SET NULL;` + индекс.

## 4. Первичные сценарии

- **Открыть дерево.** Клик по карточке проекта → `ProjectTree`: корень в центре/сверху, привязанные задачи и подзадачи разложены d3-hierarchy, бэклог-панель сбоку.
- **Кинуть идею.** Кнопка «+ Идея» → создаётся задача (`project_id`, `project_linked=false`, `parent_id=null`) → появляется в бэклог-панели.
- **Привязать к дереву (drag-to-attach — ядро).** Тащим карточку из бэклога на **узел-цель** (корень или задачу) → `PATCH { project_linked:true, parent_id: <target или null для корня> }` → идея «прирастает» с анимацией (Framer Motion), связь загорается. Альтернатива: на узле кнопка «+ подзадача» → создаёт ребёнка сразу привязанным.
- **Переместить в дереве.** Тащим узел на другой узел → меняем `parent_id` (с проверкой цикла). Тащим в пустоту/бэклог → отвязка.
- **Отвязать.** Узел → бэклог: `project_linked=false, parent_id=null`; его дети — в бэклог (или следуют за ним — решаем: **дети уходят в бэклог**, простая предсказуемая семантика).
- **Статусы.** done-узел — зелёный + галочка; open/in_progress — янтарь. Клик по узлу (не драг) → `TaskModal`.

## 5. Раскладка и рендер

- **d3-hierarchy** строит дерево из `parent_id` (корень = виртуальный узел проекта). Раскладка: `tree()` (сверху-вниз слоями) ИЛИ радиальная (`cluster` + polar). Старт — **радиальная** (корень в центре, ветви наружу — ближе к «дереву навыков»); позиции пересчитываются при изменении структуры.
- **react-flow** рендерит узлы (кастомные `nodeTypes`) и связи (кастомные анимированные `edgeTypes`). Пан/зум/фиттинг — встроенные (`fitView`).
- **Warm-HUD узлы:** модуль-карточка (`--card` фон, `--card-edge`/акцент-рамка), заголовок (чёткий DOM-текст), статус-пип/галочка, на hover — подъём + свечение (Framer Motion), кнопки «+ подзадача» и «открыть». Корень — крупнее, ornate-рамка, эмодзи/буква.
- **Связи:** SVG-path с `stroke-dasharray` бегущим (CSS `@keyframes`), янтарное свечение у привязанных, `filter: drop-shadow`. Фон — тёплый графит + янтарная схемная сетка (CSS/SVG pattern) + виньетка.
- **Бэклог-панель:** сбоку (drawer/колонка) со списком непривязанных идей — draggable в холст.
- **reduced-motion:** отключаем бегущий пунктир/пульс/анимации входа.

## 6. Бэкенд (`swarm-api`, `_shared/tasks`)

- Миграция `parent_id` (§3).
- `types.ts`: `Task.parent_id: string|null`, `TaskInput.parent_id?`.
- `db.ts`: `createTask` пишет `parent_id`; `listTasks` — фильтр `parentId?` (и/или отдавать всё дерево проекта одним `GET /tasks?project_id`).
- `swarm-api`:
  - `GET /tasks?project_id` уже отдаёт задачи проекта (с `parent_id`, `project_linked`) — этого достаточно, дерево собирается на клиенте.
  - `PATCH /tasks/:id` принимает `parent_id`: валидация (родитель того же проекта и `project_linked`, **нет цикла**); при `parent_id!=null` форсим `project_linked=true`; при отвязке (`project_linked=false`) — `parent_id=null` и **дети → бэклог** (`project_linked=false, parent_id=null` каскадом в этом воркспейсе).
  - `POST /tasks` принимает `parent_id`.
- Изоляция `group_id` + visibility приватных — как в v1 (не обходить guard'ы).

## 9а. Беклог визуала — референс от владельца (2026-08-03, вернуться после лимитов)

Владелец прислал скрин инфографики «CLAUDE CORE» (hub-and-spoke, тёмные карточки вокруг центра) и сказал: нравится визуал карточек, хочет похожее в дереве проекта. Разобрать и по возможности перенести на `HudNode`/`HudEdge` (уже частично в эту сторону — акцент-полоса слева, но можно докрутить):
- Карточка: тёмно-синяя/графитовая, скруглённые углы, **цветной хедер-бар сверху** с иконкой + подписью раздела (не полоса сбоку, а именно шапка).
- Внутри карточки — компактная мини-схема-пайплайн: иконка-вход → **оранжевая пилюля** (акцентное действие/статус по центру) → иконка-выход, с мелкими подписями под каждой.
- Стрелки-связи между карточками — толстые, с закруглёнными углами (не прямые «в лоб», а L-образные/со скруглением), два цвета чередуются (голубой/бирюзовый) — по смыслу входящих/исходящих.
- Центр — акцентный тёмный хаб-квадрат с логотипом/иконом и обводкой-рамкой (как «CLAUDE CORE»), крупнее остальных карточек.
- Не копировать один в один (это чужой инфографика-стиль, не тех-HUD), а вытащить принцип: **чёткая карточка-модуль с собственной мини-иконографией внутри**, а не голая надпись. Это следующий шаг полировки после того как механика (магнит/скорость/зум) станет стабильной.
