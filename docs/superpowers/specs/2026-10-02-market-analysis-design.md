# «Анализ рынка» — дизайн раздела

**Дата:** 02.10.2026 · **Статус:** на согласовании у владельца · **Решение:** [decisions/2026-10-02-market-analysis-section.md](../../decisions/2026-10-02-market-analysis-section.md)

## Что это

Раздел Swarm, где по каждой стране Dodo видно рынок быстрого питания из открытых источников: где стоят точки конкурентов и как растут сети, сколько зарабатывают их юрлица, сколько стоит пицца, как устроена доставка — и где на этом фоне мы сами. Данные живут в базе и обновляются кодом по расписанию, без LLM.

**Продукт — система обновления, а не перенос файла** (решение владельца 02.10.2026). Каждый блок страницы держится на **источнике** с частотой и статусом: автоматический, ручной или закрытый. Новая страна заводится **конфигом страны** (какие источники, какие сети, какие юрлица), а не новой выгрузкой. Страница показывает у каждого блока, откуда данные и когда они последний раз обновлялись.

Образец того, что должно получиться, — разовый анализ Хорватии для партнёра (файл «Хорватия: сети QSR», срез 01.10.2026). Его страницу не воспроизводим. Из его данных берём только **первичную заливку ручных источников** — то, что кодом пока не собирается (финансы из Fina, точки локальных сетей без доступного локатора, факты рынка доставки). Оформление — в стиле Swarm.

**Первый этап:** Хорватия, Румыния и Эстония — у каждой конфиг страны и работающие автоматические источники; ручные источники заполнены первичными данными.

## Кто и как пользуется

- Участник воркспейса открывает «Анализ рынка» в левой рейке (на мобайле — пункт «Ещё»), выбирает страну и листает одну страницу сверху вниз: сводка → карта → динамика сетей → пицца-конкуренты → Dodo → цены → доставка → деньги → реестр точек → свежесть данных.
- Админ загружает снимок страны (первичный сбор или ручная правка) и разбирает очередь изменений, которую раз в неделю наполняют сборщики.
- Видны только страны из `workspaces.allowed_markets` воркспейса. Продажи Dodo публичны (решение владельца), отдельных прав на раздел нет.

## Глоссарий

- **Источник** — откуда берётся один вид данных одной страны: адаптер (`dodo-publicapi`, `osm-overpass`, `ee-ariregister`, `ro-datagov`, `locator:<сеть>`, `manual`), какие данные он кормит, частота, статус и время последнего успешного запуска. Хранится в базе (`mkt_sources`), показывается на странице.
- **Конфиг страны** — файл `scripts/market/countries/<CC>.ts`: сети (ключ, название, сегмент, теги OSM, адаптер локатора, если есть), юрлица операторов с рег. номерами, список источников. Добавить страну = написать конфиг; добавить сеть = строка в конфиге.
- **Адаптер** — код, читающий один тип источника по единому контракту (`collect(country, config) → данные или «не удалось: причина»`). Один адаптер обслуживает много стран (OSM, Dodo) или одну сеть (локатор).
- **Ручной источник** — данные без автоматического источника (Fina, рынок доставки, цены). Вносятся загрузкой таблицы или снимка, у них есть дата сверки, и страница честно показывает их возраст. Хорватский файл — их первичная заливка.
- **Сборщик** — запуск адаптеров по расписанию: раз в неделю (или месяц) читает источники и сравнивает с базой.
- **Кандидат** — предложение сборщика («новая точка», «точка пропала из источника», «новый год отчётности»), ждущее подтверждения человеком. Сборщик сам не переписывает проверенные записи.
- **Статус проверки** — у каждой записи, как в хорватском файле: `official` (локатор сети), `confirmed`, `corrected`, `added`, `unverified`, `internal`.

## Источники и что из них берётся кодом

| Данные | Источник | Частота | HR | RO | EE |
|---|---|---|---|---|---|
| Наши пиццерии, юрлица франчайзи, даты открытия | `publicapi.dodois.io/{cc}/api/v1/unitinfo/all` | неделя | ✅ | ✅ | ✅ |
| Выручка Dodo по стране | `…/FinancialMetrics` | неделя (копится помесячно) | ✅ | ✅ | ✅ |
| Заказы Dodo по каналам | `…/orders/countBySource/{y}/{m}/{d}` | неделя (дни → месяцы) | ✅ | ✅ | ✅ |
| Точки международных сетей | OpenStreetMap (Overpass, по тегу `brand`) | неделя → кандидаты | ✅ | ✅ | ✅ |
| Финансы юрлиц | открытые выгрузки реестров | год / месяц | ❌ Fina закрыта | ✅ data.gov.ro, год | ✅ ariregister, месяц |
| Курс в евро | ЕЦБ (Data API) | месяц | — | RON→EUR | — |
| Точки локальных сетей, цены, оценки, факты рынка доставки | снимок (ручной сбор) | по необходимости | ✅ из файла | первичный сбор | первичный сбор |

Сверка OSM с ручным реестром Хорватии (02.10.2026): международные сети совпадают на 70–100% (McDonald's 51 против 50), локальные сети OSM не видит вовсе. Поэтому OSM даёт **кандидатов**, а не правду.

**Не автоматизируем в первом этапе** (и пишем это на странице): цены и оценки (Wolt — серая зона по условиям, Google Places платный), локаторы McDonald's и KFC (отвечают роботам 403), финансы Хорватии (Fina — вход и запрет перепубликации; обновление раз в год вручную через снимок).

**Локальные сети** обновляются адаптерами локаторов `locator:<сеть>` — по одному на сеть с открытым списком точек (JSON, wp-json, sitemap, HTML). Какие локаторы реально отдают данные, берём из инструкции коллеги, собиравшего хорватский анализ, и из разведки RO/EE. Сеть без доступного локатора остаётся ручным источником и помечается на странице.

**Заведение Румынии и Эстонии** — конфиг страны (сети, теги OSM, юрлица с рег. номерами, источники) плюс разовая разведка локаторов локальных сетей. Ручные источники (факты рынка, цены) заполняются первично тем же импортом. Регулярное обновление дальше — только кодом.

## Устройство

```
GitHub Actions (cron, ночь)            Supabase                              miniapp
scripts/market/*.ts  ── POST ──▶  market-ingest (edge fn, токен)  ──▶  mkt_* таблицы
                                                                         ▲
админ: импорт снимка / очередь ── swarm-api /market/* (сессия) ─────────┘──▶ MarketScreen
```

- **Сборщики** — Deno-скрипты в `scripts/market/`, адаптер на источник (`adapters/dodo.ts`, `osm.ts`, `ee-ariregister.ts`, `ro-datagov.ts`; курсы ЕЦБ берут сами адаптеры), точка входа `run.ts`. Запускаются workflow `market-collect.yml` раз в неделю, в воскресенье 23:00 UTC (≈01:00 по Белграду, внутри ночного окна); источники с частотой «месяц/год» — только в первую неделю месяца, плюс ручной запуск кнопкой. Репозиторий публичный — минуты Actions бесплатны; код сборщиков открыт, данные — только в базе.
- **Запись** идёт через отдельную edge-функцию `market-ingest`, принимающую только данные раздела, по токену `MARKET_INGEST_TOKEN` (секрет в GitHub и в Supabase). Ключ service role в Actions не кладём: у токена права только на `mkt_*`.
- **Чтение** — модуль `swarm-api/market.ts` (`handleMarketRoutes`) по образцу `task-archive.ts`: сессия, воркспейс, проверка, что страна в `allowed_markets`.
- **Каждый запуск сборщика пишет строку в `mkt_runs`** (источник, страна, начало/конец, статус, сколько прочитано/кандидатов, текст ошибки). Упавший или пропущенный сборщик виден на странице как «данные не обновлялись N дней», а не молчит.

## Данные (новые таблицы, все с RLS без политик и `revoke` с anon/authenticated)

Данные не принадлежат воркспейсу — это рынок страны; доступ режется по `allowed_markets`.

- `mkt_chains` — сеть в стране: ключ, название, сегмент (pizza/burger/chicken/bakery/…), пекарня?, происхождение, оператор, год входа, заметки, слот цвета.
- `mkt_locations` — точка: сеть, название, город, адрес, координаты, размещение, дата открытия (частичная: год/месяц/день) и флаг «оценка», статус (open/closed/planned/paused), дата закрытия, формат, источник, статус проверки, заметка проверки, `first_seen_at`, `last_seen_at`.
- `mkt_companies` — юрлицо: сеть, название, рег. номер, владелец, заметки.
- `mkt_financials` — юрлицо × год: выручка, чистая прибыль, сотрудники (все в EUR, исходная валюта и курс рядом), источник, статус проверки. Уникально (юрлицо, год).
- `mkt_prices` — позиция: сеть, пицца, тип, размер в см, цена EUR, канал, источник, дата снятия.
- `mkt_ratings` — оценка: точка или сеть, площадка, оценка, число оценок, дата.
- `mkt_facts` — универсальные факты страны: тема (`delivery`, `market`, `deal`, `timeline`, `insight`, `commentary`), дата/год, текст, значение, источник. Держит рынок доставки, сделки, таймлайн.
- `mkt_dodo_monthly` — страна × месяц: выручка (местная валюта и EUR), число пиццерий, заказы по каналам.
- `mkt_candidates` — предложение сборщика: вид, источник, полезная нагрузка, ссылка на существующую запись, статус (pending/accepted/rejected), кто и когда решил.
- `mkt_runs` — журнал запусков (см. выше).
- `mkt_sources` — источники страны: адаптер, какие данные кормит (`locations`/`financials`/`dodo`/`prices`/`facts`), сеть (для локатора), частота, режим (`auto`/`manual`/`blocked` с причиной), `last_ok_at`. Наполняется из конфига страны при каждом запуске сборщика; ручные источники получают `last_ok_at` при импорте.

Изменения проверенных записей не стирают историю: смена статуса точки пишет `closed_on`/`last_seen_at`, физического удаления нет.

## Правила сборщиков (ядро — под тестами)

- **Dodo — источник истины для своих точек:** новые пиццерии и смена статуса применяются сразу, без очереди.
- **OSM → кандидаты:** точка OSM сопоставляется с существующей точкой той же сети ближе 150 м. Нет пары → кандидат «новая точка». Точка из реестра со статусом `official`/`confirmed` не пропадает из-за OSM никогда; кандидат «возможно закрыта» появляется только у записей, источником которых был OSM, и только после трёх недель отсутствия подряд. Принятая по одной находка становится `confirmed` (человек её посмотрел). Для первичной заливки страны без ручного реестра (Румыния, Эстония) админ принимает все находки точек разом (`POST /market/:cc/candidates/accept-all`): они остаются `unverified` и по-прежнему получают «возможно закрыта», если пропадут из OSM. «Возможно закрыта» и правки финансов разом не принимаются.
- **Реестры → финансы:** год пишется сразу, если юрлицо уже сопоставлено с сетью (сопоставление — ручное, через снимок); новое значение поверх проверенного — кандидат, а не перезапись.
- **Заказы Dodo** копятся по дням и сворачиваются в месяц; неполный месяц помечается.

## Экран

У каждого блока — подпись источника и возраста данных («Dodo publicapi · обновлено 3 дня назад», «Fina · ручной, сверка 01.10.2026»).

Один экран `MarketScreen` с выбором страны (чипы из `allowed_markets`, у которых есть данные). Разделы сверху вниз, пустой раздел прячется с подписью «нет данных: источник такой-то закрыт»:

1. **Сводка** — точек по сетям, открытия за год, выручка Dodo, место Dodo среди пицца-сетей, свежесть данных.
2. **Карта** — контур страны и точки/хитмап, фильтр по сетям, ползунок «сеть на конец года». Контуры — Natural Earth (общественное достояние), статическим SVG-ассетом на страну, как в хорватском файле: без тайлов и без новых библиотек, CSP не трогаем.
3. **Динамика сетей** — точек на конец года по сетям, таймлайн открытий/закрытий.
4. **Пицца-конкуренты** — выручка и выручка на точку.
5. **Dodo** — продажи по месяцам, заказы по каналам.
6. **Цены** — средняя пицца ~30 см по сетям.
7. **Доставка** — платформы и факты рынка.
8. **Деньги** — финансы операторов по годам.
9. **Реестр точек** — таблица с поиском и фильтром статуса.
10. **Свежесть и изменения** — журнал запусков; для админа — очередь кандидатов (принять/отклонить, «принять все новые точки») и импорт снимка.

Графики — SVG в коде экрана на токенах `--chart-1..5`, без новой зависимости (по навыку `dataviz`). Тексты интерфейса — парами RU/EN через `useDt`. Светлая и тёмная тема.

**Регистрация раздела** — по образцу `sprints`: `RoyTab` (`lib/royRoute.ts`), `ROY_TABS_ALL` (`lib/royUrl.ts` + тест), `RoyRail.tsx`, `RoyApp.tsx` (список вкладок в sessionStorage, `RAIL_TAB`, `SECTION_TITLE`, рендер, пункт «Ещё»). Мобильный таб-бар не трогаем (решение 22.08.2026). Защищённые пути не задеваются.

## Демо

В демо — **только вымышленные данные** («рыба», решение владельца 02.10.2026), никакой официальной информации ни по одной стране. Демо-воркспейс видит одну выдуманную страну **Demoland** с кодом `XD` (диапазон `XA–XZ` в ISO 3166 отдан под пользовательские коды и реальной стране не достанется). Всё по-английски: выдуманные сети, точки, юрлица, цены, финансы и продажи Dodo, контур страны тоже свой. Настоящие воркспейсы `XD` не видят, потому что его нет в их `allowed_markets`; демо-сессия видит только `XD`.

Данные заводит функция `public.market_demoland_seed()` (миграция `20261003110000_market_demoland.sql`, сгенерирована `scripts/market/demoland-seed.ts` из `miniapp/src/lib/marketDemo.ts` — тот же генератор кормит DEV_MODE). Даты в ней считаются от `now()`, pg_cron `market-demoland` зовёт её раз в сутки, чтобы демо не выглядело застывшим. Демо-сессия админом не бывает и XD не меняет. Сборщики страну `XD` не трогают: у неё нет источников.

## Проверка

- **Ядро, тесты до кода:** валидатор снимка (битый снимок отклоняется с понятной причиной), сопоставление OSM↔реестр (150 м, та же сеть), правило «возможно закрыта», число точек на конец года, свёртка заказов в месяц, пересчёт в EUR, доступ по `allowed_markets` (`*.db.test.ts`: чужая страна → 403). Каждая проверка прогоняется на заведомо сломанном входе.
- **Остальное — запуском:** сборщики гоняются вручную по трём странам на локальной базе, импорт хорватского снимка → страница совпадает с исходным файлом по ключевым цифрам (611 точек, 23 сети, выручки из Fina), экран смотрится в обеих темах и на мобайле.
