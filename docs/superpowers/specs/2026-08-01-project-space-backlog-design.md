# Project Space — облако проектов и бэклога

> Дата: 2026-08-01 · Статус: дизайн согласован, готов к плану · Ветка: `feat/project-backlog`

## 1. Обзор

**Проблема.** У команды растёт число кодовых/рабочих проектов, между ними легко запутаться. Нет единого места, где видно все проекты, их задачи и «что вообще в планах». Существующая вкладка «Граф» (дерево зависимостей задач) нигде не используется.

**Решение.** Заменить неиспользуемую вкладку «Граф» в экране задач на **Project Space** — двухуровневый интерфейс:

1. **Сетка проектов** — карточки проектов воркспейса со счётчиком задач; плитка «+ новый проект». Команда сама заводит проекты и кидает в них идеи.
2. **Облако проекта** (провал внутрь карточки) — интерактивный canvas: проект в центре, вокруг летают карточки задач. Связанные с проектом задачи соединены линией с центром; «плавающие» карточки бэклога — рядом, без линии. **Drag-to-connect**: перетащил карточку на центр → связал; утащил обратно → отвязал. В этой тактильности — суть фичи.

**Ключевой принцип: без дублирования данных.** Проект и задача — обычные строки в БД. Задача, созданная в облаке проекта, — это тот же `Task`, что и везде: она автоматически видна в обычном списке задач (вкладки Список/Таймлайн/Спринт). Один Task — несколько поверхностей отображения.

**Явно вне скоупа сейчас:**
- Спринты **не** используются как признак связи (функционал спринтов сам под вопросом — не привязываемся).
- Таймлайн остаётся как есть (его судьба — открытый вопрос на будущее, не в этом релизе).
- Зависимости задача↔задача (старый Граф) в облако **не** переносим — рёбра только «задача↔проект».

## 2. Поверхности

| Поверхность | Тех. | Назначение | Backing |
|---|---|---|---|
| Вкладка «Проекты» в `TasksScreen` | React (miniapp) | Замена вкладки «Граф»; хостит сетку и облако | `swarm-api` |
| Сетка проектов (`ProjectsGrid`) | React | Список карточек-проектов + создание | `GET/POST /projects` |
| Облако проекта (`ProjectSpace`) | Canvas 2D (по образцу `system-map.html`) | Проект-хаб + летающие задачи, drag-to-connect | `GET /tasks?project_id`, `PATCH /tasks/:id` |
| Карточка задачи (провал из узла) | React (`TaskModal`, существующий) | Детали/редактирование задачи | `swarm-api` |

## 3. Модель данных

### Новая таблица `projects`

```sql
create table projects (
  id uuid primary key default gen_random_uuid(),
  group_id text not null references workspaces(id),   -- как у sprints
  name text not null,
  color text,                                          -- hex/токен для узла (nullable)
  emoji text,                                          -- опциональная иконка узла
  created_by bigint,                                   -- telegram_id автора
  created_at timestamptz not null default now()
);
grant all on projects to service_role;                 -- правило _template_new_table.sql
```

### Изменения в `tasks` (обе — безопасный `ADD COLUMN`)

- `project_id uuid` — nullable FK → `projects(id)`. `NULL` = задача не в Project Space (живёт как обычно).
- `project_linked boolean not null default false` — свой независимый признак «связана с проектом линией». **Не** переиспользует `sprint_id` (отвязка от спринтов — сознательное решение).

**Семантика внутри облака проекта** (все задачи с данным `project_id`):
- `project_linked = true` → узел соединён линией с центром-хабом (в активной работе / принята в проект).
- `project_linked = false` → плавающая карточка бэклога, без линии.

Задача может быть в проекте (`project_id` задан), но плавать (`project_linked = false`) — это и есть бэклог проекта.

## 4. Первичные сценарии

**Завести проект.** Вкладка «Проекты» → плитка «+ новый проект» → имя (+ цвет/emoji опц.) → `POST /projects` → карточка появляется в сетке. Доступно любому участнику воркспейса.

**Кинуть идею в бэклог проекта.** Провалиться в проект → кнопка «+» в облаке → создаётся `Task` с `project_id = текущий`, `project_linked = false` → открывается `TaskModal` для деталей → карточка появляется плавающей. Эта задача сразу видна и в обычном списке задач.

**Связать / отвязать (drag-to-connect).** В облаке тащим плавающую карточку на центральный хаб-узел → `PATCH /tasks/:id { project_linked: true }` → при перерисовке карточка соединена линией. Тащим связанную от центра наружу → `project_linked: false` → снова плавает. Оптимистичный апдейт: линия появляется/исчезает мгновенно, откат при ошибке API.

**Открыть задачу.** Клик (без драга) по узлу задачи → существующий `TaskModal` (статус, исполнители, комментарии — всё уже есть). Никакого нового UI задачи.

**Прикрепить существующую задачу к проекту.** Через `TaskModal` — новое поле выбора проекта (`PATCH /tasks/:id { project_id }`). Задача появляется в облаке этого проекта (плавающей, пока не связана).

## 5. Экраны и навигация

`TasksScreen` тулбар: `Список · Таймлайн · Спринт · Проекты` (было `… · Граф`).

```
View = "list" | "timeline" | "sprint" | "projects"   // заменили "graph"
```

**`ProjectsGrid`** (state: список проектов + счётчики):
- Карточки: имя, цвет/emoji, счётчик задач (всего / из них в бэклоге). Плитка «+ новый проект».
- Клик по карточке → `ProjectSpace` этого проекта (внутренний стейт вкладки, не роут).

**`ProjectSpace`** (canvas):
- Переиспользуем **технику** `miniapp/public/system-map.html`: pan/zoom (wheel + drag фона), pick узла по координате, hover, детерминированная авто-раскладка узлов вокруг хаба (аналог `fanDoor()`), лёгкий дрейф/«галактика» по вкусу. Это **новая, отдельная реализация на реальных данных** — сам `system-map.html` не трогаем (он статичный маркетинговый «объясняльник» продукта).
- Хаб = узел проекта в центре. Узлы задач — вокруг: связанные (`project_linked`) ближе к центру + линия к хабу; плавающие — во внешнем кольце без линии.
- Позиции узлов **не персистятся** в БД (авто-раскладка по id + свободный драг для тактильности/связывания). Персистится только `project_linked` через drag-to-connect. Это осознанно сокращает объём (без x/y-колонок и стейта позиций).
- Кнопка «←» назад в сетку; кнопка «+» — добавить карточку.

## 6. Бэкенд (`swarm-api`)

Новый роут-модуль `projects` (по образцу `sprints`):

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/projects` | Проекты воркспейса + счётчики задач (всего / в бэклоге). Все участники. |
| `POST` | `/projects` | Создать (`name`, `color?`, `emoji?`). Любой участник воркспейса. |
| `PATCH` | `/projects/:id` | Переименовать / сменить цвет-emoji. |
| `DELETE` | `/projects/:id` | Удалить проект. Задачи освобождаются: `project_id = NULL`, `project_linked = false` (FK `ON DELETE SET NULL` + сброс флага). |

Изменения существующих:
- `GET /tasks` — новый фильтр `project_id`; в ответе отдавать `project_id`, `project_linked`.
- `PATCH /tasks/:id` — принимать `project_id` и `project_linked`.
- `POST /tasks` — принимать `project_id` (для создания карточки прямо в облаке).

**Безопасность.** Проекты — на уровне воркспейса, изоляция по `group_id` (как sprints). Задачи в облаке идут через ту же visibility-логику (приватные задачи чужого владельца не текут). Мутации `project_id`/`project_linked` — стандартный owner/участник-guard как у прочих полей задачи.
