# Спринт-борд: бэклог, публичное планирование, свимлейны

> Дизайн-спека. Дата: 2026-07-17. Ветка: `sandbox_vas`. Компонент: `miniapp/src/components/tasks/SprintBoard.tsx` + `swarm-api` + `_shared/tasks/`.

## 1. Цель

Превратить спринт-борд из «канбана по статусам с фильтром по спринту» в настоящую доску **планирования**: слева пул невзятых задач (бэклог), справа колонки спринта; задачи затаскиваются из бэклога в спринт. Спринт обретает ценность как time-box, а не как сохранённый фильтр.

## 2. Текущее состояние (что есть)

- `SprintBoard.tsx`: чипы-переключатели спринтов (`Бэклог` = псевдо-спринт `sprint_id=null` + реальные спринты), выбран ОДИН; внутри — 3 колонки статусов (Открыто/В работе/Готово); дропдаун на карточке для смены спринта; создание/удаление спринта (только админ); прогресс-бар.
- Данные уже поддерживают почти всё: `tasks.{sprint_id, status, priority, timeline_position, label_ids, tags, country, assignee_telegram_ids, is_private, owner_id}`; `sprints.{status: planned|active|completed, start_date, end_date, name, group_id}` (без `owner_id` — спринт воркспейсовый).
- API уже есть: `fetchTasks`, `updateTask` (в т.ч. `timeline_position`), `fetchSprints`, `createSprint`, `updateSprint` (статус!), `deleteSprint`, `addTasksToSprint`/`removeTasksFromSprint` (bulk через `setTasksSprint`), роуты `/sprints`, `/sprints/:id`, `/sprints/:id/tasks`.

## 3. Модель и приватность (центральное решение)

**Спринт — общий на воркспейс и ПУБЛИЧНЫЙ в окне спринт-борда.**

- Задача, лежащая в спринте (`sprint_id != null`), видна **всем** участникам воркспейса на спринт-борде — **независимо от `is_private`**. Добавление задачи в спринт = осознанный акт «выложить в командное планирование».
- **Публичность строго локальна:** только на спринт-борде (новый эндпоинт). Везде ещё (база знаний, списки задач, поиск, бот, MCP) приватность работает как раньше — личная задача остаётся личной. `is_private` НЕ меняется при добавлении в спринт.
- **Бэклог** (`sprint_id=null`) — по **обычной** приватности: зритель видит свои личные + все командные; чужие личные скрыты; админ — всё. Публичной задача становится, только когда её втащили В спринт.
- **Воркспейс-изоляция (`group_id`) остаётся железной** всегда, даже для админа. Ослабляется ТОЛЬКО приватность-в-воркспейсе и ТОЛЬКО для in-sprint задач на этом эндпоинте.
- Спринты **единообразно** публичны в окне — без per-sprint флага `is_public` (YAGNI; можно добавить позже).

Следствие (в плюс): раньше состав/счётчик спринта мог отличаться у разных зрителей (у каждого своя видимость) — теперь спринт **одинаков для всех**, прогресс консистентен.

## 4. Раскладка и взаимодействия

Когда выбран реальный спринт:
```
[ Все | По сотрудникам ]   [ 🔍 поиск | метки | страна | «мои» ]   [чипы спринтов + ➕ 🗑]  [Начать/Завершить]
┌── Бэклог ──┐ ┌── Открыто ──┐ ┌── В работе ──┐ ┌── Готово ──┐
│ невзятые    │→│   спринт    │ │   спринт     │ │  спринт    │
│ (приватность│ │ (публично   │ │ (публично    │ │ (публично  │
│  обычная)   │ │  в окне)    │ │  в окне)     │ │  в окне)   │
│ ручной      │ │             │ │              │ │            │
│ порядок     │ │             │ │              │ │            │
└─────────────┘ └─────────────┘ └──────────────┘ └────────────┘
```

- **Drag Бэклог → колонка спринта:** атомарно `sprint_id = выбранный` + `status = колонка`. Обратно (спринт→Бэклог): `sprint_id = null` (статус сохраняется).
- **Ручной порядок в бэклоге:** drag внутри колонки Бэклог меняет `timeline_position` (PATCH `updateTask`); сортировка бэклога по `timeline_position` (при null — по `priority`, затем `due_date`).
- **Режим «По сотрудникам» = свимлейны:** горизонтальная дорожка на каждого сотрудника (по `assignee_telegram_ids`), пересекающая колонки статусов; задачи без исполнителя — лейн «Без исполнителя». Переключатель «Все ↔ По сотрудникам» вверху. Тумблер только для колонок спринта; бэклог остаётся плоским (левая колонка).
- **UI-подсказка приватности:** при перетаскивании личной (`is_private`) задачи в спринт — короткий тултип/бейдж «Личная — в спринте увидит вся команда».
- **Тач-фолбэк:** дропдаун смены спринта на карточке оставить (нативный HTML5-drag капризен на мобиле/в Telegram).

## 5. Объём v1 (всё, что решили)

1. Колонка «Бэклог» + drag-в-спринт (атомарно sprint_id+status).
2. Публичность in-sprint задач в окне (privacy carve-out, §3).
3. Фильтр/поиск на борде: текст, смарт-метки (`label_ids`), теги, страна, «Мои» (по `assignee_telegram_ids`). Переиспользуем `lib/smartLists.ts`/`filterByLabel`.
4. Ручной порядок бэклога (`timeline_position`, drag-reorder).
5. Жизненный цикл спринта в UI: **Начать** (`planned→active`), **Завершить** (`active→completed`) с **переносом незакрытых** задач → бэклог (дефолт) или в выбранный следующий спринт.
6. Пресеты дат быстрого создания: «1–15 <месяц>» / «16–конец <месяц>» с авто-названием и датами.
7. Свимлейны «по сотрудникам».
8. Мульти-выбор в бэклоге → закинуть пачкой (`setTasksSprint` bulk).

## 6. Изменения на бэкенде

**Новое (единственное security-sensitive):**
- **`GET /sprint-board`** (swarm-api) — данные борда одним ответом:
  - `backlog: Task[]` — `sprint_id IS NULL`, **с обычным** privacy-фильтром (как `listTasks`: `viewerId`/`isAdmin`).
  - `sprintTasks: Task[]` — `sprint_id IS NOT NULL` для воркспейса, **БЕЗ** privacy-фильтра (публично в окне). Прямой запрос в самом хендлере, помеченный явным комментарием-carve-out; `group_id` фильтр обязателен.
  - Клиент группирует `sprintTasks` по `sprint_id` и статусу.
  - **`listTasks` (общий движок) НЕ трогаем** — никакого privacy-bypass флага в переиспользуемой функции (её зовут бот/MCP); carve-out живёт ТОЛЬКО в этом хендлере swarm-api, в одном явном месте (принцип entries-guard).

**Переиспользуем как есть (UI-обвязка):**
- Жизненный цикл: `updateSprint(id, { status })` (есть). «Завершить» = `status='completed'` + перенос: `setTasksSprint(undoneIds, null|nextSprintId, groupId)`.
- Порядок бэклога: `updateTask(id, { timeline_position })` (есть). Возможно тонкий bulk-хелпер для переиндексации соседей.
- Привязка/отвязка: `setTasksSprint` / `/sprints/:id/tasks` (есть).
- Создание с пресетами: `createSprint` (есть) — пресеты считаются на клиенте.

## 8. Модель данных

**Новых колонок НЕ требуется.** Всё есть: `tasks.{sprint_id, status, timeline_position, priority, assignee_telegram_ids, is_private}`, `sprints.{status, start_date, end_date, name, group_id}`.
- Перенос «в следующий спринт» — «следующий» определяем по датам (ближайший `start_date` > текущего) или явным выбором в диалоге завершения. Дефолт переноса — бэклог (проще, без догадок).
- Per-sprint публичность — НЕ вводим (спринты единообразно публичны в окне).

## 9. Безопасность (обязательный ревью)

Carve-out приватности — security-sensitive. Требования:
- `group_id`-изоляция в `/sprint-board` — ВСЕГДА (и для backlog, и для sprintTasks), даже админу.
- Privacy-bypass — ТОЛЬКО для `sprint_id IS NOT NULL` и ТОЛЬКО в этом хендлере. Backlog и все прочие эндпоинты — прежняя приватность.
- Прогнать **security-reviewer** по новому хендлеру перед мержем (утечка чужих личных в НЕ-спринтовые пути = регрессия приватности).
- Проверить, что мутации (drag, reorder, привязка) идут через существующие проверки воркспейса (`setTasksSprint`/`updateTask` уже `eq(group_id)`).

## 10. Тестирование

- **Unit:** сортировка бэклога (timeline_position→priority→due_date); группировка свимлейнов по assignee; вычисление пресетов дат «1–15»/«16–конец».
- **Доступ (критично):** `/sprint-board` — не-владелец ВИДИТ чужую личную задачу, лежащую В спринте, но НЕ видит её же, пока она в бэклоге; чужой воркспейс не виден никогда. Проверить, что `GET /tasks`/поиск/бот приватную in-sprint задачу по-прежнему НЕ отдают не-владельцу (публичность не протекла).
- **E2E (сам, на проде — правило «test yourself»):** создать спринт пресетом «1–15», затащить задачи из бэклога, начать/завершить с переносом, переключить свимлейны, применить фильтр «Мои».
- **Сборка:** `npm run build` в `miniapp/`; глянуть борд в светлой/тёмной теме; `deno check` затронутых edge-функций.
