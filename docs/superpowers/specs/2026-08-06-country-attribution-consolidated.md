## 0. Решения этой сессии (ledger)

1. **Ядро — принцип «упоминание ≠ предмет»**, причём на ДВУХ уровнях: страна (упомянута ≠ встреча про неё) и токен (слово прозвучало ≠ оно что-то определяет / человек такой роли).
2. **Смещение: «точность сейчас, полнота по мере созревания».** Не уверен → `General`. Словари асимметричны (RS/SI густо, CY/EE/LT пусто), боль прода — перетег, поэтому дефолт консервативный.
3. **Скелет поддержки:** один YAML (данные) + один матчер в проде (TS, читает YAML) + `match2.py` как офлайн-стенд эвала (НЕ второй тегер) + петля курирования (агент правит YAML) + линт YAML (коллизии). Санитайзер и поиск-фильтр живут в TS.
4. **Города вместо пиццерий.** Нужен ТЕГ, не инвентарь точек: голое «Бургас» ловит «Бургас-1/2/10». Номера выкинуты, каждый рабочий город = тег.
5. **Человек-ключ = фамилия / полное имя / почта. Голое первое имя — НИКОГДА** (Сергей/Антон/Саша = много разных людей; в спич-транскриптах имя ≠ идентификатор).
6. **Заголовок несёт ~80% ответа.** Название/код страны В ЗАГОЛОВКЕ = сильный детерминированный сигнал (title-scoped; голый код в теле опасен — «HUb»).
7. **General-слой** (форс General независимо от упоминаний стран): 1:1/sync, HQ-серии (РКО/система оценки, IMF-инспектора-продукт, International Marketing, «Обучение в странах»). **Подтверждать чтением встреч, а не догадкой из одного заголовка.**
8. **Гео расширено** (название + национальность: RU/эндоним/EN/транслит). Склонения добирает стеммер. Голые ISO-коды не в гео.
9. **Royalty Fee — boilerplate** (рассылка по каждой стране), не отдельный якорь; сигнал несёт только название страны в теме → сворачивается в правило «страна в заголовке».
10. **Майнер связок = кандидатогенератор для человека, не решатель.** Наивная co-occurrence даёт тематический мусор. Гоняем регулярно; на текущем объёме данных мало.
11. **Эталон = ~10–12 руками-размеченных встреч, НЕ `tags_in_base`** (база пере-тегана — это и есть баг, который чиним).

## 1. Проблема (данные прода, снято 2026-08-06)

- **184 встречи.** Распределение по числу тегов: 0 стран — 5, 1 — 124, 2 — 37, 3 — 6, 4 — 12. Максимум сейчас 4 (снимок дизайна 07-30 «64/175 с 3+, хвост до 17–19» **устарел** — теги с тех пор частично почистили; учитывать это, не брать старую цифру за факт).
- **Однозначных якорей мало.** Домен/`Royalty Fee`/уникальный вендор — только у **18** встреч. По расширенным якорям (страна/город + фамилия партнёра) однозначно-односрановых — **39**; **123** упоминают ≥2 страны; **22** — без страны. Вывод: большинство встреч правда трогают несколько рынков — вот механизм перетега.
- Поиск-гибрид (семантика+full-text, RRF) исправен; его портит грязная разметка на входе в буст. Страна в `match_entries_hybrid` сейчас — мягкий БУСТ, а не фильтр; чужие не отсекаются.

## 2. Принцип: упоминание ≠ предмет

Тег = страна **является предметом** записи. Присутствие токена (страна, город, слово «инспектора», имя) НЕ означает, что запись про это. Это верно и для стран, и для любых токенов — поэтому:

- **Решают только однозначные якоря**, которые «просто так не звучат»: домен `dodopizza.XX`, название страны в заголовке, фамилия партнёра + свой город.
- **Всё остальное неоднозначно → `General`.** Не выжимать «умные» связки из того, что слово где-то мелькнуло.
- Co-occurrence-майнинг подкидывает **кандидатов человеку**, членство не определяет.

## 3. Целевое поведение и смещение

- **Схлопывание при 2+ рынках:** ровно 1 явный рынок → тег; 0 или ≥2 → `General`.
- **1:1-синки → `General`** детерминированно (attendees ≤2 ИЛИ заголовок `1-1/1:1/X x Y/weekly/sync`), независимо от LLM.
- **Смещение — точность:** пока словари асимметричны, «не уверен → General». По мере наполнения словарей + накопления эталона ослабляем в сторону полноты там, где данные позволяют.
- Запрос «по стране X» → показывать **X + General**, встречи только-другой-страны прятать (фильтр).

## 4. Архитектура и поддержка

| Слой | Где живёт | Роль |
|---|---|---|
| `keys_all.yaml` | **единый источник данных** (правят владелец + агент) | словарь: strong/weak/risky/noise/pairs |
| Матчер | **один, в проде на TS** (`_shared/`), читает YAML | тегирование на ingest'е |
| `match2.py` | офлайн-стенд | тюнинг весов по эталону; **не пишет теги в прод** |
| Петля курирования | задача агента | находит новых людей/искажения → правит YAML |
| Линт YAML | CI/pre-commit | коллизии: один ключ ≠ strong у двух стран; noise-омонимы под контролем |
| Санитайзер (A) + Поиск-фильтр (C) | живой TS | чинят боль прода сами по себе, ортогональны словарю |

**Правило против дрейфа:** алгоритм существует ОДИН раз (TS-прод). `match2.py` повторяет ту же логику только для подбора весов; после подбора числа переносятся в TS.

## 5. Схема словаря (+ уточнения сессии)

- **strong** (одного сильного попадания в идеале достаточно — но см. §6 про MIN_W): `geo`, `cities`, `domains`, `vendors`, `local`, `meetings`, `legal`.
  - **geo** = название страны + национальность (RU/эндоним/EN/транслит). Базовые формы (склонения — стеммер). См. `geo_synonyms_expanded.yaml`.
  - **cities** = рабочие города (голые имена, RU+лат). **Пиццерии-с-номерами удалены** — город ловит «Город-N».
  - **domains** = `dodopizza.XX`, рабочие почты, тел. код.
  - **meetings** = названия регулярных встреч. **Не** класть boilerplate вроде «Royalty Fee» (общий по всем странам) — только уникальную часть.
- **weak** (люди): **только фамилия/полное имя/почта + алиасы. Первые имена в одиночку — запрещены.** Работают только в связке (см. pairs) или при наличии strong той же страны.
- **risky**: короткие омонимы («Бар», «Целе») — только точная форма, без стемминга.
- **noise**: как STT коверкает имена собственные — точная форма; гигиена списка критична (омонимы «Wendy», «Kifir»).
- **pairs**: связки разнородных ключей, уникальные для страны (пример владельца: `Юрий + Вива + ВНЖ = BG` — Viva не подключить только в BG из-за ВНЖ). Заранее все не построить; вычленяются регулярным майнером (§10).

**ISO-коды** (HU, RS) — не в словаре как ключи тела; ловятся отдельным **title-правилом**.

## 6. Сигналы и веса (`match2.py`) — сверка кода со спеком

Веса: пиццерии/домен/legal 4 · вендор/локальное/встреча 3 · гео 2 · risky 2 (точно) · noise 4 (точно) · человек +1/попадание · пара +5. Порог: вес ≥ `MIN_W=5` и ≥35% лидера.

**Расхождения код↔спек (чинить при порте в TS):**
1. **«Одного попадания достаточно» — в коде НЕ так.** Макс. одиночный strong = 4 < MIN_W 5 → нужен второй сигнал/повтор/пара. То же «две персоны» (вес 2 < 5). Код фактически строже спека — это ОК для «точности сейчас», но зафиксировать сознательно.
2. **`global`-схлопывания в коде НЕТ.** Спек: 3+ страны и лидер <2× второго → `global`. `verdict()` этого не делает (мульти-тегает всех ≥35%). **Добавить** — это ключ к анти-перетегу.
3. **Эталон в коде неверный:** сверка с `tags_in_base` (пере-теганной базой) награждает баг. Заменить на gold-set (§11).
4. **title-сигнал** (название/код страны в заголовке) в текущем `match2.py` не выделен (заголовок лишь ×2). Добавить как сильный title-scoped сигнал.
5. **Вес × число вхождений** надувает повтор (5×«Сербия» = RS 10) — усилитель асимметрии. Рассмотреть кап на повтор.

## 7. General-слой (форс General)

Структурные сигналы → `General`, что бы ни упоминалось:
- **1:1 / sync / weekly** (attendees ≤2 или заголовок).
- **HQ/кросс-маркет серии** (подтверждено чтением встреч): РКО / система оценки / IMF-инспектора (продукт+аудит, общекомандное — напр. «ЛК инспекторов IMF», «РКО 2.0»), International Marketing / «Dodo International Marketing», «Обучение в странах».
- **HQ-люди по ФАМИЛИИ** (не по имени): напр. Кузнецов (Сергей) — HQ-аудитор, всплывает в General/BG, не рынок. (Первые имена Сергей/Саша/Ксения/Антон — НЕ маркеры: много людей.)

Правило: General-маркеры добавляем **только прочитав встречу**, не из одного заголовка (урок сессии: «инспектора» я раздул из одного тайтла — так нельзя).

## 8. Поиск — страна как фильтр (C, из паркованного)

`match_entries_hybrid`: при заданном `filter_country` пул кандидатов ограничить `countries && {X}` OR `countries && {General}`; только-другую-страну исключить. `/ask`/`/search` уже шлют `detectQueryCountry(q)` — менять только RPC (миграция DROP+CREATE, сверить сигнатуру перегрузок).

## 9. Бэкфилл (D, из паркованного)

Прогнать правила A по существующим `entries` (санитайзер 2+→General, 1:1, снять литеральный `General` из миксов). Сначала SELECT-препросмотр + снапшот старых `countries`, потом UPDATE строго по WHERE. `entry_date IS NULL` → заполнить из `meetings`.

## 10. Майнер связок (регулярный проход)

Переиспользуемый SQL: якоря (домен/страна/город/фамилия) → встречи ровно одной страны → лифт **имён собственных** (не мешок слов) + разброс по многим странам = HQ-шум. **Кандидаты для человека, не решения.** Прогон 2026-08-06: переоткрыл известных партнёров (валидация), нашёл **HU = встречи на английском** (фича «язык»), в основном опроверг «умные сигналы». Данных мало (39 чистых из 184) — связки всплывут по мере роста базы.

## 12. Порядок стройки и прод-safety

A (санитайзер + тесты) → C (миграция RPC-фильтр) → перенос матчера B в TS (читает YAML) + title-правило + global-схлопывание → D (бэкфилл на проде, со снапшотом). Раскатка — только после проверки на реальном `/ask` «по Сербии» (правило прода). A+C можно катить раньше словаря — они снимают главную боль сами.
