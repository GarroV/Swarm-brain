# Ежедневный отчёт активности (daily activity report) — дизайн

> Дата: 2026-07-19. Статус: утверждён владельцем, готов к плану реализации.
> Тип: новая фича бота (`swarm-bot`). Автор запроса — владелец (админ).

## Цель

Владелец (админ) каждое утро получает в Telegram короткую сводку активности за **предыдущие календарные сутки**:

- **сколько встреч** добавлено в систему;
- **сколько новых данных** добавлено (заметки, ссылки, файлы, голосовые, инфа из чата).

Это **счётчики активности**, а не пересказ контента. Существующий недельный `digest.ts` (LLM-пересказ «что произошло по рынкам», по каждому пользователю) — другая фича; её не трогаем.

## Решения (из брейншторминга)

| Вопрос | Решение |
|---|---|
| Получатель | Только владелец — `ADMIN_USER_ID` (`744230399`, `swarm-bot/lib/supabase.ts`), в личку бота. Один получатель. |
| Детализация | 2 главные цифры + разбивка по источникам/типам. |
| Воркспейсы | Разбивка отдельно по каждому `group_id` (сейчас `cee` / `other`). |
| Период | Вчерашние **календарные** сутки `[00:00, 24:00)` в таймзоне `Europe/Belgrade` (CET/CEST). |
| Время отправки | ~08:00 по месту (cron ~06:00 UTC; ±1ч из-за DST — косметика, окно счёта всегда точное). |
| Канал | Telegram (как у текущего дайджеста). |

## Что считаем

Одна таблица — `entries`, окно по `created_at ∈ [sinceISO, untilISO)`.

- **Встречи** = `entry_type = 'meeting'` (все источники).
- **Новые данные** = `entry_type = 'note'` (заметки/ссылки/файлы/голос/чат — всё это `note`).
- **Исключаем** `source = 'digest'` (служебные записи дайджеста не считаются активностью).
- Группировка результата: `group_id` × `entry_type` × `source`.

### Граница по встречам (осознанное ограничение MVP)

Считаются встречи, **попавшие в базу знаний** (`entries`). Черновики рекордера / встречи «на вычитке», ещё **не опубликованные** (живут в таблице `meetings`, `status='awaiting_review'`), в счёт **не входят** — их ещё нет в `entries`. Granola-автоимпорт кладёт встречи сразу в `entries` (`confirmed=false`), поэтому они считаются.

_Будущее расширение (не в этом MVP):_ добавить счётчик «захвачено рекордером, ещё на вычитке» отдельным запросом к `meetings`.

### Маппинг `source` → отображение

Встречи (`entry_type='meeting'`):

| `source` | Ярлык |
|---|---|
| `desktop-agent` | рекордер |
| `granola` | granola |
| `read_ai` | read.ai |
| прочее | `<source>` как есть |

Новые данные (`entry_type='note'`):

| `source` | Ярлык |
|---|---|
| `telegram`, `note` | 💬 чат |
| `link` | 🔗 ссылки |
| `voice` | 🎤 голосовые |
| `document`, `file` | 📄 файлы |
| прочее | 📦 прочее |

## Окно времени

`yesterdayWindow(tz = "Europe/Belgrade", now = new Date())` → `{ sinceISO, untilISO, dateLabel }`:

1. Определить локальную дату «сегодня» в `tz` через `Intl.DateTimeFormat('en-CA', { timeZone })` → `YYYY-MM-DD`.
2. «Вчера» = сегодня − 1 день (в локальной дате).
3. `since` = локальная полночь «вчера», `until` = локальная полночь «сегодня»; обе конвертировать в UTC-инстант с учётом смещения `tz` (устойчиво к DST — смещение берётся из `Intl`, не хардкодится).
4. `dateLabel` = «вчера» в формате `DD.MM` (ru).

Так граница суток всегда корректна независимо от того, во сколько именно выстрелил cron.

## Формат сообщения (Telegram, HTML)

Штатный день:

```
📊 Свод за 18.07 (вчера)

🎙 Встречи: 4
   CEE 3 · Other 1
   рекордер 2 · granola 2

📝 Новые данные: 11
   CEE 7 · Other 4
   💬 чат 6 · 🔗 ссылки 3 · 📄 файлы 2
```

Правила рендера:
- Обе секции (**Встречи**, **Новые данные**) показываются всегда — даже с нулём (владелец хочет видеть и ноль).
- Подстроки секции (воркспейсы, источники) показываются только для **ненулевых** значений. Если итог секции = 0 — подстрок нет (только «🎙 Встречи: 0»).
- Порядок источников в подстроке — по убыванию счёта.

Тихий день (0 встреч и 0 данных):

```
📊 Свод за 18.07 (вчера)

За вчера ничего не добавили — тихий день.
```

(Отправляем всегда, в т.ч. в тихий день — это сигнал, что cron жив.)

## Архитектура и файлы

Новый файл `swarm-bot/handlers/daily-report.ts` (отдельно от `digest.ts` — разные назначения; не раздуваем модуль). Разбит на изолированные, тестируемые единицы:

| Единица | Тип | Ответственность |
|---|---|---|
| `yesterdayWindow(tz, now?)` | чистая | вычислить окно `[sinceISO, untilISO)` + `dateLabel` |
| `aggregateActivity(rows)` | чистая | из строк `entries` собрать `ReportData` (счётчики по воркспейсам/источникам) |
| `formatReport(data, dateLabel)` | чистая | из `ReportData` собрать текст сообщения (HTML) |
| `sendDailyReport()` | I/O | запрос `entries` в окне → `aggregateActivity` → `formatReport` → `sendMessage(ADMIN_USER_ID, …)` |

Типы:

```ts
type EntryRow = { entry_type: string; source: string; group_id: string | null };

interface SectionCounts {
  total: number;
  byWorkspace: Record<string, number>; // group_id → count
  bySource: Record<string, number>;    // ярлык → count
}
interface ReportData {
  meetings: SectionCounts;
  notes: SectionCounts;
}
```

- Отчёт **не** сохраняется в `entries` (не засоряем базу знаний статистикой; YAGNI).
- Запрос: `entries.select('entry_type, source, group_id').gte('created_at', sinceISO).lt('created_at', untilISO).neq('source','digest').in('entry_type', ['meeting','note'])`. Пагинация не нужна (сутки активности умещаются; при необходимости — `limit` с запасом, но реалистично < сотен строк).
- Отображаемый ярлык воркспейса — `group_id.toUpperCase()` (CEE / OTHER); `null`/пусто → «Без воркспейса». Группировка динамическая — новый воркспейс появится сам.

## Триггеры

### Cron
- Тело запроса к `swarm-bot`: `{ "daily_report_cron": true }`.
- Добавить флаг в guard-список крон-триггеров в `index.ts` (проверка `X-Cron-Secret`, рядом с `digest_cron`/`granola_poll`).
- Диспатч: `if (body.daily_report_cron === true) { await sendDailyReport(); return 200; }`.
- pg_cron (документируется в `docs/SETUP.md`, Шаг 12):

```sql
select cron.schedule(
  'daily-report',
  '0 6 * * *',  -- 06:00 UTC ≈ 07–08:00 Europe/Belgrade
  $$ select net.http_post(
       url := 'https://<YOUR_PROJECT_REF>.supabase.co/functions/v1/swarm-bot',
       headers := '{"Content-Type":"application/json","X-Cron-Secret":"<CRON_SECRET>"}',
       body := '{"daily_report_cron":true}'
     ); $$
);
```

### Ручная команда `/report`
- Только админ (`ADMIN_USER_ID` или `allowed_users.is_admin`) — иначе тихо игнор/«команда недоступна».
- Дёргает тот же `sendDailyReport()`. Служит и ручным вызовом по запросу, и смоук-тестом.
- В публичное меню `setMyCommands` **не** добавляем (админская, как `/superadmin`). В `/help` для админа — по желанию (не обязательно в MVP).

## Тестирование

- `swarm-bot/handlers/daily-report.test.ts` (deno test):
  - `aggregateActivity` — фикстуры строк → корректные счётчики (воркспейсы, источники, маппинг ярлыков, `digest` исключён на уровне запроса — в юните проверяем маппинг источников).
  - `formatReport` — штатный день (обе секции, разбивки) и тихий день (0/0 → плашка); строки воркспейсов/источников с нулём не рендерятся.
  - `yesterdayWindow` — при фикс. `now` даёт ожидаемые `sinceISO/untilISO/dateLabel`; корректность на границе DST (проверить хотя бы летнюю дату).
- `deno check` затронутых функций (pre-commit хук).
- Смоук: `/report` в Telegram от владельца → сообщение приходит, цифры бьются с реальными данными за вчера (проверю сам по БД).

## Не делаем (YAGNI)

- Веб-виджет / pull-версия (owner хочет пуш).
- Рассылку не-админам, per-user opt-in.
- Историю/персист отчётов.
- LLM-текст поверх цифр.
- Счёт неопубликованных черновиков `meetings` (вынесено в будущее расширение).
