# Дизайн: страновая атрибуция встреч (теги + поиск)

- **Дата:** 2026-07-30
- **Ветка:** `worktree-country-attribution` (worktree-изоляция), слив в `main` через merge
- **Статус:** черновик на ревью владельца
- **Триггер:** дайджест и поиск/ask подмешивают чужие страны (HU/SI под запрос «по Сербии»); реальные сербские встречи не находятся

## 1. Проблема (подтверждено данными прода)

Запрос «дай последнюю встречу по сербии» вернул источники с тегами **RS, SI (Slovenia), HU (Hungary)**; ответ сослался на встречу, которой нет в кликабельных источниках сверху. Причины (по убыванию вклада):

1. **Мега-перетегивание — главное.** Классификатор тегает страну по упоминанию/перечислению, а не по предмету. Примеры из прода:
   - «Dodo International Marketing» → `[RS,TR,KG,BY,HU,MD,MX,IN,RO,TJ,NG,General]` (12) и `[ES,BG,RS,MD,HU,KG,BY,MN,TJ,TR,LT,MX,IN,RO,General]` (15) — датированы и свежи → всплывают в ЛЮБОМ страновом запросе/разделе дайджеста.
   - «Sync HQ x Dodo Pizza HU» (кросс-маркет) → `[HU,RO,RS,HR,KG,General]`.
   - «Vasiliy/Sergey weekly» (1:1) → `[SI]` (мис-тег).
   - Системно: **64 из 175** встреч-записей имеют 3+ стран, хвост до 17–19.
2. **Страна в `/ask` и `/search` — мягкий БУСТ, а не фильтр** (`match_entries_hybrid`: `case … then country_weight/rrf_k else 0`). Чужие страны не отсекаются. (`/digest` уже фильтрует `countries.overlaps`, поэтому его загрязняют только сами теги.)
3. **`entry_date=null` у 15 из 183 встреч** → окно свежести (`20260724130000`) их дропает, когда есть ≥5 свежих (вторично).

## 2. Целевое поведение (со слов владельца)

- Тег страны = страна **является предметом** записи.
- Кросс-маркет / HQ / международные обзоры / 1:1-синки без привязки к рынку → **`General`** (или пусто), НЕ перечислять все страны и НЕ лепить одну случайную.
- Запрос «по Сербии» → показывать **RS + General** (общекомандные), а встречи с тегом ТОЛЬКО другой страны (HU-only/SI-only) — **прятать**.

## 3. Фикс (3 части)

**A. Данные — бэкфилл (быстрое облегчение, без деплоя).**
- Грубый перетег: записи с `cardinality(countries) >= 5` → после глазами-проверки схлопнуть в `['General']` (это международные/HQ-обзоры). Сначала SELECT-список, потом UPDATE (только WHERE, снапшот старых значений в отдельную колонку/лог для отката).
- `entry_date IS NULL` у встреч → заполнить из `meetings.started_at`/`meetings.created_at` (по `entry_id`).

**B. Классификатор — точность (`_shared/countries.ts` `COUNTRY_PROMPT_RULE`).**
- Усилить: перечисление/сравнение/allowlist соседей, HQ/международный обзор, 1:1-синк без привязки → `General`/пусто. НИКОГДА не выдавать длинный список стран. Заголовок встречи — сигнал (но не единственный).
- Кап: если модель насчитала >3 стран-предметов — почти наверняка это `General`.

**C. Поиск — страна как фильтр (`match_entries_hybrid`, новая миграция).**
- Когда `filter_country` задан: пулы кандидатов (full_text/semantic) ограничить `e.countries && array[filter_country] OR e.countries && array['General']`; встречи только-другой-страны исключить. Буст/свежесть оставить.
- `/ask`,`/search` уже передают `detectQueryCountry(q)` — менять вызовы не нужно, только RPC.

## 4. Фазы

- **P1 (сегодня, максимум облегчения):** A (бэкфилл перетега + entry_date) + C (фильтр в поиске). Убирает HU/SI из «сербской» выдачи и чинит дайджест сразу.
- **P2:** B (промпт классификатора) — чтобы новые встречи тегались правильно. + опц. полная ре-классификация спорных через LLM.

## 5. Проверка

- До/после на реальном `/ask` «дай последнюю встречу по сербии» (через прод после деплоя/бэкфилла): в источниках только RS + General, HU/SI ушли; реальные сербские встречи (Белград-2, трудовое право Сербии) — на месте.
- Дайджест: раздел «Сербия» без венгерских/словенских пунктов.
- `deno check`; для чистых функций классификатора — юнит-тест на новые правила, где выполнимо.

## 6. Риски

- **Схлопывание в General потерять нюанс:** для встреч с 5+ странами это почти всегда международный обзор — риск мал; снапшот старых `countries` для отката.
- **Фильтр спрячет нужное:** General включаем всегда; untagged/только-другая-страна прячем для странового запроса — если владелец захочет мягче, ослабим.
- Миграция RPC — **DROP+CREATE** (как `20260724130000`), сверить сигнатуру, иначе неоднозначность перегрузок ломает `/search`,`/ask`.
