# Дизайн: страновая атрибуция встреч (теги + поиск + ростер)

- **Дата:** 2026-07-30 (консолидировано 2026-08-06 с владельцем — заменяет черновик 07-30)
- **Ветка:** `feat/country-attribution` (worktree-изоляция), слив в `main` через merge. Старая `worktree-country-attribution` (7 дней, не влита) этой спекой перекрыта.
- **Статус:** на ревью владельца
- **Триггер:** дайджест и поиск/ask подмешивают чужие страны (HU/SI под запрос «по Сербии»); реальные сербские встречи не находятся

## 1. Проблема (подтверждено данными прода)

Запрос «дай последнюю встречу по сербии» вернул источники с тегами **RS, SI (Slovenia), HU (Hungary)**; ответ сослался на встречу, которой нет в кликабельных источниках сверху. Причины (по убыванию вклада):

1. **Мега-перетегивание — главное.** Классификатор тегает страну по упоминанию/перечислению, а не по предмету. Примеры из прода:
   - «Dodo International Marketing» → `[RS,TR,KG,BY,HU,MD,MX,IN,RO,TJ,NG,General]` (12) и `[ES,BG,RS,MD,HU,KG,BY,MN,TJ,TR,LT,MX,IN,RO,General]` (15) — датированы и свежи → всплывают в ЛЮБОМ страновом запросе/разделе дайджеста.
   - «Sync HQ x Dodo Pizza HU» (кросс-маркет) → `[HU,RO,RS,HR,KG,General]`.
   - «Vasiliy/Sergey weekly» (1:1) → `[SI,RS]` — уикли-синк с двумя рынками, должен быть General.
   - «Ksenia — Aleksandra 1-1» → `[HU,RS,MD,General]` — 1:1 с четырьмя тегами, причём `General` смешан с конкретными странами (микс — отдельный баг: ingest-путь granola не гоняет санитайзер).
   - Системно: **64 из 175** встреч-записей имеют 3+ стран, хвост до 17–19. Плюс масса двойных тегов (`[SI,RS]`, `[ES,HU]`, `[HR,BG]`), которые сейчас НЕ схлопываются (порог `applyGeneralSentinel` = 3+).
2. **Страна в `/ask` и `/search` — мягкий БУСТ, а не фильтр** (`match_entries_hybrid`: `case … then country_weight/rrf_k else 0`). Чужие страны не отсекаются. (`/digest` уже фильтрует `countries.overlaps`, поэтому его загрязняют только сами теги.)
3. **`entry_date=null` у 15 из 183 встреч** → окно свежести (`20260724130000`) их дропает, когда есть ≥5 свежих (вторично).

Поиск как таковой исправен (гибрид семантика + full-text, RRF) — его портит грязная разметка на входе в буст. Graphify (граф кодовой базы) рассмотрен и отклонён: не тот корпус, проблему меток не решает.

## 2. Целевое поведение (решения владельца, 2026-08-06)

- Тег страны = страна **является предметом** записи.
- **Схлопывание при 2+ рынках:** ровно **1** явный рынок → чёткий тег; **0 или ≥2** → **`General`**. Не перечислять страны, не лепить случайную. Правится при вычитке (UI уже есть).
- **1:1-синки → `General` по дефолту**, детерминированно (не только промптом): встреча 1-на-1 не привязана к рынку, пока владелец не проставит вручную.
- **Карта опыта (ростер):** есть устойчивые признаки рынка (города, люди, темы), по которым встреча явно причисляется к стране. Люди **пересекаются** между рынками (Антон и в SI, и в RS) → один признак не решает, нужна доминирующая **комбинация**.
- Запрос «по Сербии» → показывать **RS + General** (общекомандные), а встречи с тегом ТОЛЬКО другой страны (HU-only/SI-only) — **прятать** (фильтр, решение владельца).

## 3. Фикс (4 части, строим одним заходом)

### A. Классификатор — точность (`_shared/countries.ts`, `_shared/meta-extract.ts`)

1. **Порог схлопывания 2+ → General.** `applyGeneralSentinel`: `specific.length === 1` → оставить; иначе (`0` или `>=2`) → `["General"]`. (Правка `>= 3` → `>= 2`; сейчас двойные теги выживают.)
2. **Детерминированное правило 1:1 → General.** Если встреча 1-на-1 — по числу участников (`attendees.length <= 2`) ИЛИ по заголовку (regex: `1-1`, `1:1`, `X x Y`, `weekly`, `sync`, `/1 на 1/`) → `["General"]`, **независимо** от вывода LLM. Применяется в `meta-extract` для всех путей.
3. **Единый санитайзер на ВСЕХ ingest-путях** (granola / read-ai / desktop-agent / ручной) — прогонять `applyGeneralSentinel` + правило 1:1 в одном месте, чтобы никто не хранил `[A,B,General]`-микс (сейчас granola хранит сырой вывод).
4. **Усилить `COUNTRY_PROMPT_RULE`:** перечисление/сравнение/allowlist соседей, HQ/международный обзор, 1:1 без привязки → `General`/пусто. НИКОГДА не выдавать длинный список стран.

### B. Карта опыта — ростер рынков (`_shared/market-roster.ts`, НОВЫЙ)

- Структура: `country → { cities: string[], people: string[], topics: string[] }`. Ростер **курирует владелец** (сид ниже). Смежен со словарём имён `glossary.ts`, но отдельная сущность (там — нормализация написания для Whisper; тут — признаки рынка).
- **Применяется двумя слоями** (выбор владельца — оба, т.к. люди пересекаются):
  1. **В промпт классификатора** — как контекст-подсказка «признаки рынков», чтобы LLM различал SI/RS.
  2. **Детерминированный арбитр** поверх вывода LLM: скорим каждый рынок по числу совпавших признаков (город/люди/темы) в тезисах+заголовке. Рынок получает тег, ТОЛЬКО если его score **явно доминирует** и он **единственный** лидер → эта страна; ничья / несколько сильных / никого → `General`. Единичное совпадение имени (Антон) не решает; «Антон + Любляна» → SI, «Антон + Наталья + Белград» → RS.
- **Сид (заполнить/подтвердить владельцем при стройке):**
  - **SI (Словения):** города — Любляна; люди — Овчинников (Антон), Катя, Кристина; темы — TODO.
  - **RS (Сербия):** города — Белград, Нови Сад; люди — Антон, Наталья, Виталий; темы — TODO. (Уточнить «навесат/навеса два бёдра» — STT покорёжил, вероятно топоним/имя.)
  - Прочие рынки — по мере надобности; пустой ростер для страны = слой по ней не срабатывает (fallback на LLM+сентинел).

### C. Поиск — страна как ФИЛЬТР (`match_entries_hybrid`, новая миграция)

- Когда `filter_country` задан: пулы кандидатов (full_text/semantic) ограничить `e.countries && array[filter_country] OR e.countries && array['General']`; встречи только-другой-страны исключить. Буст/свежесть оставить.
- `/ask`, `/search` уже передают `detectQueryCountry(q)` — менять вызовы не нужно, только RPC.
- Миграция — **DROP+CREATE** (как `20260724130000`), сверить сигнатуру, иначе неоднозначность перегрузок ломает `/search`,`/ask`.

### D. Данные — бэкфилл (детерминированно, без LLM, со снапшотом)

- Прогнать по существующим `entries` те же правила A (санитайзер 2+ → General, правило 1:1, снять литеральный `General` из миксов). Сначала `SELECT`-список затронутых, снапшот старых `countries` (лог/отдельная колонка для отката), потом `UPDATE` строго по `WHERE`.
- `entry_date IS NULL` у встреч → заполнить из `meetings.started_at`/`meetings.created_at` (по `entry_id`).
- Опц.: спорные (оставшиеся 2-страновые до фикса) можно доразметить арбитром B, где ростер уверенно решает.

## 4. Порядок

Владелец выбрал **«всё вместе»** — единая спека и стройка. Внутренний порядок сборки (для безопасности прода): A (чистое ядро + тесты) → B (ростер + арбитр) → C (миграция RPC) → D (бэкфилл на проде, после того как A/B задеплоены и проверены). Раскатка на команду — только после проверки на реальном `/ask` (правило прода).

## 6. Риски

- **Схлопывание в General теряет нюанс:** двойной тег иногда легитимен (реально два рынка-предмета) → уедет в General. Митигируется правкой при вычитке (UI есть) + снапшотом старых `countries` для отката.
- **Фильтр спрячет нужное:** General включаем всегда; untagged/только-другая-страна прячем для странового запроса — если владелец захочет мягче, ослабим до буста.
- **Ростер устаревает / неполон:** пустой ростер по стране = fallback на LLM+сентинел, не хуже текущего. Люди-дубликаты обезврежены требованием доминирующей комбинации.
- **Миграция RPC** — DROP+CREATE, сверить сигнатуру перегрузок.
- **Бэкфилл на проде** — деструктивный UPDATE: только со снапшотом, строго по WHERE, сначала SELECT-препросмотр.
