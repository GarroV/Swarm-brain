# Доска спринтов — проект

**Дата:** 22.10.2026. **Решения владельца:** [docs/decisions/2026-10-22-sprint-board-direction.md](../../decisions/2026-10-22-sprint-board-direction.md) (дословно, по пунктам — ниже ссылки вида «Р1»). **Макеты** (вне репозитория, локально у владельца): доска v3.1 и «Как выглядит перенесённая задача».

## Зачем

Экран «Спринты» умеет всё, но ощущается «как костыли и обременение, а не помощь». Аудит 22.10 нашёл корень: **перенос — полудействие**. «→» и сдвиг срока задачу никуда не двигают, а только вешают пометку «к переносу»; задача уезжает позже, на приёмке. Поэтому причину нельзя спросить в момент решения, и её выпрашивают в трёх местах (значок в строке, поле под строкой, поле в приёмке). Вдобавок действия спрятаны за наведением, а поиск и фильтр по человеку есть только в «Плане».

Цель — чтобы спринты **помогали планировать во времени**: видно весь план, видно, что в каком спринте, перенос — одно настоящее действие с одной обязательной причиной, история не теряется, по каждой задаче можно увидеть её путь.

## Цели

1. **Новый вид «Доска спринтов»** рядом со «Список» (старый канбан снят 22.10.2026, Р12): слева закреплённый **мастер-план** со всеми задачами пространства (Р3, Р10), справа колонки спринтов, которые прокручиваются вбок под ним.
2. **Перенос — настоящее действие.** Задача сразу оказывается в спринте-цели, в прежнем остаётся **снимок** «перенесена → Спринт N · Причина: «…» · кто · когда» (Р4).
3. **Причина переноса обязательна и спрашивается один раз** — в момент переноса (Р1). Если перенос случился без человека в спринтах (срок сменили в карточке), снимок красный «причина не указана», её спрашивают один раз — при закрытии спринта. Уже записанную причину не спрашивают повторно.
4. **Задача может вестись в нескольких спринтах**, это задаётся заранее (Р5): «⋯ → Спринты задачи…». Между своими спринтами задача «продолжается» — без причин.
5. **Срок — внешняя жёсткая дата** (Р7). Действия на доске его не меняют. Работа, запланированная после срока, и перенос за срок подсвечиваются и требуют причину; срок меняется только явно.
6. **Ход задачи** — в любой момент через «⋯» (Р8): её спринты, апдейты (комментарии) по окнам спринтов, переносы с причинами, сколько заняло, насколько позже первого срока.
7. **Закрыть спринт** — один список незакрытых: куда дальше и почему; снимок спринта сохраняется. Прошлые спринты на доске — свёрнутые полоски, раскрываются кликом (Р9).

## Не цели

- Карточку задачи не меняем (Р6). В разделе «Задачи» задача остаётся обычной задачей.
- Вид «Список» не выпиливаем (Р2). Старый канбан «Статусы» снят позже (Р12).
- Автоматическая раскладка задач групп, которые ни разу не клали в спринт, — по-прежнему нет (решение 19.10, п.8).
- Третий язык интерфейса — отдельный план (i18n). Новые тексты — `dt("рус","eng")` как в соседнем коде.

## Анти-цели (провал, даже если «работает»)

- Причину спрашивают больше одного раза за один перенос, или красное «причина?» висит на задаче, у которой причина уже есть.
- Система сама двигает срок задачи.
- Главные действия видны только при наведении.
- Мастер-план уезжает при прокрутке колонок.
- Ломаются «Список», аналитика спринтов, журнал, MCP-инструменты спринтов, раздел «Проекты» (защищён — не трогаем вообще).

## Словарь

- **Пространство спринтов** — `sprint_cycles.tab_id` (+ `group_id` воркспейса). В нём один идущий спринт и сколько угодно запланированных (`draft`).
- **Мастер-план** — все задачи групп пространства (группы = подпроекты проекта пространства, решение 05.10), то, что сейчас показывает панель «План».
- **Строка спринта** — `sprint_items` (спринт × задача). Задача может иметь строки в нескольких спринтах.
- **Спринты задачи (план работы)** — набор её живых строк в спринтах пространства, всегда подряд.
- **Продолжение** — задача незакрыта к концу спринта, но у неё уже есть строка в следующем по плану. Причина не нужна.
- **Перенос** — задача уходит из спринта туда, где её не планировали (за последний свой спринт). Причина обязательна.
- **Снимок** — строка спринта, из которой задача ушла (или строка закрытого спринта): показывает состояние на момент ухода/закрытия, не редактируется, кроме вписывания недостающей причины.
- **Спринт срока** — спринт пространства, в окно которого попадает `tasks.due_date` (флажок 🏁).

## Как работает — для человека

### Доска

- Переключатель вида в полосе спринта: одна пилюля **Список · План · Доска спринтов** («План» — часть списка, на доске его нет; «Статусы» сняты, Р12). Выбор помнится, как сейчас.
- Над доской одной строкой: пространство, поиск, «Все люди», «Требуют внимания», «История спринтов». Поиск и люди действуют на **все** колонки, включая мастер-план.
- Колонки слева направо: **Мастер-план** (закреплён) · прошлые закрытые спринты (полоски, раскрываются) · идущий (шире, с прогрессом и «Закрыть спринт») · запланированные · «+ Спринт».
- Мастер-план: группы → задачи, у каждой полоска спринтов (закрашены её спринты, рамка — идущий) и срок с 🏁. Готовые внизу или скрываются флажком, как сейчас.
- Карточка: слева кружок «готово», название целиком, справа «⋯». Под названием: срок (красный, если просрочен), метки («2-й спринт», «из Спринта 4», «спринт 2 из 3», «сверх плана», риск/проблема цветной полосой слева), аватар.
- Снимок ушедшей задачи — серая пунктирная карточка в блоке «Ушли из спринта» внизу колонки: «перенесена → Спринт 5 · срок 21.10 → 16.11», ниже «Причина: «…» · кто · дата». Без причины — красное «причина не указана — нажмите, чтобы вписать» (вписывание в маленьком окне).

### Меню «⋯» (одно на всё)

- Спринты задачи… · Ход задачи по спринтам
- Сверка: По плану / Риск / Проблема (пояснение — комментарием по желанию, поле не требуется)
- Взять в Спринт N (из мастер-плана) / Перенести в Спринт N… (из идущего) / Переставить в Спринт N (между запланированными, без причины)
- Убрать из спринта (снятие, как сейчас `withdrawn_at`)
- Заморозить · Открыть карточку · Сделать подзадачей…

Перетаскивание делает то же, что пункты меню. На телефоне перетаскивания нет — только меню.

### Перенос (из идущего спринта в другой, незакрытой задачи)

Окно: «Перенести в Спринт N», поле «Почему не успели в этом спринте?» (кнопка неактивна, пока пусто), блок про срок:
- цель не позже спринта срока → «Срок 30.10 не меняется — успеваете»;
- цель позже спринта срока или срок уже прошёл → «Срок 21.10 будет сорван. Новый срок: [дата]», по умолчанию — последний день спринта-цели; можно стереть — задача останется просроченной.

После «Перенести»: строка в цели (`carried_from` = исходная строка), исходная строка становится снимком с причиной, причина уходит комментарием в задачу (существующий механизм 19.10), срок меняется только если человек оставил новую дату.

### Срок сменили в карточке задачи

Как сейчас (триггер `sprint_autoplace_task`), но **сразу двигает**: задача получает строку в спринте нового срока, строка идущего становится снимком без причины (красный). Если новый срок внутри идущего — ничего не происходит.

### Спринты задачи…

Окно с плитками спринтов пространства (прошлые недоступны, идущий в рамке, спринт срока с 🏁). Выбор — непрерывный отрезок. Итог текстом: «Ведём в 3 спринтах: С4–С6. Срок 01.12 (🏁 С7) не меняется». Если последний выбранный позже спринта срока, или отрезок продлевает задачу за её последний спринт из идущего, — красная подсказка и обязательная причина. Сохранение создаёт недостающие строки в запланированных спринтах (`in_plan = true`) и снимает лишние **только в запланированных** (в идущем и прошлых не удаляет).

### Закрыть спринт

Заменяет «Принять спринт» (то же действие `accept_sprint_cycle`, новое окно):
- «Сделано N из M». Снимок сохраняется в «Историю».
- **Продолжаются** (есть строка в следующем по плану) — списком, без вопросов.
- **Незакрытые без продолжения** — по каждой: куда (Спринт 5 по умолчанию / другой запланированный / вернуть в мастер-план / отменить задачу) и причина. Причина подставляется, если уже есть (из снимка или из комментария переноса этой задачи за этот спринт), — с пометкой «причина уже есть». Кнопка неактивна, пока у каждой нет причины (кроме «отменить»).
- **Уже ушли без причины** (срок сменили в карточке) — по каждой поле причины.

### Ход задачи

Окно из «⋯» в любой момент: итог (спринтов, переносов, апдейтов, дней от взятия в первый спринт, отставание от первого срока), затем по спринтам: даты, срок на входе/выходе, комментарии задачи, попавшие в окно спринта, перенос с причиной, итог («сделана 12.11 — до срока»).

### Телефон

Колонки во всю ширину с прокруткой по одной (scroll-snap), мастер-план первой. Перенос и «Спринты задачи» — через «⋯».

## Модель данных (что меняется)

Опора на существующее: `sprint_items` уже допускает задачу в нескольких спринтах (уникальность по паре спринт+задача), есть `carried_from`, `carry_count`, `carry_reason`, `frozen_*`, `withdrawn_at`.

Добавить (аддитивные колонки, без переименований — правило двух шагов):
- `sprint_items.moved_at timestamptz`, `moved_to uuid` (строка-цель), `moved_by text` — строка стала снимком переноса. Снимок = `moved_at is not null`. Заполняются `frozen_*` на момент ухода.
- `sprint_items.carry_reason` — переиспользуем как причину ухода для снимка. `to_carry`/`carry_auto` остаются для старых строк и «Списка» на переходный период; новый код ими не пользуется (снятие — отдельным шагом после раскатки, два шага).
- `sprint_items.plan_reason text` — причина плана работы после срока / продления (из «Спринтов задачи»).

Правила (в одном месте — функции базы, их же зовут API и MCP):
- `sprint_move_task(item_id, target_cycle_id, reason, new_due?, actor)` — перенос из идущего: проверка причины (не пустая), вставка строки цели, превращение исходной в снимок, опциональная смена срока (без повторного срабатывания автоматики), комментарий-причина.
- `sprint_set_task_span(task_id, tab, from_cycle, to_cycle, reason?, actor)` — плитки «Спринты задачи».
- Триггер срока — переписать ветку «срок за концом идущего»: вместо пометки — перенос без причины.
- `accept_sprint_cycle` — принимает решения по каждой незакрытой (куда/причина) вместо «все хвосты в ближайший».
- Прогресс и статистика: снимки ушедших считаются «перенесено», не «не сделано»; продолжения — «продолжились».

Миграция существующих данных: открытые строки с `to_carry = true` в идущих спринтах остаются как есть; при закрытии спринта они попадают в список «без продолжения» с подставленной причиной (если есть).

### Расхождения с нынешним кодом, которые проект меняет осознанно

- **Триггер срока сейчас удаляет строки задачи во всех запланированных спринтах, кроме цели** («в двух местах задача не висит», `sprint_autoplace_task`). С планом работы на несколько спринтов это молча сносит план. Новое правило — ниже, «Смена срока у задачи с планом».
- **Уникальность `(cycle_id, task_id)`** в `sprint_items` не даёт держать снимок и живую строку одной задачи в одном спринте. Решение — ниже, «Возврат в спринт со снимком» (индекс не меняем).
- **`accept_sprint_cycle`** сейчас сам решает, куда едут хвосты. Новая версия принимает решения по каждой незакрытой задаче (куда / причина / отменить); меняется сигнатура → правятся её потребители: `_shared/tasks/sprint-cycles.ts`, `swarm-api/sprint-cycles.ts`, MCP `accept_sprint`. Старую сигнатуру держать на время перехода не нужно — потребители в одном репозитории и катятся одной раскаткой.

### Правила на граничные случаи (решены при вычитке проекта)

- **Смена срока у задачи с планом.** План сохраняется. Новый срок внутри плана — строки не трогаются; спринты плана после спринта срока подсвечиваются «после срока» (без удаления). Новый срок позже последнего спринта плана — план продлевается строками до спринта срока, строка идущего (если задача в нём) остаётся живой (она продолжается), а продление помечается «продлена без причины» и попадает в вопросы при закрытии идущего. Задача без плана (одна строка) — как в разделе «Срок сменили в карточке».
- **Возврат в спринт со снимком.** Если задача возвращается в спринт, где лежит её снимок (срок вернули, перенесли обратно), снимок **оживает**: `moved_*` сбрасываются, причина остаётся в истории комментарием. Уникальный индекс не меняется.
- **Нет спринта-цели.** Как сейчас у автоматики: недостающие запланированные спринты создаются подряд (`sprint_autoplace_target`, тот же предел). В окне переноса на доске цели — существующие спринты и «+ новый после последнего».
- **«Взять в спринт» после срока** из мастер-плана — подсветка и обязательная причина в `plan_reason` той строки; в «Спринтах задачи» причина пишется в `plan_reason` последней добавленной строки. Причины выхода за срок также уходят комментарием в задачу.
- **Статистика.** Закрытые спринты не пересчитываются (их `stats` заморожены). Новые категории («перенесено», «продолжилось») считаются для спринтов, закрытых после раскатки; аналитика показывает старые и новые как есть.
- **«Список»** переходит на то же действие переноса (`sprint_move_task`) и то же окно с причиной — два разных смысла «→» не остаются. Кнопка «→» в строке «Списка» открывает окно переноса.
- **Кто и когда у снимка.** `moved_by` — telegram id человека (как `withdrawn_by`); перенос автоматикой — `null`, показывается «автоматически · сменили срок». Через MCP — личность из токена.
- **Ход задачи и окна.** Спринты пространства идут встык и не пересекаются, комментарий попадает в спринт по `created_at`; комментарий между спринтами (зазор) — в ближайший предыдущий.
- **Защищённые пути.** Перед работой сверить `.github/protected-paths.txt`: `_shared/tasks/sprints.ts` защищён (это проекты), `sprint-*.ts` — нет. Если правка всё же понадобится в защищённом — трейлер `Owner-approved` с цитатой из решения 22.10.

## Границы и защищённое

- Раздел «Проекты» (`.github/protected-paths.txt`, `SprintBoard.tsx` — доска проектов, `_shared/tasks/sprints.ts`, миграции, трогающие `projects`/`sprints`) — **не трогать**. Нужны данные групп — читать существующими функциями.
- Все проверки доступа — как у существующих эндпоинтов спринтов (видимость пространства, приватные задачи в спринты не попадают).

## Оставлено исполнителю

Вёрстка и компоненты (переиспользовать `PlanPanel`, `SprintRow`/канбан-карточки, `useRowDrag`), формат ответа API доски, кэширование, точные тексты в рамках правил выше, порядок миграций, тесты ядра (перенос, план работы, закрытие, триггер срока) — по правилу «ядро — тесты до кода».

## Вопросы, решённые мной (не владельцем) — проверить при чтении

- Ход задачи — через «⋯» на доске, в карточку задачи не встраиваю (Р6 важнее; Р8 допускает «либо через три точки»).
- Перестановка между запланированными спринтами — без причины (это планирование, а не срыв).
- Новый срок при срыве по умолчанию — последний день спринта-цели.
- «Принять спринт» переименовывается в «Закрыть спринт».
- Смена срока не сносит план работы на несколько спринтов (сейчас сносит); продление за план без причины спрашивается при закрытии.
- «Список» переходит на тот же перенос с окном причины.
