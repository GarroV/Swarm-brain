# Переиспользование вкладки/окна при открытии встречи из уведомления

Дата: 2026-06-17

## Проблема

Уведомление «📝 Тезисы встречи готовы» (`meeting-ingest`) содержит кнопку «Открыть»
с обычной `url:`-ссылкой `https://swarm-brain.pages.dev/?meeting=<id>`. В Telegram
Desktop каждый клик открывает **новую вкладку браузера**. Нужно: при наличии уже
открытой вкладки/окна приложения — переходить в нём на нужную встречу, а не плодить
вкладки.

## Ограничения

- Кнопка бота — обычная навигация браузера. Страница назначения не может
  программно сфокусировать/закрыть чужую вкладку, которую она не открывала.
- Поэтому надёжный «no new tab» возможен только: (а) установленный PWA с
  `launch_handler` + `handle_links`; (б) свежая вкладка с одной записью истории —
  ей `window.close()` разрешён.
- Целевая среда — **Telegram Desktop → Chrome** (десктоп). iOS Safari link-capturing
  PWA не поддерживает (вне рамок задачи).

## Решение — два слоя, только во фронте `miniapp/`. Кнопку бота не трогаем.

### Слой 1 — установленный PWA
`public/manifest.webmanifest`:
```json
"launch_handler": { "client_mode": "focus-existing" },
"handle_links": "preferred"
```
- `handle_links: preferred` → Chrome перехватывает in-scope ссылки и открывает их в
  установленном PWA, а не во вкладке браузера.
- `focus-existing` → окно PWA не перезагружается, фокусируется; целевой URL приходит
  в `window.launchQueue`. Подключаем consumer: парсим `meeting` → событие
  `roy:open-meeting`.

### Слой 2 — обычный браузер (дедуп вкладок)
Новый модуль `src/lib/single-tab.ts`:
- **Лидер-выборы** через `navigator.locks` (эксклюзивный лок `swarm-leader`,
  удерживается всё время жизни вкладки) → ровно одна «переиспользуемая» вкладка;
  при её закрытии лидером становится следующая из очереди.
- **Обмен** через `BroadcastChannel('swarm-tabs')`.
- Новая вкладка с deep-link **до тяжёлого рендера** вызывает `tryHandoff(id)`: шлёт
  `claim`, ждёт ~250 мс. Лидер ловит → `roy:open-meeting` + `window.focus()` +
  `ack`. По `ack` новая вкладка делает `window.close()`. Нет ответа → сама вызывает
  `registerInstance()` (становится лидером) и рендерится.

### Общая точка
Оба слоя в итоге диспатчат `CustomEvent('roy:open-meeting', { detail: { id } })`
(+ `history.replaceState` на `/?meeting=<id>`). `RoyApp` слушает это событие и
вызывает `openMeeting(id)` (тот же код, что и для начального deep-link).

### Интеграция
- `src/components/SingleTabGate.tsx` (клиентский) в `layout.tsx` оборачивает
  `children`. Всегда регистрирует инстанс (лидерство + launchQueue). Блокирует
  рендер мини-сплэшем **только** когда есть deep-link и идёт хэндофф; иначе рендерит
  сразу.
- `RoyApp`: deep-link-логика вынесена в `openMeeting(id)`; добавлен слушатель
  `roy:open-meeting`.

## Фоллбэки
- `window.close()`/`focus()` заблокированы → новая вкладка показывает мини-экран
  «Открыто в другой вкладке».
- Нет `BroadcastChannel`/`navigator.locks` → поведение как сейчас (новая вкладка).

## Развёртывание
- Только пересборка `miniapp` → Cloudflare Pages (push в `sandbox_vas`).
- Бамп версии кэша в `public/sw.js` (`roj-static-v23` → `v24`), чтобы подхватился
  новый манифест.
- Supabase / бот **не трогаем**.

## Проверка
- Telegram Desktop: открыть приложение во вкладке → нажать «Открыть» в уведомлении
  дважды → существующая вкладка переходит на встречу, лишние вкладки закрываются.
- Установить PWA → нажать «Открыть» → открывается/фокусируется окно PWA на встрече.
