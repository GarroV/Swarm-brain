# Редизайн веба «Рой» — Swarm-brain-4 (desktop + добивка мобильных)

**Дата:** 2026-06-18
**Статус:** согласован, готов к плану реализации
**Ветка работы:** `sandbox_vas` (через git worktree на воркстрим)

---

## 1. Контекст и ключевой вывод

`Swarm-brain-4/` — это общая папка дизайн-исследований, где соседствуют три разных продукта:
**Рой** (наш веб), **Just Tell** (отдельная P2P-платформа поддержки) и **PetStuff** (nutrition-app).
Для этой задачи релевантен **только** Рой:
- `Swarm-brain-4/design_handoff_roy/` — канонический мобильный хендофф;
- `Swarm-brain-4/dashboard.jsx`, `board.jsx`, `admin.jsx`, `Рой - дашборд.html`, `Рой - экраны.html` — **новый desktop-концепт**.

**Главный факт:** мобильный хендофф (`design_handoff_roy/`) **уже реализован в проде**. Токены в
[`miniapp/src/app/globals.css`](../../../miniapp/src/app/globals.css) совпадают с README хендоффа дословно
(тот же hex, те же имена), шрифт Golos Text подключён, все 10 мобильных экранов построены в
[`miniapp/src/components/roy/`](../../../miniapp/src/components/roy/), навигация 4-таба + push-стек работает.

Поэтому этот редизайн — **не переделка с нуля**, а: (а) сборка нового **desktop**-концепта,
(б) **добивка** отдельных мобильных экранов до спеки хендоффа, (в) обкатка **dark mode**.

## 2. Цели

- Собрать desktop-концепт «единый экран» (главный экран, доска задач, ревью встреч) на реальных данных.
- Закрыть расхождения мобильных экранов с хендоффом.
- Привести dark mode в рабочее состояние.
- Сохранить единый визуальный язык на весь продукт.

## 3. Не-цели (явно вне скоупа)

- **Полная календарная админка** (согласование/перенос запланированных встреч, детект конфликтов): нет данных —
  Google Calendar подключён **read-only** (`calendar.events.readonly`) и сервер знает только «текущую» встречу
  (окно now−2мин…+10мин в [`meeting-current`](../../../supabase/functions/meeting-current/index.ts)).
  Хранилища событий нет. Это отдельный проект.
- **Попапы** концепта («вам назначили задачу», «новые встречи» + колокол): требуют realtime, апп на
  static-export + polling. Возможная отдельная фаза.
- **Just Tell / PetStuff** и превью-инструменты (`design-canvas.jsx`, `support.js`, `ios-frame.jsx`,
  `tweaks-panel.jsx`) — в реализацию не идут.
- **Возврат старых Base-фильтров** хендоффа (Документы/Транскрипты): текущая таксономия (Заметки/Ссылки/Файлы)
  отражает новую facets-модель (entry_type = только Встреча/Заметка), её не трогаем.
- **NewTask/NewEntry → роевые push-формы**: на этом проходе оставляем существующий `TaskModal` (Dialog).
  Перевод в push-стиль — опционально, низкий приоритет, вне этого скоупа.

## 4. Принятые решения (из брейншторма)

1. **Скоуп:** полный проход — desktop + мобильные добивки + dark mode.
2. **Визуальный язык:** единый. Берём раскладку/инфоархитектуру нового концепта, но собираем в **уже
   отгруженной системе** (Golos Text, flat-поверхности, тонкие `--line`, примитивы `roy/ui`). Asap-шрифт,
   точечную текстуру фона и толстые `2px ink` рамки из прототипа **не переносим**.
3. **Блок встреч:** показывает последние встречи, аппрув-нужные вперёд. На существующих данных
   (`fetchMeetings` + `fetchAgentMeetings("awaiting_review")`), без нового бэкенда.

## 5. Дизайн-система (WS1 · S)

Токены уже в проде и менять их не нужно. Только пиксельные доводки в
[`globals.css`](../../../miniapp/src/app/globals.css) / [`roy/ui.tsx`](../../../miniapp/src/components/roy/ui.tsx):

- роевой Input → радиус 18px (сейчас shadcn `rounded-lg` ≈13px);
- сверка теней: тост `0 10px 30px rgba(0,0,0,.3)`, активный сегмент `0 1px 4px rgba(80,60,20,.1)`;
- TypeTag-цвета через `color-mix(... 14%)`, радиусы чипов (market 7px / type 8px), таб-бар подпись 10.5px.

**Acceptance:** визуально роевой Input и чипы совпадают с хендоффом; примитивы не перекрашены глобально
(меняем только роевой слой, shadcn-переменные не трогаем).

## 6. Desktop · Главный экран (WS-Home · L)

Заменяем текущий бенто [`RoyDashboard.tsx`](../../../miniapp/src/components/roy/RoyDashboard.tsx) на
3-колоночную раскладку концепта ([`dashboard.jsx`](../../../Swarm-brain-4/dashboard.jsx)), в текущих примитивах
и на реальных данных. Грид `288px · minmax(0,1fr) · 344px`, gap 16.

| Зона | Что | Данные |
|---|---|---|
| Лево | **Мои задачи** (Сегодня / На неделе, + «N без срока») | `fetchTasks` → assignee = текущий пользователь; группировка: сегодня (due ≤ сегодня) / на неделе (due ≤ +7д) / без срока |
| Центр-верх | **Поиск-герой** (поле 2px ink, иконка spark, ⌘K, чипы быстрых запросов) | существующий `ask`/answer-флоу (`push answer`) |
| Центр-низ | **Материалы за сутки** (лента: иконка типа · заголовок · тип · автор · «N ч») | `fetchEntries` → `created_at` за последние 24ч, сорт по свежести |
| Право-верх | **Встречи** (аппрув-нужные вперёд) → шапка ведёт в Админку | `fetchMeetings` (неподтв. вперёд) + `fetchAgentMeetings("awaiting_review")` |
| Право-низ | **Задачи команды** → шапка ведёт в Доску | `fetchTasks` → assignee ≠ текущий пользователь |

- Паттерн «панель раскрывается в полную вкладку по клику на шапку» — уже есть в `DashBlock`, переиспользуем.
- Только `lg+`. На мобайле/планшете остаётся `SearchScreen` (логика выбора в `RoyApp.tsx`, `isDashboard`).
- Состояния: loading (шиммер `roy-shim`), empty (текст), error (graceful — пустая панель).

**Acceptance:** на `lg+` главная = 3 колонки с реальными данными; «Мои» и «Команда» корректно разделены по
assignee; материалы показывают только записи за 24ч; клики по шапкам ведут на нужные вкладки/экраны.

## 7. Desktop · Доска задач (WS-Board · M)

Концепт [`board.jsx`](../../../Swarm-brain-4/board.jsx): kanban с переключателем scope **Мои / Команда / Все**.
Ложится на существующую вкладку «Задачи» (десктоп уже рендерит
[`tasks/TasksScreen.tsx`](../../../miniapp/src/components/tasks/TasksScreen.tsx) с видами Доска/Таймлайн/Спринт/Граф) —
дорабатываем вид «Доска» (`KanbanBoard`) под scope.

- **Колонки v1 = существующие статусы:** Открыто / В работе / Готово (метки как в остальном приложении).
  Колонку «На ревью» из концепта в v1 **не вводим** — нет такого статуса задач (есть open/in_progress/done/cancelled).
  Добавление статуса `review` — возможная будущая аддитивная миграция (`ADD VALUE`), вне этого скоупа.
- **Scope-фильтр** Мои/Команда/Все — по assignee, поверх `fetchTasks`.
- Карточка: точка приоритета, заголовок, теги, срок, аватар исполнителя/пометка «Личное».

**Acceptance:** на вкладке «Задачи» вид «Доска» имеет переключатель Мои/Команда/Все; карточки раскладываются
по существующим статусам; никаких миграций БД.

## 8. Desktop · Админка / ревью встреч (WS-Admin · M)

Концепт [`admin.jsx`](../../../Swarm-brain-4/admin.jsx) master-detail (список · детали · действия), собранный
поверх **существующих очередей ревью**:

- **Список (слева):** неподтверждённые встречи (`fetchMeetings({confirmed:false})`) + черновики «на вычитке»
  (`fetchAgentMeetings("awaiting_review")`), аппрув-нужные сверху; статы (на согласовании / всего за неделю).
- **Детали (центр):** заголовок, организатор/источник, мета, AI-саммари, участники, повестка/тезисы из записи.
- **Действия (справа):** Согласовать (= confirm/перевод в подтверждённые) · Отклонить (= delete черновика).
  Логика уже есть в [`AgentReviewQueue`](../../../miniapp/src/components/AgentReviewQueue.tsx) / `MeetingReview`.
- Календарные конфликты/перенос — **нет** (нет данных).

Доступ: открывается с шапки блока «Встречи» на главном экране; для `me.is_admin` — также из «Ещё → Админ».

**Acceptance:** master-detail список реально читает обе очереди; Согласовать/Отклонить дёргают существующие
эндпоинты; экран в роевом визуальном языке (не shadcn-дефолт `AdminScreen`).

## 9. Mobile · Добивка до спеки (WS-Mobile · M)

Расхождения между хендоффом и кодом (каждый экран независим):

- **SearchScreen:** добавить блок «Продолжить» (N задач в работе → таб Задачи; ближайшая встреча → её деталь).
- **AnswerScreen:** уточняющие чипы (доп-вопросы) + шиммер-плейсхолдеры в загрузке (карточка 86px + 3×64px).
- **TaskDetail:** секция «Связано из базы» (карточки связанных записей).
- **RecordDetail:** закреплённая нижняя панель «Связать» (вторичная) + «В задачу» (primary).
- **MeetingDetail:** секция «Задачи из встречи» (карточки связанных задач).

**Acceptance:** каждый экран совпадает с разделом README хендоффа; деградация graceful, если связанных
данных нет.

## 10. Dark mode + полировка (WS-Dark · S)

Тёмные токены полные, но не обкатаны. Прогнать на реальном устройстве/в Telegram WebView, проверить контраст
роевых экранов и desktop-панелей, починить найденное. (Прототипная смена статус-бара iPhone на светлый — про
корпус прототипа, в Telegram неприменима, игнорируем.)

**Acceptance:** dark mode читаем на всех роевых и desktop-экранах; нет нечитаемых сочетаний; reduced-motion работает.

## 11. Риски

- **WS-Home assignee-логика:** «Мои vs Команда» зависит от того, как `tasks.assignees` соотносится с текущим
  пользователем (telegram_id vs имя). Уточнить в плане по `types.ts` / `api.ts`.
- **Материалы за сутки:** объём `fetchEntries` без серверного фильтра по дате — отфильтровать на клиенте или
  добавить `date_from` (эндпоинт уже принимает `date_from`/`date_to`).
- **Next.js 16 / static export:** никакого SSR/Realtime; всё клиентское + polling. Новых серверных зависимостей
  desktop-экраны не вводят.
- **Telegram WebView перф:** анимации/`backdrop-blur` проверить на слабых устройствах.

## 12. Порядок реализации

- **Фаза 1 (параллельно):** WS1 (токены) · WS-Dark — фундамент пиксель-точности.
- **Фаза 2:** WS-Mobile — 5 независимых экранов, параллелятся через `git worktree` (см. CLAUDE.md).
- **Фаза 3 (последовательно):** WS-Home → WS-Board → WS-Admin — самый объёмный desktop-блок в конце.

Каждый воркстрим: своя worktree-ветка от `sandbox_vas`, `deno check`/type-check затронутого, коммит+пуш на
каждое логически завершённое изменение, обновление `docs/ARCHITECTURE.md` + `docs/MINIAPP_ARCHITECTURE.md`
при изменении флоу/структуры.
