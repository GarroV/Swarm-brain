# Метрики разбора задач (#136, частично)

`swarm-api/task-extraction-response.ts` сохраняет прежние JSON/SSE-ответы
`POST /tasks/extract` и пишет одну JSON-строку по завершении:

- `event`: `task_extract`;
- `mode`: `json` или `sse`;
- `outcome`: `done`, `upstream_error`, `invalid_response` или `stream_error`;
- `task_count`: число предложений в HTTP-ответе, а не сохранённых задач;
- `first_task_ms`: время до первой поставленной в HTTP-поток валидной задачи;
- `total_ms`: время до завершения обработки.

Время монотонное, отсчитывается перед вызовом экстрактора. JSON и поток без задач
имеют `first_task_ms: null`. Счётчик учитывает прежние потолки: JSON 10, SSE 20.
Текст запроса, задачи, идентификаторы и содержимое ошибок в метрику не входят.
Серверный TTFT не доказывает отсутствие буферизации в сети или браузере.

## Проверка и граница

`deno test -A --config deno.json supabase/functions/swarm-api/task-extraction-response.test.ts`
читает настоящий `Response.body`, пока upstream ещё открыт: первая задача уже
доступна, а метрика завершения ещё не записана. Сценарии покрывают JSON, SSE,
отказ до заголовков, ошибку после первой задачи, непарсящийся ответ и потолки.

Для поиска в `function_edge_logs` нужна строка JSON с `event = task_extract`;
сравниваются `mode`, `first_task_ms` и `total_ms`, отдельно проверяется `outcome`.
Пустой ответ JSON имеет ноль задач и `first_task_ms: null`. Ошибка до первого
предложения тоже имеет `first_task_ms: null`, но другой `outcome`.
Метрики не создают задач и не меняют SSE-события `task` / `done` / `error`.

Для завершения #136 нужен отдельно разрешённый вызов живого экстрактора с обычной
веб-сессией: сопоставить серверные метрики и времена получения кадров клиентом.
Синтетические потоки проверяют обработку и метрики, но не скорость модели и сети.
