# Комментарий к задаче — 20 000 знаков

**Дата:** 22.09.2026
**Статус:** принято, реализовано (issue #445)

## Решение владельца (дословно)

> «я думаю что 20к хватит. по сути должно вмещать лонг пост из телеграма»

Про поведение Enter в поле ввода — отдельно, в том же разговоре: **оставить как есть**
(Enter отправляет, Shift+Enter переносит строку), привычное действие не переучиваем.

## Почему вопрос вообще встал

Пользователи жаловались, что нельзя добавить большой объёмный комментарий. Предел был
**4000 знаков** — санитарное число из плана фичи 21.07.2026, без технического обоснования
ни в плане, ни в спеке, ни в коде. В базе ограничения нет: колонка `content` типа `text`.

Жалоба звучала как «не работает», а не «слишком длинно», по двум причинам:

1. Отказ сервера (400 «Слишком длинно») до человека не доходил — веб ловил ошибку пустым
   `catch` и показывал «Не удалось отправить».
2. Поле ввода было в одну строку с потолком 112px и без растягивания: вставленный большой
   текст человек не видел целиком.

На момент решения в проде 227 комментариев, самый длинный — 2891 знак, средний — 139.

## Почему предел остаётся, а не снимается совсем

Лента комментариев задачи отдаётся **одним запросом целиком, без пагинации**. Без предела
одна вставленная простыня означала бы мегабайты на каждом открытии задачи.

20 000 знаков ≈ лонг-пост из телеграма целиком; для транскрипта встречи есть база знаний.

## Что сделано

- `COMMENT_MAX` = 20 000 в `_shared/tasks/comments.ts` — один источник для веба и MCP.
- Отказ называет фактическую длину и предел, а не просто «слишком длинно».
- Веб (`miniapp/src/lib/taskComments.ts` + `components/tasks/TaskComments.tsx`): зеркало
  предела для отказа до отправки, счётчик остатка на последней тысяче знаков, поле ввода
  растёт под текст до 240px, длинные комментарии в ленте сворачиваются («Показать полностью»),
  причина отказа сервера показывается человеку.
