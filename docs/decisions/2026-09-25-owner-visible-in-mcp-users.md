# Владелец виден в MCP `get_users`; личность в MCP — только из токена

**Дата:** 2026-09-25 · **Задача:** #502

## Решение владельца (дословно)

> «я не вижу причин почему не показывать. я же также пользуюсь конкретно этим воркспейсом. в чем проблема?»

## Контекст

Агент в соседнем окне не смог оставить комментарий к задаче: схема `add_task_comment` требовала
`requesting_user_id` («Твой Telegram user ID — обязателен»), а владельца не было в `get_users`,
который исключал `ADMIN_USER_ID` с первого коммита MCP-сервера, без объяснения причины.

## Что решено

1. `get_users` показывает владельца наравне с остальными участниками воркспейса.
2. Личность вызывающего берётся только из токена. Поля личности убраны из `required` в `tools/list`,
   а в описании сказано, что их не передают (`swarm-mcp/identity.ts`).
3. Новый инструмент `whoami` показывает, от чьего имени работает коннектор.

Новый «внутренний ID» не заводится: у людей без Telegram уже есть синтетический отрицательный
`telegram_id` (выдаётся при Google-входе в `auth-resolve`). Переименование колонки — отдельный
вопрос, эту проблему оно не решает.
