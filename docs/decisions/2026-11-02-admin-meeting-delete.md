# Администратор может удалить любую встречу своего пространства

Решение владельца 02.11.2026:

> верни возможность удаления любой встречи для роли админа. это важно. есть очень чувствительные встречи

Администратору возвращается удаление групповых и чужих черновиков своего пространства.
Обычный сотрудник по-прежнему удаляет только собственный одиночный черновик;
групповую запись он может скрыть у себя. Удаление у всех требует отдельного подтверждения.
Проверка есть в интерфейсе вычитки, очереди, административном экране и на сервере.

Для DELETE опубликованной встречи администратор получает доступ и к личной записи
своего пространства. Это не расширяет чтение, редактирование, публикацию или смену
приватности. Другие пространства закрыты. Ошибка удаления БД не выдаётся за успех.

Текущая семантика сохранена: черновик физически удаляется из `meetings`, опубликованная
встреча архивируется через `archiveEntry` вместе с задачами. Архив сохраняет содержимое;
это не безвозвратное уничтожение данных. Владелец уточнил:

> нет, удалить всм из всех доступов. Пусть в архиве остается, вдруг пригодится

Безвозвратное удаление опубликованных встреч не добавляется. Исходная запись в `meetings`
наследует доступность связанной записи в `entries`: архив закрывает старые ссылки, пометки,
правку, публикацию, вопросы по расшифровке и обращения MCP к исходнику. В списке
опубликованных исходников архив отсекается до пагинации. `meetingEntryIsLive` проверяет
живую запись того же пространства и закрывает доступ при ошибке проверки. После
восстановления записи связанный исходник снова доступен по прежним правам.

Подготовка в рабочей ветке, без удаления пользовательских встреч и без продовой раскатки.
