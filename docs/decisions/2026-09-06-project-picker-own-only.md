# Выбор проекта в карточке задачи — только свои проекты и подпроекты

**Дата:** 2026-09-06 · **Статус:** принято, действует · **Решение владельца, не техническая деталь**

> ⛔ **Не менять без явного решения владельца.** Сужает — только для витрины выбора — правило
> [2026-08-24 «Доска проектов — общее пространство»](2026-08-24-subproject-visibility.md), которое
> само переписывалось трижды. Читать оба файла вместе.

## Повод

Владелец открыл карточку задачи и увидел в списке «Проект» плоскую простыню: подпроекты вперемешку
с группами, названия по фамилиям сотрудников, порядок по времени создания.

> «чет тут хуйня какая-то. при настрйоке задачи и проекта я должен видеть только СВОИ проекты и
> подпроекты. а сейчас чето в кучу видно все подряд, включая кажется задачи»

> «а еще в контекстном меню по хорошему разделить бы: сначала показывать проекты, потом подпроекты.
> так будет чуть проще»

Проверено на проде в тот же день: **задач в списке не было** — все 48 строк это `projects`. Ощущение
«видны задачи» давали подпроекты группы «IMF & HQ IT», названные по фамилиям («Дмитрий Карпов»,
«Юля Емельянова»). Реальных дефектов было два: состав (48 строк трёх авторов) и вид (ни иерархии,
ни сортировки; «Маркетинг» существует дважды — под «Испанией» и под «Черногорией», выбрать нужный
из плоского списка невозможно в принципе). Разбор — issue [#260](https://github.com/GarroV/Swarm-brain/issues/260).

## Решение

Витрина выбора проекта в карточке задачи показывает **только свои** проекты и подпроекты, **двумя
секциями**: сначала «Проекты», затем «Подпроекты» с подписью группы.

| Строка | В списке |
|---|---|
| Я её автор | да |
| Подпроект в моей группе, автор — коллега | да (сосед по моей ветке) |
| Строка без автора (`created_by=null`, легаси/бот) | да — иначе она стала бы недостижимой |
| Чужой проект/подпроект | нет |
| Чужой проект, к которому задача **уже привязана** | да, и первым в своей секции |
| Личность зрителя ещё не пришла | показываем всё |

Две последние строки — не поблажки, а защита от молчаливых потерь:

- уберёшь уже привязанный чужой проект — подпись в карточке схлопнется в «—», и первый же автосейв
  оторвёт задачу от проекта, ничего не спросив;
- пустой список при неизвестном зрителе означал бы «не к чему привязать задачу», а `fetchMe` может и
  упасть. Отбор по автору здесь — **удобство выбора, а не замок**: доступ стережёт `canViewProject`
  на сервере, и он не изменился.

## Границы решения

**Доска проектов (`SprintBoard`) осталась общей.** Владелец говорил про «настройку задачи», и правило
2026-08-24 («проекты и подпроекты это общее пространство для всех») продолжает действовать для доски,
мобильных экранов проектов и API `GET /projects`. Сузилась ровно одна поверхность — выпадающий список
в карточке задачи. Если понадобится сузить и доску — это отдельное решение, отдельный файл.

## Что это значит для кода

- Состав и порядок считает чистая функция `buildProjectOptions` в `miniapp/src/lib/projectPicker.ts`
  (10 тестов в `projectPicker.test.ts`, включая «чужой привязанный не пропадает» и «два Маркетинга
  различимы»). `TaskModal.tsx` только рисует то, что она вернула.
- `TaskModal` тянет `fetchProjects()` и `fetchMe()` **одним `Promise.all`** и ставит состояние вместе:
  раздельные `setState` дали бы кадр, где список ещё полон чужими проектами.
- Подпись подпроекта — «Группа › Имя»: без неё одноимённые строки неразличимы.
- Сортировка внутри секции — по алфавиту (`localeCompare("ru")`), а не по `created_at`.
- Моки `DEV_MODE` (`api.ts`) получили реалистичный `created_by` (свои + коллега + ничейная строка) —
  иначе локальный прогон не проверял отбор вовсе.
