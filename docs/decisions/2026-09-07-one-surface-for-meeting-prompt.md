# Предложение записать — одна поверхность: капсула

**Дата:** 2026-09-07 · **Статус:** принято · **Решение владельца, не техническая деталь**

> ⛔ Не менять без явного решения владельца. Пересматривает часть решения
> [2026-09-02](2026-09-02-pill-and-join-button.md) («две поверхности сразу»). Закрывает
> [#263](https://github.com/GarroV/Swarm-brain/issues/263).

## Повод

Владелец прислал скриншот капсулы на идущей встрече, дословно:

> «у меня зачем-то два уведомления от рекордера. одно черное, второе просто как обычное. чето тут
> не правильно помоему. при этом уведомление про звонок висит в ожидании действия»

## Решение

**Штатный баннер macOS для предложения записать — убрать. Остаётся только наша капсула.**

Владелец выбрал из трёх вариантов («убрать штатный баннер» / «оставить обе, но снимать штатный,
когда капсула на экране» / «оставить как есть, чинить только зависание») первый, зная минус:
если капсулу закрыли, системного напоминания об этой встрече больше не будет.

## Почему решение 02.09.2026 пересмотрено, а не нарушено

Тогда две поверхности были вынужденной конструкцией: `UNMutableNotificationContent` не даёт своей
вёрстки, поэтому «текст и кнопки — в штатном баннере, а вид — в нашей капсуле». С тех пор капсула
получила собственные «Подключиться» / «Записать» / ✕ и время слота — то есть **всё**, ради чего
держали штатный баннер. Он перестал добавлять что-либо и остался чистым дублем.

Цели решения 02.09.2026 (кнопка перехода в звонок, лаконичность, время слота) остаются в силе —
их несёт капсула.

## Границы

Убирается **только предложение записать** — встреча (`notifyMeeting`) и запасной детект звонка по
микрофону (`postCallNotification`). Информационные уведомления рекордера остаются штатными
баннерами, у них нет второй поверхности и заменить их нечем:

| Остаётся | О чём |
|---|---|
| `meeting-uploaded` | отправлено, тезисы придут в Telegram |
| `callend-*` | звонок завершён, сохраняю |
| `google-reconnect` | нужен новый токен Google |
| `sysstall-*` | системный звук не пишется |
| `deferred-*` / `recovered-*` | запись отложена / подобрана после сбоя |

Из-за этого разрешение на уведомления и предупреждение об отказе (#155) сохраняются полностью.

## Следствия

- **Звук ушёл вместе с баннером** — привлекал внимание `sound = .default` у уведомления, теперь
  предложение появляется молча. Своего звука капсуле НЕ добавляли осознанно: `NSSound` не знает
  про режим «Не беспокоить» (публичного API состояния Фокуса нет), то есть звучал бы и там, где
  система его глушила. Если тишина окажется неудобной — отдельная развилка владельца.
- Категории и кнопки уведомлений (`MEETING_START`, `MEETING_START_JOIN`, `RECORD`, `JOIN`) больше
  не нужны и удалены вместе с обработчиком действий.
- Побочно закрыт живой баг: обработчик `didReceive` стартовал запись по клику **любого**
  уведомления приложения (`UNNotificationDefaultActionIdentifier`) — в том числе «нужен новый
  токен» и «звонок завершён». Теперь клик по информационному уведомлению ничего не запускает.
