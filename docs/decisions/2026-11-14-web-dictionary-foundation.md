# 2026-11-14 — Первый словарный слой веба (#1025)

Техническая реализация первого этапа [#1025](https://github.com/GarroV/Swarm-brain/issues/1025),
по [решению владельца 19 октября](2026-10-19-search-and-2fa-deadline.md#3-третий-язык--не-сейчас):
«Запланируй значит эту работу. будем потихоньку делать».

## Выбор реализации

`i18next` закреплён на `26.7.2` в npm и Deno lockfiles. Один синхронный экземпляр работает
с ресурсами в памяти; `getFixedT` даёт отдельную функцию языка. Нет загрузчика словарей по
сети, определения языка браузером, middleware или новых маршрутов. Это сохраняет нынешний
Next static export для Cloudflare Pages. `next-intl` также умеет работать на клиенте;
выбран меньший независимый слой без изменения маршрутизации приложения.

Документация: [i18next API](https://www.i18next.com/overview/api),
[configuration](https://www.i18next.com/overview/configuration-options),
[next-intl client configuration](https://next-intl.dev/docs/usage/configuration).

## Контракт первого этапа

- `miniapp/src/lib/i18n/locales/*.json` — плоские ключи и строки. Генератор находит языки
  по файлам, проверяет одинаковые ключи, параметры и необходимые `Intl.PluralRules` формы.
  Повторяющиеся JSON-ключи, пустые строки и устаревший generated catalog — ошибка.
- `useT()` возвращает стабильную функцию. Ключи и параметры проверяет TypeScript;
  неизвестные ключи и неверные параметры также отвергаются во время исполнения.
  Интерполяция не интерпретирует значение пользователя как ключ или шаблон. Экранирование
  текстовых узлов остаётся за React; переводчик не предназначен для `innerHTML`.
- Точный язык, затем его базовая часть, затем EN — порядок выбора словаря. Нынешний
  `useLang()` продолжает выбирать RU для обычного пользователя и EN для демо. Серверный
  профиль, выбор третьего языка в продукте и язык содержания — последующие этапы.
- `useDt()` остаётся совместимым: прежний результат и стабильность функции сохраняются.
  Автозамена `i18n-migrate.mjs` переносит только статические пары; динамические строки и
  неоднозначные ссылки останавливают перенос до записи файлов.
- Пилот — только `NotificationSoundToggle`: две прежние подписи без изменения текста,
  HTML-классов, обработчика, хранения настройки и условия воспроизведения звука.

## Граница проверки в CI

`scripts/check-i18n.mjs` включён в общий `scripts/check`, включая `fast`. Он проверяет
словари, generated catalog, зарегистрированные перенесённые разделы и новые TSX-компоненты.
В них прямой JSX-текст, строковые текстовые атрибуты, статические строки через локальные
переменные/объекты и неизвестные или динамические ключи отклоняются. Технические атрибуты
и пользовательские данные не переводятся автоматически.

`i18n-legacy-sections.json` фиксирует существующие компоненты для постепенного переноса;
`i18n-migrated.json` не даёт перенесённому разделу незаметно вернуться на `useDt`.
Старый сторож русских JSX-строк продолжает проверять прежние области. Проверка не является
анализом всех путей строк через импортированные пользовательские функции: добавляя новые
текстовые API компонентов, нужно расширять перечень текстовых атрибутов и тесты гейта.
Весь старый веб и остальные шесть этапов #1025 этим изменением не объявляются перенесёнными.

## Перенос следующего раздела

Из `miniapp/` выполнить, сначала без `--write`:

```sh
node scripts/i18n-migrate.mjs src/components/Section.tsx section.title section.description
node scripts/i18n-migrate.mjs src/components/Section.tsx section.title section.description --write
npm run i18n:check
```

Ключи перечисляются в порядке статических вызовов `dt(ru, en)`. Добавить файл раздела
в `scripts/i18n-migrated.json` и убрать из legacy-списка. Проверить точность RU/EN и
поведение экрана. Для нового языка добавить полный JSON-словарь, запустить
`npm run i18n:generate` (его также вызывает сборка) и включить generated catalog в PR.
Провайдеры и маршруты для обнаружения файла не правятся; доступность нового языка
пользователю зависит от отдельного этапа языка в профиле.
