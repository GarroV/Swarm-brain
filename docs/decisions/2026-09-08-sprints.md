# Спринты: отдельное пространство поверх тех же задач

**Дата:** 2026-09-08
**Статус:** принято владельцем в разговоре, реализация впереди

## Решение

Спринты — **новая вкладка рядом с «Задачи» и «Проекты»**, а не переделка доски проектов.
Это функция планирования по времени: чёткое начало и конец, заморозка в конце и снимок
состояния на момент заморозки.

Дословно (владелец, 08.09.2026):

> «Я тебе говорю, нужны спринты. Всё, это просто функция, которая с чётким временем,
> началом и концом, и заморозкой, и соответственно снимком на момент собственно заморозки.»

> «Вкладка спринтов — это принципиально новый space для работы именно со спринтами, где те же
> самые задачи, по сути это просто очень большой глобальный фильтр для работы над задачами и
> планирования по времени, потому что в самих задачах, в разделе задач, мы это не можем сделать.
> В разделе проектов мы тоже не совсем можем это сделать, потому что мелкие задачи в духе
> „переслать отчёт“ явно в спринт нет смысла брать. То есть туда будут уходить только самые
> важные ключевые задачи по конкретным узким направлениям.»

## Что решено по частям

| Вопрос | Решение владельца |
|---|---|
| Доска проектов | **Не трогаем.** Колонка «Бэклог» остаётся как есть: «я бы вот не трогал то, что есть» |
| Слово «бэклог» в спринте | Заменяем на **«Задачи»**: «в спринтах давай просто backlog заменим на слово задачи… рядом будет канбан стандартный» |
| Статус `backlog`, спрятанный из списка задач | Оставляем спрятанным: «список задач стоит так, список задач — какой там может быть бэклог» |
| Кому принадлежит спринт (проекту / команде) | **Вопрос снят как пустой:** «какая разница, кому они принадлежат? Мы создаём проект, мы создаём спринт, и по этому спринту работаем» |
| Задачи разных людей в одном спринте | Нормально и ожидаемо: «они будут в одном пространстве… я не вижу проблемы» |
| Вкладки на доске проектов (в коде — таблица `sprints`) | Это **проекты, а не спринты**. Имя в коде — недоработка: «это нужно будет обязательно потом когда-нибудь пофиксить, чтобы код привести в порядок, но это не горит» |
| Что берём в спринт | Только ключевые задачи узкого направления; мелочь вроде «переслать отчёт» — нет |

## Аналитика, которая требуется

Владелец назвал явно:

- сколько задач выполнено в спринте и кем;
- когда задачи завершены;
- сколько спринтов задача заняла (если переносилась);
- по человеку: сколько задач создал, сколько закрыл, сколько времени над ними работали;
- общий результат спринта, зафиксированный в момент заморозки.

## Почему не иначе

Разбирали три альтернативы, все отклонены:

- **Вернуть смысл таблице `sprints`** (переименовать вкладки) — миграция живых данных ради
  красоты имён, польза нулевая для пользователя. Отложено, не горит.
- **Спринт как поле у задачи** — задача, прожившая три спринта, оставит след только в последнем;
  теряется история переносов, которую владелец назвал среди нужной аналитики.
- **Спринт как режим доски проектов** — смешивает постоянную работу (проект живёт годами) с
  временным окном; владелец прямо просил отдельное пространство.
