# Отчёты по сотрудникам через MCP

Решение владельца от 27.11.2026: предоставить внутренний MCP-инструмент отчётности
только администраторам; управленческие отчёты не размещать в общей базе команды.

- `get_employee_report` формирует отчёт по одному сотруднику или всем текущим
  участникам своего пространства за выбранный период. Ответ доступен запросившему
  администратору в его MCP-клиенте; Swarm его автоматически не сохраняет и не рассылает.
- Доступ определяется существующими ролями админа и мастер-админа, с обязательным
  членством в текущем пространстве. Новый список руководителей не вводится.
- Существующая сводная статистика `get_task_stats` получает ту же проверку роли.
- Права на исходные задачи, закрытые проекты, личные встречи и заметки сохраняются.
  Админская роль отчёта не даёт обхода приватности других сущностей.
- Распознаваемые управленческие отчёты при явном сохранении через MCP всегда личные.
  Доступ к сохранённому отчёту определяется его автором и явным `shared_with`,
  а не ролью администратора.

Расчёты и их ограничения описаны в `ARCHITECTURE.md`. Изменения продукта готовятся
к отдельному выпуску по действующим правилам раскатки.
