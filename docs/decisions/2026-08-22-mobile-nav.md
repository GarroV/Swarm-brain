# ADR: Мобильная навигация — четыре таба и приоритет задач

**Дата:** 2026-08-22
**Статус:** Принято, реализуется
**Ветка:** `feat/mobile-nav`

---

## Контекст

Владелец: «в мобильной версии при скроллинге задач постоянно срабатывает открытие задачи… чтобы проскролить — приходится делать это на пустом пространстве слева от задач», далее — «проведи критический анализ интерфейса при мобилке, нужно лаконичное логичное меню».

Аудит на живом приложении (Chrome, touch-эмуляция 390×844) выявил, помимо самого бага:

- **Настройки / Команда / Админ / Карта системы доступны только с таба «Поиск»** — кнопка «Меню» есть в шапке одного экрана из четырёх (проверено: с «Задач», «Базы», «Встреч» входа нет).
- **Проектов на мобильном нет вообще** — `RoyTasksScreen` рендерит только список; «Проекты» (доска спринта) живут в десктопной `TasksScreen` за порогом 1024px.
- Заголовок экрана дублирует активный таб (h1 «Задачи» при подсвеченном табе «Задачи») — ~60px на каждом экране.
- Экран задач: 199px управления до первой строки (линза + «По рынкам» + «Все сотрудники» + чипы) + 69px таб-бар; под список 68% экрана.
- Тач-цели ниже нормы 44px: чекбокс задачи **19×19**, чипы линзы 27px, кнопки встреч 32–36px.
- Действия строки в двух логиках: у встреч карандаш/корзина всегда на виду, у задач те же действия — в свайпе.
- Задача, созданная без срока, возвращает в «Сегодня», где её нет (проверено: «Все» 13→14, в «Сегодня» не видна).

---

## Решения владельца (2026-08-22)

**Приоритет на телефоне — дословно:** «Задачи: смотреть и закрывать, Задачи первоочередное, проекты, поиск».
Следствие: дом мобильного приложения — задачи, а не «Поиск».

**Набор табов — дословно:** «задачи, проекты, встречи, еще».
Поиск перестаёт быть табом (становится 🔍 в шапке каждого корневого экрана); «База», «Команда», «Настройки», «Админ», «Карта системы», «Фидбек» уходят в «Ещё».

**Вид проектов на телефоне:** список проектов → задачи внутри проекта (теми же строками со свайпом).
Канбан со свайпом по колонкам отклонён: горизонтальный свайп колонок конфликтует со свайпом строки.

**Встречи — дословно:** «во встречах не забудь проконтролировать чтобы были кнопки для правки названия и тезисов, а также выбор куда сохранять (в какую базу)».
Проверено: на `MeetingDetail` это уже есть — `ActionChip` «Название», «Тезисы», «Страны», «Удалить» + `Segmented` «Общее/Личное» и кнопка «Сохранить в базу»/«Сохранить в личное». Требование — сохранить эти органы управления при редизайне, не добавлять новые.

**Выбор хранилища у УЖЕ СОГЛАСОВАННОЙ встречи — НЕ возвращать.** Решение от 2026-08-21 (коммит `0f1d55b`: «решение по ней уже принято», вместо органов управления — бейдж «Согласована · Общее|Личное») остаётся в силе.

**Про поиск — дословно:** «у нас поиск в вебе один, откуда ты второй выдумал?»
Владелец прав по существу: поля на доме и в «Базе» оба зовут `openAnswer` и ведут в один экран ответа. Расходятся только плейсхолдеры («Спросить или найти…» / «Семантический поиск по базе») — это читается как две функции. Решение: **формулировка одна во всех точках входа**, канонический вход — 🔍 в шапке.

## Что меняется в коде

| Область | Было | Станет |
|---|---|---|
| `RoyTab` | `search` \| `task` \| `book` \| `cal` | `task` \| `projects` \| `cal` \| `more` |
| Дом мобильного | `search` (SearchScreen) | `task` (список задач) |
| Поиск | таб «Поиск» | 🔍 в шапке любого корневого экрана → тот же `openAnswer`/`AnswerScreen` |
| «База» (`RoyBaseScreen`) | таб | пункт «Ещё» (экран не переписывается) |
| «Ещё» | push-роут `more`, доступен только из шапки «Поиска» | корневой таб: профиль/выход · База · Команда · Настройки · Админ · Карта · Фидбек |
| Проекты | недоступны | новый экран: список проектов → задачи проекта |
| Шапка | h1, дублирующий таб | `[аватар] Раздел [🔍]` — аватар ведёт в «Ещё» с любого экрана |
| Фильтры задач | 3 яруса (линза + 2 тумблера + чипы) | 1 строка: чип-меню «Мои ▾» (линза + «По рынкам» + «Все сотрудники») + чипы смарт-списков с маской обрезки |
| Строка встречи | постоянные карандаш/корзина | свайп, как у задач |
| Чекбокс задачи | тач-цель 19×19 | 44×44 (круг визуально тот же) |
| После создания задачи | остаёшься в фильтре, где её не видно | список переключается на тот, где задача видна |

Тексты новых поверхностей закладываются сразу EN+RU (правило проекта №6). Проверка каждого шага — puppeteer-смоук с touch-эмуляцией (CI заморожен до 01.09, гоняется локально).
