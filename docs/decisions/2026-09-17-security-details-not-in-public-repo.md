# Детали уязвимостей не попадают в публичный репозиторий

**Дата:** 2026-09-17
**Статус:** принято

## Повод

`docs/security-hardening-progress.md` — внутренний трекер security-работ с перечнем незакрытых дыр живого продукта — лежал в запушенной ветке `feat/security-storage-fix` и читался анонимно. Проверено `curl` без токена: HTTP 200 (контрольный несуществующий файл — 404). Создан 05.09, обнаружен 17.09 — около 12 дней публично.

В файле были рабочие детали: предсказуемые пути в публичном бакете, факт анонимного скачивания внутреннего документа, состояние вебхука бота, отсутствие rate-limiting, порядок раскатки фикса.

Глобальное правило про приватные advisory существовало и раньше, но покрывало issues — не файлы в ветках. Ветки публичного репозитория видны всем так же, как `main`.

## Формулировка владельца (дословно)

> «реши проблему с публичным трекером и проведи работу чтобы не допускать таког ов будущем.
> Сноси ветку, но не забывай что нельзя сейчас никак навредить пользователям»

## Решение

1. Ветка `feat/security-storage-fix` снесена с origin. Работа не потеряна: локальная ветка цела, плюс проверенная копия `git bundle` в `~/Documents/workbench/private/`. Пользователи не затронуты — CI слушает только `main`, PR с ветки не было, прод не раскатывался.
2. Подробный трекер удалён из репозитория; копия живёт вне git. Статус работ ведётся в issue #284 нейтральными строками, детали — в приватных advisory.
3. Защита механическая, а не только правило: `.githooks/pre-push` блокирует пуш внутренних security-материалов (проверен тремя тестами — рискованное имя, маркер внутри файла, обычная правка проходит).

## Что осталось известным риском

Объекты удалённой ветки ещё достижимы по SHA коммита (404 по имени, 200 по SHA) — GitHub держит их до сборки мусора. Полная очистка возможна только через поддержку GitHub; решение по этому — за владельцем.
