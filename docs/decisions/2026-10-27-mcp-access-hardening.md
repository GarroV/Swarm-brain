# 27.10.2026 — доступ MCP: токен на 30 дней, отзыв триггером, два шага для опасного, журнал

Issue #1083 (+ журнал из #1082). Стандарт — скилл `mcp-server`, разделы «Доступ и личность» и «Защита»;
образец — DECIMUS (`src/mcp/confirm.py`, журнал вызовов).

## Что решено

1. **Токен живёт 30 дней.** Выпуск пишет `expires_at = now() + 30 дней` (`_shared/mcp-token.ts`).
   Живые токены, выпущенные бессрочными, миграция `20261027120000` продлевает на 30 дней от раскатки —
   никого не отрезаем в ночь раскатки. `swarm-mcp` сверяет срок на каждый вызов и **строку без срока
   считает негодной** (fail-closed; `token-state.ts`).
2. **Протухший или отозванный токен не роняет хендшейк.** `initialize` отвечает, `tools/list` отдаёт
   пустой список, `tools/call` — отказ «открой веб → Настройки → Claude Desktop и выпусти новый». Подсказка
   не про `/mytoken`: бот ключи не выдаёт (#1061).
3. **Триггер БД гасит токен** при смене `group_id` или `is_admin` (хэш и срок обнуляются в той же
   транзакции; перевыпуск в том же UPDATE не гасится). Удаление из `allowed_users` убирает токен вместе
   со строкой. Флага «отключён» в таблице нет — отдельного случая нет. Явные REVOKE/GRANT на новые функции
   (урок GHSA-vxrp: по умолчанию EXECUTE у PUBLIC).
4. **Разрушающие инструменты — в два шага** (`confirm.ts`). Класс — `destructive` в `annotations.ts`.
   Первый вызов: `confirmation_required` + токен `<срок>.<HMAC-SHA256(секрет, автор, инструмент,
   канонические аргументы без токена, срок)>`, 5 минут. Второй вызов исполняется только с тем же
   автором, инструментом и аргументами. Секрет — `MCP_CONFIRM_SECRET`; **нет секрета — разрушающие
   инструменты отказывают**, а не работают без подтверждения.
5. **Журнал изменяющих вызовов** `mcp_tool_journal`: время, `telegram_id`, инструмент, итог
   (`ok`/`refused`/`error`), последние 6 символов хэша токена. Без аргументов и без токена. Только
   дописывается; RLS без политик.

## Честные пределы

- Токен подтверждения не доказывает, что человек прочёл ответ: клиент может повторить вызов сам. Он
  гарантирует, что действие идёт по точным аргументам из ответа и в пределах срока.
- Запрос совсем без токена по-прежнему получает ответ `tools/call` с отказом, а не HTTP 401 с
  `resource_metadata` (стандарт требует 401 для входа через сайт). Это отдельная работа вместе с OAuth-входом.
- «Роль» в триггере — `allowed_users.is_admin`; роль в `user_profiles.role` — должность, доступ не задаёт.
- Журнал не чистится (рост — строка на изменяющий вызов); первый шаг подтверждения в него не пишется.
- Исход `ok` значит «инструмент вернул ответ», а не «правка применилась»: часть инструментов сообщает
  о неудаче текстом.
- Тот же `smcp_`-токен принимают `agent-auth` (рекордер) и `market-ingest`; срок 30 дней действует и
  там (оба уже сверяют `expires_at`).

## Раскатка

Перед выкладкой задать секрет: `MCP_CONFIRM_SECRET` (случайные 32+ байта) в окружении Edge Functions.
Пока его нет, delete/archive/remove/accept/publish через MCP отказывают с понятным текстом.
