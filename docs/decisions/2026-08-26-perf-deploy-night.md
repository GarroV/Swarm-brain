# Ускорение веба раскатано в ночном окне

**Дата:** 2026-08-26 · **Статус:** выполнено · **Решение владельца, не техническая деталь**

## Повод

Владелец пожаловался, что веб очень долго грузится, и попросил профилировать. По итогам —
шесть коммитов в ветке `perf/lean-meetings-payload` (issues #102, #103, #107, #108).

В том же разговоре владелец сначала ограничил раскатку:

> «ебаш фиксы. ускоряй, но все мержи и апдейты только ночью»

Затем, после отчёта о готовности:

> «давай ебаш все, заливай пуш мержи»

## Решение

| Вопрос | Ответ |
|---|---|
| Раскатывать ли вне утреннего окна 09:00–10:00? | **Да** — но не обходом, а в ночном слоте: канон [2026-08-24-deploy-window.md](2026-08-24-deploy-window.md) прямо отводит ночь под рискованное. Раскатка шла в **23:19–23:30 по Белграду**, среда |
| Разрешение | Явное «да» владельца в этом же разговоре («заливай пуш мержи»), как требует канон |
| Почему ночь, а не утро | Меняется контракт `GET /meetings` + веб. У пользователей с ОТКРЫТОЙ старой вкладкой новый API отдаёт урезанный `content`, а старый код не знает про флаг `truncated` и показал бы 400 символов как полный транскрипт (issue #90 — нет сигнала «есть новая версия»). Ночью в Swarm никого нет, перезагрузка вкладки снимает проблему |
| Порядок | **Сначала веб, потом функция.** Обратный порядок как раз и дал бы старому коду урезанные ответы |

## Что уехало

`main` = `3afadbc` (fast-forward), метка `prod-deployed` передвинута туда же.

- **Веб** — Cloudflare Pages собрал сам с `main`; проверено по маркеру «Загружаем расшифровку…» в живом чанке.
- **`swarm-api` → v132 ACTIVE.** Других функций правки не касались.
- **Миграций нет.**

## Проверено фактически

- `deno task test` 341/0, `deno check`, `tsc --noEmit`, `next build` — на ребейзнутом коде.
- e2e в Chromium на собранном бандле: 9 API-запросов, 0 дублей, 0.81 МБ сырых против 20.4 МБ до.
- **Совместимость в обе стороны** прогнана отдельно: новый веб против СТАРОГО контракта API
  (состояние между двумя шагами раскатки) — транскрипт и извлечение задач работают, просто
  без ускорения. Ленивая до-загрузка не срабатывает, и это верно: старый API не присылает `truncated`.
- Прод после раскатки: `/meetings`, `/entries`, `/agent-meetings` → 401 (не 500), `make smoke-prod`
  зелёный, в `function_edge_logs` **ни одной 5xx**.
- Живой трафик подтвердил замер `/tasks`: 21.9 кБ gzip на 188 задачах.

## Что НЕ проверено

**Payload `GET /meetings` на живом авторизованном запросе.** В 23:30 приложением никто не
пользуется, а собственной прод-сессии у сессии Claude нет (`WEB_JWT_SECRET` отдаётся только
дайджестом). Падение 10.0 МБ → 452 кБ измерено SQL-запросом по прод-данным и e2e на собранном
бандле, но не снято с реального запроса. Подтверждается за секунды: владелец открывает
`swarm-brain.pages.dev` и смотрит вес `meetings` в DevTools — «до» у него уже зафиксировано
(4 893 кБ).

## Побочная находка

`scripts/deploy-window.sh` знает только утреннее окно 09:00–09:59 и про ночной слот из канона
не в курсе — в 23:19 он отказал и потребовал `FORCE=1`, хотя ночь правилами разрешена.
Расхождение инструмента с каноном — issue #115.
