## Что в артефакте (разбор кода, не по памяти)

Модель данных — константа `DATA`, три уровня:
НАПРАВЛЕНИЕ → ИНИЦИАТИВА (`own`, `start`, `end`) → ЗАДАЧА (`t`, `own`, `s`, `e`, `s1`, `id`).

Поверх — слой состояния `st` в артефактовом хранилище Claude (`window.storage`, общее
для всех зрителей): `edit` (правки), `added`/`deleted`, `sprintOf` (в каком спринте
задача), `status`, `check` (чекпоинт), `links`, `comments`, `reason` (причина переноса),
`unlock`, `log` (журнал), `sprints` (итерации со снапшотом строк).

Функции, которых у нас НЕТ:
- итерация со сроками: старт → контрольная точка (`check` = старт + 6 дней) → закрытие;
- **заморозка** спринта после старта (`frozen`), разморозка по коду (`UNLOCK`);
- **закрытие со снапшотом** (`closeSprint`): фиксирует строки как были, незакрытое
  переносит в следующий спринт с ОБЯЗАТЕЛЬНОЙ причиной;
- чек-ин середины спринта (`checkView`), аналитика (`anView`), журнал (`logView`),
  таймлайн (`timeline`), цвет по владельцу (`ownColor`), фильтр «мои», просроченность.

## Решения владельца 18.09.2026 (дословно, где дословно)

1. **Задачи — те же самые, что в «Задачах» и «Проектах»** (вариант «Те же задачи (tasks)»).
   Инициатива = проект/подпроект, задача = обычная `tasks`-строка. Второй правды не заводим.
2. **Переделываем вкладку «Спринты»**: внутри неё — список больших кросс-командных
   проектов («Качество в Европе» и т.д.), у каждого своя доска инициатив с итерациями.
   Нынешние вкладки-«спринты» (которые на деле просто вкладки доски) становятся чем-то
   другим или уходят — решить отдельно.
3. **Порядок работ:** «делаем рабочий интерфейс на основе артефакта. задачи заливаем да,
   но! у многих эти же задачи уже могут быть в сворме, значит их надо как-то сконнектить.
   это нужно будет прям очень аккуратно провести, я думаю что это проблема уже после
   реализации самого интерфейса». То есть: **сначала интерфейс, импорт и склейка
   дублей — отдельным этапом после.**
4. Граница смысла, заданная владельцем: «Проекты» = канбан для упорядочивания задач;
   доска инициатив = большая проектная работа, где те же задачи трекаются по спринтам.

## Заход 6 — развилки исследования (18.09.2026)

Спрошено после исследования (отчёт — `docs/furca/research-report.md`), ответы владельца на четыре
развилки. Во всех четырёх выбрана рекомендация.

1. **Отменённая задача в итогах спринта** — «Отдельной цифрой, мимо процента». Не входит ни в
   «сделано», ни в знаменатель; в итогах появляется своя цифра «отменено». Меняет поведение
   нынешнего отчёта #267, где отмена задачи повышала процент выполнения.
2. **Причина при автоматическом переносе** — «Предложить, но не требовать». В окне приёмки виден
   список уезжающих автоматически, у каждого необязательное поле причины; не заполнил — уезжает
   как раньше.
3. **Сколько раз задача переносилась** — «Показывать „×3“ в строке». Плюс колонка в таблице причин
   переносов. В артефакте этого нет — сознательная добавка.
4. **Кто не отметился на сверке** — «Показывать „не отмечено“». Начиная с дня сверки неотмеченные
   задачи получают серую пометку, число стоит в баннере и у каждого человека.
