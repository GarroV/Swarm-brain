# Серверные копии записей разбирает система, а не человек

Дата: 12.11.2026. Продолжает [2026-10-27-all-recordings-uploaded.md](2026-10-27-all-recordings-uploaded.md). Задача: #1314.

## Слова владельца

> «Я не хочу отлавливать каждую косячную запись… Хочется максимально сразу обыграть все вот эти кривые, косые моменты».

## Решение

1. Копия (`meeting_audio_backups`) не вычищается по сроку, пока не разобрана (`resolved_at`).
2. Разбор делает `meeting-process` каждым тиком по дешёвым признакам (держатель права, источник, длительность, время, статус), без распознавания: `covered` (встреча получила полную запись того же человека), `covered_elsewhere` (тот же звук ушёл отдельной встречей), `ingested` (копия влита второй записью тем же путём, что вторая запись в `meeting-ingest`; стенограмма заменяется, только если копия полнее), `needs_review` (система не решила).
3. Копию другого человека (мог быть другой звонок) в чужую встречу не вливаем. ~~Она в `needs_review`~~ Дополнение 13.11.2026: такая копия становится ОТДЕЛЬНОЙ встречей этого человека (`manual:<id копии>`, название из встречи-источника + «отдельная запись / separate recording»), чужая встреча не меняется. Слова владельца 12.11.2026: «Я не хочу отлавливать каждую косячную запись… Записи, которые были на одной встрече и на параллельной встрече, они должны быть самостоятельными, потому что это разные встречи». Условия (проверка безопасности 13.11.2026): причина копии `deferred` (отказ по праву не обходится), допуск загрузившего проверяется заново (`mayRecordNow`), на пару (встреча-источник, источник) не больше одной своей встречи (следующие копии вливаются в неё). В `needs_review` остаются копии без файлов, без пространства, те, чей источник уже принят встречей, и случаи того же человека (заморожена, нет держателя, не освободилась за 48 ч).
4. Сравнение «по содержанию» (транскрибировать и сопоставить тексты) не добавлено: дешёвых признаков хватило на оба реальных случая 09.11 и 11.11.2026; потолок расхода не понадобился.
