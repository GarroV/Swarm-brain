# Двухфакторный вход для всех — ключи доступа

**Дата:** 14.10.2026 · задача #955

**Решение владельца (дословно):** «Заложи- еще в сформе тоже дополнительно функционал привязки фингертив. То есть двухфакторку давай будем делать, по сути, для всех пользователей, вообще вне зависимости от роли.»

**Что закреплено:**
- Второй фактор при входе в веб — обязателен для всех, независимо от роли.
- Способ: ключ доступа (passkey / WebAuthn) — отпечаток, лицо, Windows Hello или аппаратный ключ. Библиотека — SimpleWebAuthn.
- Сброс ключей при потере устройства — админ пространства или мастер-админ, в управлении людьми (#233).
- Порядок — как у мастер-админки: строим рядом, обязательность включаем отдельным шагом; объявление людям — только по «да» владельца на текст.

## Уточнение владельца в тот же день — как в decimus

> Пожалуйста, не еби мозги и сделай точно так же, как мы с тобой сделали для детсу. То есть, чтобы у человека просто при входе просило привязать палец. И все. Безополнительных кнопков, без дополнительного меню, всего остального. Понятное дело, что в настройках можем добавить, и аутентификатор, тут херню. Ну, короче, состыкуйся с детсумсом.

Образец — decimus, решения D484/D485 (`GarroV/decimus` `docs/furca/decisions.md`). Отменяет «полная сессия только после подтверждения ключом» и «экран привязки» выше.
- **Палец сохраняется сам.** После входа через Telegram или Google первая загрузка страницы в браузере без сохранённого ключа сама открывает окно Touch ID и создаёт ключ доступа (платформенный, имя вида «Chrome · Mac»). Без кнопки и без вопроса. Если браузер не дал открыть окно без жеста или человек закрыл его — одна строка «Включить вход по Touch ID в этом браузере»; отказ помнится до следующего входа.
- **Вход пальцем.** На странице входа браузер, где ключ уже есть (метка в localStorage), сам просит Touch ID, ключ находится без логина, и человек входит. Без метки — страница входа как сейчас, кнопка «Войти по Touch ID» запасная. QR-кода нет: окно само не открывается там, где ключа нет.
- **Для всех пользователей**, без исключений по роли. Демо-вход вне этого.
- **В настройках** — запасной способ: приложение-аутентификатор и резервные коды. Ключи доступа отдельным списком не ведём.
- **Уборка:** ключ, которым не входили 30 дней, снимается сам. Ручной сброс входа у человека — у админа пространства и мастер-админа.

## Поправка владельца в тот же день — «всегда входит гугл сначала»

> всегда входит гугл сначала

Отменяет «вход пальцем без логина» выше (пункт «Вход пальцем» и кнопку «Войти по Touch ID» на странице входа) и уточняет «палец сохраняется сам». Реализация части 1 (#955):
- **Страница входа не меняется:** никакого авто-`navigator.credentials.get` на `/login` и кнопки «Войти по Touch ID» там. Первый шаг всегда Google (Telegram не трогаем, но и ему тот же второй шаг).
- **Сразу после возврата из Google, на первой загрузке приложения:** само открывается окно Touch ID. Режим — по ключам человека (см. следующую поправку): нет ключей — сохраняется палец (`create`), есть — подтверждение (`get`). Без кнопок.
- **Сессия «без второго шага»:** метка `sf` в JWT, `GET /me → second_step`. В части 1 работу без шага НЕ блокируем; замок обязательности — env `SECOND_STEP_REQUIRED` в swarm-api, по умолчанию выключен, включается отдельным шагом.
- Устройство — [ARCHITECTURE §Аутентификация п.4](../ARCHITECTURE.md#swarm-api--бэкенд-веб-интерфейса).

## Уточнение владельца: в новом браузере палец без проверки не сохраняем

Владелец на объяснение «в новом браузере палец без проверки не сохраняем»: «ну это вроде и логично же».
- Авто-сохранение пальца после Google — **только если у человека ещё нет ни одного ключа** (самый первый вход). После сброса входа админом ключей нет — снова «первый вход».
- Ключи есть, в этом браузере метки нет: сначала САМ вызывается `get` с его ключами (синхронизированный iCloud-ключ подтянется — человек прикладывает палец). Не вышло — новый ключ **не создаём**; сервер отказывает в регистрации нового ключа тому, у кого ключи уже есть. Сессия остаётся «без второго шага», строка: «Подтвердите вход кодом из приложения-аутентификатора или попросите админа пространства сбросить вход» (EN: «Confirm sign-in with your authenticator app code, or ask your workspace admin to reset sign-in»).
- Приложение-аутентификатор (TOTP) в первой части не делаем — строка пока ведёт к сбросу админом; код из приложения — вторая часть. Обязательность — за выключателем `SECOND_STEP_REQUIRED`, по умолчанию выключен.
