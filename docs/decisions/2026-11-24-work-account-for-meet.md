# Рабочий аккаунт для входа в созвоны

Дата: 24.11.2026.

Для каждого сотрудника в Swarm используется только его рабочая почта для созвонов.
Выбор между личным и рабочим аккаунтами в продукте не требуется.

Из веба ссылка открывается в новой вкладке того же браузера. Из рекордера — в системном
браузере по умолчанию: Safari, Dia, Chrome или другом. Решение не должно требовать
конкретного браузера или изменения браузера по умолчанию.

Целевой сценарий: в одном профиле браузера могут одновременно использоваться рабочий
и личные Google-аккаунты. Переход из Swarm должен явно направлять Meet на известную
рабочую почту сотрудника. Перебор аккаунтов и выбор по их порядку не требуются.
Если рабочая сессия истекла или отсутствует, повторную авторизацию выполняет Google;
после неё пользователь продолжает вход в исходную встречу. Автоматическая подстановка
личного аккаунта вместо рабочего не соответствует требованию.

При проектировании открытия Meet необходимо отдельно учитывать аккаунт Google внутри
текущего профиля браузера и отдельные профили Chrome. Нельзя предполагать, что указание
рабочей почты в ссылке автоматически откроет другой профиль браузера.

Реализация: сервер берёт `allowed_users.email` авторизованного сотрудника и добавляет
для человека отдельное `open_url`: `https://accounts.google.com/AccountChooser` с
регистрозависимым `Email` и `continue`, содержащим исходную встречу. Это механизм,
используемый [Google Site Kit](https://github.com/google/site-kit-wp/issues/5453).
Параметры выбора чужого аккаунта `authuser`/`login_hint` из исходной ссылки удаляются.
Адрес комнаты `join_url` остаётся исходным для идентичности встречи и пропуска бота.

Потребители: обе версии списка встреч в вебе, уведомление/выбор встречи рекордера и
его доска. Поле добавляется в ответы человеку `meeting-current`, `calendar/today` и
`board/today`; календарный пропуск бота получает прежнюю ссылку. Для других площадок
ссылка не меняется. Отсутствие рабочей почты даёт `open_url: null`: нового входа в Meet
нет, запись и приглашение бота остаются отдельными действиями. Старый сервер без поля
поддерживается до выпуска функций; старое поведение в таком случае сохраняется.

Проверка рекордера без записи и сети: `SwarmRecorder --selftest-meet-link`.
