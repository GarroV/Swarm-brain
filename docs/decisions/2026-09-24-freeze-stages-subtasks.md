# 2026-09-24 — Заморозка, этапы спринта, подзадачи

Решения владельца, сказанные по ходу переноса спринтов на витрину (`feat/new-ui`). Беклог: #475, #477.

## Заморозка — для задач и проектов, не для спринтов
Дословно: «заморозку давай потом обсудим. она нужна будет по сути для задач и проектов, но не спринтов.
Заморозка по сути убирает задачу или проект в отдельный список, и не участвует в статистике нигде.
заморозить может любой участник».

- Заморозка спринта из стенда (`frozenNote`, «Разморозить») — **не делаем**.
- Заморозка задачи/проекта: уходит в отдельный список, исключается из ВСЕЙ статистики (счётчики, аналитика
  спринтов, дашборд). Заморозить может любой участник. Детали — отдельное обсуждение («давай потом обсудим»).

## Этапы спринта — три
Дословно: «в спринтах у нас есть этап где мы планируем задачи, потом чекпоинт, где к этой дате все должны
отписаться комментарии со статусом по задачам и потом уже финал, когда идет по сути приемка задач. ну то есть
созвон и обсуждение».

1. **Планирование** — набор задач в спринт (от `start_date`).
2. **Чекпоинт** — к дате (`check_date`) каждый отписывается комментарием со статусом по своим задачам.
3. **Финал** — приёмка задач: созвон и обсуждение (`end_date`, «Принять спринт»).

Полоса этапов стенда (5 шагов с заморозкой) заменяется этими тремя. `check_date` форма создания пока не заполняет.

## Подзадачи — ещё один уровень под задачей
Дословно: «для задач в спринтах нужен еще один уровень вложенности. Т.е. у нас есть "Инициативы качества" как
проект, внутри есть собственно инициативы, т.е. глобальные задачи, внутри этих задач у нас есть наши обычные
задачи, и вот для обычных задач нужны еще подзадачи… у задач важно проработать функционал привязки
родительская-дочерняя задачи».

Уровни: проект («Инициативы качества») → подпроект-инициатива → задача → **подзадача**. Проекты и подпроекты уже
есть (`projects.parent_id`). У задач колонка `tasks.parent_id` в базе уже есть (миграция `20260806120000_project_tree.sql`,
от выключенного дерева проектов), интерфейса привязки родитель↔дочерняя нет. Уточнение: в прототипе (стенд)
вложенность сделана для проектов (направление → инициатива), подзадач у задач там нет.

### Дополнение того же дня — подзадачи в спринте и закрытие родителя
Дословно: «по сути в спринте мы и будем подзадачами оперировать. если задача закрывается, то подзадачи тоже
логично закрыть, но надо уведомить».

- Рабочая единица спринта — **подзадача**: её берут в состав, сверяют на чекпоинте и принимают на финале.
- Закрыли родительскую задачу → её подзадачи закрываются тоже, **с уведомлением**. Кого именно уведомлять
  (того, кто закрывает, — предупреждением перед закрытием; исполнителей подзадач — пушем; или обоих) — уточнить.
- Уточнение того же дня, дословно: «если в спринте закрываем, то надо просто зачеркивать, соответственно в спринте
  будет видно что задача решена. допом уведомлений пока не надо». → Закрытые подзадачи в составе спринта
  остаются видны зачёркнутыми; уведомлений о каскадном закрытии не делаем. Порядок работ: «давай сразу подзадачи,
  пока далеко не ушли» — #478 раньше #476.
