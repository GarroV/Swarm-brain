# Подписка по комментарию: админ получает уведомления и по личным задачам

**Дата:** 2026-08-24 · **Статус:** принято, действует · **Решение владельца, не техническая деталь**

> ⛔ Не менять без явного решения владельца. Здесь снята защита, которая выглядит как утечка приватности — если код кажется дырой, читать этот файл, потом спрашивать, и только потом трогать.

## Развилка

Владелец попросил подписку по участию: «написал комментарий — как бы подписался», плюс кнопку отписаться в той же карточке ([#82](https://github.com/GarroV/Swarm-brain/issues/82)).

Возражение, которое пришло из кода: `commentRecipients` (`_shared/tasks/notify.ts`) намеренно зовёт гард с `isAdmin=false`. То есть админ, у которого **есть** оверсайт над задачами сотрудников (решение [2026-08-21](2026-08-21-admin-visibility.md)) и который **может** прокомментировать чужую личную задачу, в поток уведомлений о ней не попадает. Авто-подписка это отменила бы как побочный эффект комментария.

## Решение владельца (дословно, 2026-08-24)

> «админу нужна обратная связь. он видит 4-5 челвоек, и не может физически бегать и каждую карточку читать. т.е. подписка она для админа, а значит он и так уже видит все»

Читается так: подписка задумана **ради** админа. Оверсайт уже даёт ему доступ к этим задачам, поэтому уведомление не открывает ничего нового — оно лишь избавляет от ручного обхода карточек. Возражение снято.

## Что это значит в коде

- Подписчик (явная строка подписки) проходит проверку видимости **с учётом его оверсайта**: `canViewTask(task, id, isAdmin)`. Подписка возникает только из комментария, а комментарий требует доступа — значит доступ у подписчика уже был.
- Причастные по умолчанию (исполнители / создатель / владелец) остаются как были — **без** оверсайта, `isAdmin=false`. Решение расширяет только подписки, а не общий круг.
- **Границы: это про ЗАДАЧИ.** Записи, встречи и проекты админского обхода не имеют (решения 2026-08-07 и 2026-08-21) — на их уведомления это решение не распространяется.

## Оставшиеся развилки — дефолты приняты (не спрошены, низкая ставка)

| Вопрос | Дефолт |
|---|---|
| Подписывать молча или с пометкой | С пометкой: первое уведомление по подписке несёт «вы подписаны, потому что комментировали» + путь отписаться |
| Отписка — от задачи или от чужих комментариев | Отписка гасит уведомления **о комментариях** этой задачи, для этого человека. Назначения — отдельный тип, отпиской не гасятся |
| Новый комментарий после отписки | Отказ уважаем: подписка сама не возвращается, иначе кнопка бесполезна |
| Массовая отписка в настройках | Не делаем (YAGNI), пока не попросят |

Возражение владельца по любому из дефолтов отменяет его — они выбраны, чтобы не тормозить стройку, а не как решение.

## Не входит

Лента активности по всем задачам своих людей (уведомления без комментария) — другая фича, не эта. Здесь подписка возникает только из участия.
