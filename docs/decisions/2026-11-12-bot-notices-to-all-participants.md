# Нотисы бота встречи — всем участникам, а не только запустившему (12.11.2026)

## Решение владельца

> «Давай проработаем так, чтобы уведомление приходило всем… чтобы все видели, что не пришел бот… если у человека есть попутная еще одна встреча… записи… должны быть самостоятельными, потому что это разные встречи.»

## Поправка владельца в тот же день (приоритетнее первой формулировки)

> «Все, кто окнул встречу, те получают. Если человек не окнул, либо к нему это не относится… нахера ему это видеть».

Цель: если запустивший принял встречу, но в звонок не пошёл, те, кто реально в звонке, видят нотису и открывают доступ. Поэтому адресаты — не все `co_owners`, а только принявшие (`accepted`).

## Повод

Встреча «Caucasus, Turkiye, CA, Nigeria, Bali monthly results» (Контур.Толк): `scriba` запущен по календарю одного участника, комната была закрыта для гостей, бот ждал около 12 минут и ушёл (`guest_access_closed`). Нотиса ушла только запустившему; владелец тоже принял встречу, ждал запись и ничего не получил. В `meetings.co_owners` уже лежали все участники из Swarm. Разбор — issue #1283.

## Что решено

1. **Встречные нотисы** (привязаны к `meeting_id`: `door_waiting`, `door_denied`, `door_blocked`, `guest_access_closed`, `guest_access_waiting`, `meeting_unavailable`, `account_signin_required`, `captcha`, `no_audio`, `recording_lost`, `container_died`, `join_failed`) уходят запустившему (`identity.telegramId`) и остальным участникам из Swarm, которые ПРИНЯЛИ встречу (accepted). До-встречные (`no_conference_link`, `no_owner`) — как раньше, только запустившему.
2. **Получатели — только с сервера, не из тела запроса.** Статус ответа в `meetings.attendees` не хранится, поэтому принявших считает обход календаря (`meeting-calendar`): почты `accepted` из события запустившего и из событий склеенных людей с автозапуском (раньше их события выбрасывались при склейке) → пользователи воркспейса по почте → `meeting_calendar_jobs.notice_recipients` (новая колонка, миграция `20261112120000`). meeting-notice читает список по ключу пропуска бота. Исключаются отрицательные id (веб без Telegram), дубли и те, кого нет в `allowed_users`. Встреча по ручному приглашению (не календарь) и запрос человека — только запустившему. Ограничение: список считается при заведении задания (за ~2 минуты до начала), принявшие позже в него не попадают.
3. **Журнал и потолки — на каждого получателя** (`meeting_notice_reserve` вызывается по разу на человека: свой номер отправки, свои потолки на встречу и на сутки). Комендантский час и `telegram_outbox` — как у обычной нотисы.
4. **Бот видит только запустившего.** `attempt`, `should_leave`, 409 и 502 в ответе боту считаются по запустившему; решение «уходить» не зависит от числа получателей. Недоставка или потолок у со-участника — в лог, доставку остальным и ответ боту не меняют.
5. **Ранний «стук» `guest_access_waiting`** (Толк): как только адаптер видит закрытую комнату, процесс встречи сразу шлёт нотису короткий текст «бот не может зайти в Толк, сделайте встречу открытой для внешних участников». Один раз на встречу и человека. Итоговая `guest_access_closed` по уходу остаётся.
6. **Встречи самостоятельны.** Нотиса по встрече X пишет только в журнал `meeting_notices` и очередь Telegram. Никаких записей в `meetings`, claims, лизы, `recorders`/`co_owners`, `meeting_calendar_jobs` других встреч получателя; если у него параллельно своя встреча Y, она идёт и записывается отдельно. Проверяют тесты `meeting-notice/handle.test.ts`.

## Что осталось как есть

Тексты прежних нотис не менялись (нейтральны к тому, кто получатель); новый текст «стука» — короткий, на ru и en; язык один на всех получателей — из тела запроса (бот шлёт `en` по умолчанию): языка в профиле пользователя в системе нет.

## Текст раннего стука (владелец, 12.11.2026)

Владелец: «По поводу текста сделай короче, скриба не может зайти во встречу контртолка название Она закрыта для внешних участников. Все дальше сами поймут.»

Итог: «{bot} не может зайти во встречу Контур.Толка «{title}»: она закрыта для внешних участников.» / «{bot} can't join the Kontur.Talk meeting {title}: it is closed to external participants.»

Открыто: из чьих календарей брать «принял» (см. разбор с владельцем) — до решения PR не вливается.
