# Сколько раскаток за ночь — сколько угодно

**Дата:** 16.09.2026
**Решение владельца, дословно:** «за ночь хоть миллион прогонов, похер»

## Вопрос

`.github/workflows/deploy-window.yml` заведён двумя кронами — 21:00 и 22:00 UTC. Комментарий рядом объяснял это переходом на зимнее время и обещал, что «второй запуск тихо выходит». Летом это неправда: 22:00 UTC = 00:00 по Белграду, то есть внутрь окна 23:00–05:59, и второй помеченный PR уезжает той же ночью часом позже. Шапка `scripts/deploy-window-merge.sh` при этом отдельно декларировала «ОДИН PR за прогон. Две раскатки за ночь подряд смешивают причины, если что-то сломается» — и эта фраза читалась как «один PR за ночь».

Развилка была не техническая, а про правило: одна раскатка за ночь или сколько получится.

## Решение

Ограничения «одна раскатка за ночь» нет и не было нужно. Расписание с двумя кронами остаётся как есть; сколько прогонов за ночь — неважно.

Сохраняется ровно одно ограничение, и оно про прогон, а не про ночь: **в одном прогоне вливается один PR**. Смысл его в том, чтобы при поломке было понятно, чья она, — а не в том, чтобы растягивать очередь по ночам.

## Что из этого следует в коде

- `deploy-window.yml` — комментарий у крона больше не обещает, что второй запуск выходит; он называет факт (летом два прогона, зимой один).
- `deploy-window-merge.sh` — шапка говорит «ОДИН PR за ПРОГОН (не за ночь)», а сообщение об оставшихся помеченных PR печатает реальные времена прогонов по Белграду вместо неверного «дождутся следующей ночи» (issue #157: на этой фразе уже построили ошибочный график раскаток).
- `docs/decisions/2026-08-27-deploy-at-night.md` — строка таблицы про «один PR за прогон» помечена как пересмотренная здесь.
