# scriba — блок container

Окружение одной встречи: виртуальный экран (Xvfb), виртуальная звуковая карта
(PulseAudio null-sink), Chromium в headed-режиме и ffmpeg. **Одна встреча = один
контейнер:** sink и дисплей глобальны, два бота в одном контейнере запишут друг
друга.

Главный риск, ради которого блок выделен отдельно, — звук, который **молча не
пишется**. Смоук ниже устроен так, чтобы этот сбой не проходил незамеченным.

## Собрать и запустить

```bash
docker compose -p scriba-container -f bot/container/docker-compose.yml up -d --build
```

`entrypoint.sh` в этом порядке: Xvfb → PulseAudio с `--exit-idle-time=-1` →
null-sink `scriba` → `set-default-sink` → **самопроверка окружения** (`node
verify-environment.ts`). Без последней шага контейнер поднимался бы «успешно» и
писал бы тишину — тот самый молчаливый сбой.

Погасить:

```bash
docker compose -p scriba-container -f bot/container/docker-compose.yml down -v
```

## Смоук записи

```bash
bot/container/smoke.sh
```

Четыре прогона подряд, и красный среди первых трёх обязателен:

| шаг | ждём            | что проверяет                                                                                                                                |
| --- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 1/4 | pass            | звучащая страница записывается со звуком                                                                                                     |
| 2/4 | fail            | Chromium с `--mute-audio` — тот самый дефолт Playwright, ради которого стоит `ignoreDefaultArgs`                                             |
| 3/4 | fail            | молчащая страница — вердикт тишины                                                                                                           |
| 4/4 | pass A + pass B | два контейнера параллельно (`profiles=pair`), sink у обоих одинаковый намеренно: изоляция обязана держаться границей контейнера, а не именем |

Проверка, которая не падает на испорченном входе, — не проверка; поэтому шаги 2
и 3 обязаны краснеть, и «зелёный» итог складывается из четырёх правильных
исходов, а не из одного зелёного смоука.

## Настройка

Все переменные окружения перечислены с описаниями в
[`.env.example`](.env.example). Ключевые ручки самопроверки:

- `SCRIBA_SMOKE_PAGE` — что открыть; по умолчанию `tone.html`;
- `SCRIBA_SMOKE_EXPECT` — `sound` (по умолчанию) или `silence`;
- `SCRIBA_SMOKE_FORCE_MUTE=1` — запустить Chromium с аргументами Playwright по
  умолчанию (то есть с `--mute-audio`); нужна ровно для шага 2/4 смоука.

## Что этот блок отдаёт

Готовое окружение для `meet-adapter`. Всё, что дальше — присоединение к звонку,
запись имён говорящих, выгрузка на сервер — живёт в других блоках. Здесь только
то, что должно быть **до** первой строки логики звонка.
