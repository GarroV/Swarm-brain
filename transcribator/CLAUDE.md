# CLAUDE.md — Swarm Meetings

Инструкции для Claude Code. Прочитай `00-OVERVIEW.md` перед любой работой; остальные доки — по компоненту, который трогаешь.

## Контекст в одном абзаце

Делаем замену Granola/Read.ai для внутренней команды: тонкий macOS-агент (форк `fastrepl/anarlog`, Tauri/Rust) пишет встречи, локально транскрибирует Whisper'ом (large-v3-turbo q5, русский язык) ПОСЛЕ встречи (не реалтайм!), шлёт транскрипт + пометки пользователя в Supabase edge-функцию `meeting-ingest` (репо `GarroV/Swarm-brain`), где GPT-4o генерит тезисы по командному шаблону; человек правит тезисы в веб-версии (Next.js). Целевое железо: M1 / 8 ГБ.

## Жёсткие принципы (нарушение = переделка)

1. **Агент — тупой.** Никакой генерации тезисов, шаблонов, LLM-логики на клиенте. Только: запись → транскрибация → POST.
2. **Контракт API (`02-API-CONTRACT.md`) — закон.** Менять только синхронно с обеих сторон и с версионированием.
3. **Никакого реалтайм-STT во время звонка.** Запись в файл, транскрибация после окончания.
4. **Upsert по `meeting_id`, идемпотентность.** Правленые человеком тезисы (`notes_edited_at != null`) сервер не перезаписывает.
5. **Минимальный диф к апстриму anarlog.** Новый код — в `plugins/swarm/`. Чужие плагины НЕ удалять — не регистрировать в bootstrap. Пин на коммит апстрима, SHA в README.
6. **Переиспользуй существующее в Swarm-brain.** Перед написанием хелперов (запись в базу знаний, эмбеддинги, задачи, Telegram-отправка) — изучи `supabase/functions/read-ai-webhook/` и `swarm-bot/`, бери их паттерны и утилиты.
7. **Все секреты — в Supabase secrets / конфиг pkg.** Ничего в код и git.

## Стек и команды

- Swarm-brain: Deno, Supabase Edge Functions. Деплой: `supabase functions deploy meeting-ingest`. Секреты: `supabase secrets set`.
- Агент: монорепо anarlog — Cargo (Rust) + pnpm (TS). Сборка по их README; релиз: `tauri build` (arm64).
- Веб: Next.js в существующем веб-слое Swarm-brain.

## Стиль работы

- Этапы и гейты — в `07-ROADMAP.md`. Не перескакивай гейты: разведка (Этап 0) обязательна перед патчами anarlog, её выводы пиши в `RECON.md`.
- Русский язык в пользовательских текстах (UI агента, уведомления, тезисы), английский — в коде/комментариях.
- Тесты для backend: curl-фикстуры из `03-BACKEND-SPEC.md §5` должны проходить перед деплоем.
- Если реальная схема БД Swarm-brain отличается от ожиданий в `03-BACKEND-SPEC.md §1` — адаптируй миграцию под реальность и зафиксируй отличия в комментарии миграции, доку не считай истиной выше кода.

## Чего НЕ делать

- Не добавлять фичи вне MVP (диаризация, авто-апдейтер, Windows) — это бэклог в `07-ROADMAP.md`.
- Не тащить в форк полный UI anarlog (редактор, чат, поиск) — правка живёт в вебе.
- Не делать вторую реализацию поиска/задач/чата на клиенте — всё это уже есть в Swarm Brain.
- Не трогать существующие функции `swarm-bot` / `swarm-mcp` без необходимости; `read-ai-*` не удалять до полной раскатки (Этап 4).
