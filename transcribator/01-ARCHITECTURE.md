# 01 — Архитектура

## Контекст: что уже есть в Swarm Brain

Репозиторий: `GarroV/Swarm-brain`. Стек: Deno (Supabase Edge Functions), PostgreSQL + pgvector, OpenAI (GPT-4o, Whisper API, text-embedding-3-small), Telegram Bot API, MCP-сервер для Claude Desktop.

Существующие функции:
```
supabase/functions/
├── swarm-bot/        # Telegram-бот
├── swarm-mcp/        # MCP-сервер (search_knowledge, get_tasks, get_meetings, ...)
├── read-ai-auth/     # OAuth2 Read.ai (выводится из эксплуатации)
└── read-ai-webhook/  # Вебхук Read.ai (паттерн-образец для meeting-ingest)
```

Ключевой факт: пайплайн «встреча → база знаний → задачи → эмбеддинги → бот/MCP» уже написан и отлажен для Read.ai. Мы **заменяем источник**, а не пишем даунстрим заново.

## Принципы разделения ответственности

| Где | Что делает | Чего НЕ делает |
|---|---|---|
| Desktop Agent | запись, локальная транскрибация, пометки, отправка | НЕ генерит тезисы, НЕ хранит истину, НЕ имеет редактора заметок |
| meeting-ingest | тезисы, задачи, эмбеддинги, нотификация | НЕ проверяет тезисы (source=desktop-agent → доверенный) |
| Web Editor | правка тезисов человеком, просмотр | НЕ перегенерирует тезисы без явной кнопки |

Агент намеренно «безмозглый»: чем меньше логики на клиенте, тем реже обновления и меньше поддержки.

## Безопасность (внутренний инструмент, без паранойи)

- Агент → Supabase: статический Bearer-токен (общий секрет команды), запечён в конфиг pkg. Проверка в edge-функции, при несовпадении — 401.
- Web Editor: существующая авторизация роя (Telegram auth для Mini App).
- Аудио не покидает машину пользователя. В облако (OpenAI) уходит только текст — тот же уровень доверия, что у всего остального контента Swarm Brain.

## Отказоустойчивость

- Агент держит локальную очередь отправки (SQLite/файл): если Supabase недоступен — retry с экспоненциальным бэкоффом.
- Аудио хранится 7 дней → возможность ручной повторной транскрибации при сбое.
- Upsert по `meeting_id` → повторные отправки идемпотентны.
