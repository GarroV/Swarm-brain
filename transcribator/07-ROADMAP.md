# 07 — Роадмап: текущий статус и что осталось

Дорожная карта по фактическому состоянию на 2026-06-13. Архитектура — облачная транскрибация (OpenAI), своё лёгкое macOS-приложение-рекордер, обязательная вычитка + аппрув + выбор базы. Источник истины по решениям — `10-REVISED-DESIGN.md`; контракт и схема — миграция `20260612000000_meetings.sql` и функции `meeting-claim` / `meeting-ingest` / `swarm-api`.

> **Разворот относительно старого плана.** Этап «разведка anarlog» и anarlog-гейты сняты — форка нет, локального Whisper нет, рекордер написан с нуля на Swift. Старые этапы 0–4 (разведка → форк → плагины → pkg-пилот) неактуальны и заменены ниже.

## Сделано и задеплоено (прод, проект `vbqglndbxkpmreccpqmr`)

### Бэкенд (Supabase Edge Functions, Deno)
- [x] Таблица `meetings` — миграция `20260612000000_meetings.sql` (claim/lease, recorders, transcript, draft_notes_md, notes_edited_at, entry_id, group_id, status, `UNIQUE(identity_key)` где `identity_kind<>manual`).
- [x] `POST /meeting-claim` — регистрация записавшего в `recorders`, сохранение `user_notes` приватной entry, lease с TTL, ответ `{meeting_id, decision: transcribe|defer, lease_ttl_sec}`. Личность и `group_id` — из токена (`_shared/agent-auth.ts` → `verifyAgentToken`), без спуфинга.
- [x] `POST /meeting-ingest` — multipart `audio` (системный звук) + `audio_mic` (опц.); транскрибация обеих дорожек (whisper-1 `verbose_json`), сведение сегментов по таймстампам → `meetings.transcript` → GPT-4o тезисы → `draft_notes_md` → уведомление записавшим. Ответ 202, фон через `EdgeRuntime.waitUntil`. Защита человеческой правки: `notes_edited_at != null` → пропуск. Заливка не от claimer → 403.
- [x] `swarm-api` (веб-сессия роя): `GET /agent-meetings?status=`, `GET /agent-meetings/:id`, `PATCH /agent-meetings/:id` (правка `draft_notes_md` → `notes_edited_at`), `POST /agent-meetings/:id/publish` (`{base: workspace|personal}` → создаёт `entries` с эмбеддингом, привязывает `entry_id`, `status=in_base`, идемпотентно через гонку-гард).
- [x] Авто-извлечение задач при публикации — `createMeetingTasks` (GPT-4o-mini из `draft_notes_md` → `createTask` с привязкой `meeting_id`, резолвом исполнителя по имени, наследованием приватности `personal → is_private + owner_id`). Сбой извлечения не валит публикацию.
- [x] Видимость `source=desktop-agent` в трёх местах: `swarm-api` GET /meetings, MCP `get_meetings`, бот `rai_saved`.
- [x] Секрет `WEB_BASE_URL=https://swarm-brain.pages.dev` — кнопка «Открыть» в уведомлении ведёт на `/?meeting=<id>`.

### Рекордер (`recorder/` — своё macOS-приложение)

## Осталось

### Рекордер: захват идентичности и аудио-лимит
- [ ] **Авто-старт по календарю (EventKit)** — детект запланированного звонка, старт записи без ручного клика. Источник `calendar_event_id` для лучшего ключа дедупа.
- [ ] **Извлечение id комнаты из URL** активной вкладки — Meet-код, Контур-room. Даёт ключ `identity_kind=room` для ad-hoc звонков без календаря.
- [ ] **Нарезка/сжатие аудио > 25 МБ** — лимит файла OpenAI. Длинные встречи (>~часа AAC) резать на части либо дожимать перед заливкой.

### Бэкенд
- [ ] **Эндпоинт «Объединить встречи»** — ручная склейка дублей (кросс-источник granola и `manual:<uuid>`, у которых нет авто-дедупа). Авто-схлоп уже работает только по точным ключам (calendar/room).
- [ ] **Curl-фикстуры** — отсутствуют два сценария: «ретрай после таймаута» (идемпотентность claim/ingest) и «двойная отправка двух участников одной встречи» (один черновик, один GPT-вызов).

### Распространение
- [ ] **Упаковка/распространение рекордера** — открытый вопрос БЕЗ платного аккаунта Apple (подпись остаётся ad-hoc). TCC-разрешения (Screen Recording, микрофон) пользователь выдаёт при первом запуске и, возможно, заново после пересборки — известное неудобство.

### Переходный период: выключение источников
- [ ] **Read.ai** — выключаем в конце месяца.
- [ ] **Granola** — продолжает работать (заменеджерим, объясним команде), пока не запустим свой софт на команду; затем отключаем сами.
- desktop-agent уживается с обоими в боте/вебе/MCP через source-фильтры (уже сделано).

## Бэклог (после стабилизации, не делать сейчас)

- Сжатие/реферирование очень длинных транскриптов перед генерацией тезисов (встречи > 1.5 ч).
- Чанкование транскрипта для семантического поиска по дословным репликам (сейчас эмбеддим только тезисы — этого достаточно для MVP).
- Диаризация спикеров поверх сведения двух дорожек (кто из удалённых участников говорил).
- Переезд шага транскрибации на локальный Whisper — только если появится машина с NVIDIA-GPU; контракт ingest при этом не меняется (рекордер всё равно шлёт аудио). Это возможность, не план.
- Windows-версия рекордера — если в команде появятся не-маки.

## Риски

| Риск | Вероятность | Митигация |
|---|---|---|
| Качество русской транскрибации whisper-1 недостаточно | низкая | whisper-1 покрывает русский; шаг транскрибации сменный — при нужде меняем модель/провайдера без правки контракта |
| Длинная встреча упирается в лимит OpenAI 25 МБ | средняя | Нарезка/сжатие аудио (в «Осталось»); компактный AAC ~10 МБ/час даёт запас на ~2.5 ч |
| Таймаут edge-функции на длинной транскрибации + ретрай → дубль | средняя | Уже заложено: ingest отвечает 202, генерация в `EdgeRuntime.waitUntil`; claim идемпотентен по `identity_key` |
| Один общий черновик у нескольких записавших | низкая | First-come правка, last-write-wins; `notes_edited_at` защищает правку от повторной заливки |
| Дубли встреч без точного ключа (granola, manual) | средняя | Ручное «Объединить» в вебе (warn-at-add); авто-схлоп — только по calendar/room |
| TCC-разрешения слетают после пересборки рекордера | средняя | Пользователь переподтверждает при первом запуске; распространение бинаря — открытый вопрос (без платного аккаунта Apple) |
| Сотрудник забыл выдать разрешения → встреча молча не пишется | средняя | Рекордер проверяет разрешения; нет разрешения → состояние видно в меню-баре |
