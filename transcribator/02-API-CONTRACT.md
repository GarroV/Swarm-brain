# 02 — Контракт API: meeting-ingest

Единственная точка интеграции между Desktop Agent и Swarm Brain. Контракт фиксируем до начала разработки обеих сторон.

## Endpoint

```
POST https://<project-ref>.supabase.co/functions/v1/meeting-ingest
Authorization: Bearer <SWARM_AGENT_SECRET>
Content-Type: application/json
```

## Request body

```jsonc
{
  // Идемпотентность: UUID, генерится агентом при старте записи,
  // повторная отправка той же встречи = upsert
  "meeting_id": "9f1c2a3e-...",

  "source": "desktop-agent",          // маркер доверенного источника
  "agent_version": "0.1.0",

  // Метаданные из календаря (всё опционально кроме started_at)
  "title": "Синк по Болгарии",
  "started_at": "2026-06-11T14:00:00+03:00",   // ISO 8601
  "ended_at": "2026-06-11T14:47:12+03:00",
  "calendar_event_id": "ABC123",               // для дедупа, опционально
  "attendees": [                                // из календаря, опционально
    { "name": "Маша", "email": "m@team.com" }
  ],
  "owner_telegram_id": 123456789,    // чья машина → кому слать уведомление

  // Полный транскрипт. Сегменты с таймстампами (секунды от начала)
  "transcript": {
    "language": "ru",
    "model": "large-v3-turbo-q5",
    "segments": [
      { "start": 0.0,  "end": 6.4,  "text": "Так, все собрались, начинаем." },
      { "start": 6.4,  "end": 14.1, "text": "По Болгарии: клиент просит сдвинуть..." }
    ]
  },

  // Пометки пользователя во время встречи. Может быть пустым массивом.
  // ts = секунды от начала встречи (для сопоставления с транскриптом)
  "user_notes": [
    { "ts": 312.5, "text": "дедлайн!!" },
    { "ts": 840.0, "text": "@Маша уточнит бюджет" }
  ]
}
```

## Response

**200 OK**
```jsonc
{
  "ok": true,
  "meeting_id": "9f1c2a3e-...",
  "entry_id": "...",                 // id записи в базе знаний
  "web_url": "https://<webapp>/meetings/9f1c2a3e",  // deep link для уведомления
  "summary_status": "done",          // done | processing (если генерация асинхронная)
  "tasks_created": 3
}
```

**Ошибки**
| Код | Когда | Поведение агента |
|---|---|---|
| 401 | неверный секрет | показать ошибку в UI, не ретраить |
| 400 | невалидный payload | лог, не ретраить (баг) |
| 409 | конфликт upsert (редко) | ретрай 1 раз |
| 429 / 5xx | перегрузка/сбой | retry с бэкоффом: 1м, 5м, 15м, 1ч, 6ч; очередь сохраняется между перезапусками агента |

## Правила обработки на сервере

1. **Upsert по `meeting_id`.** Повторная отправка перезаписывает транскрипт и перегенерирует тезисы, НО: если тезисы уже редактировались человеком (`notes_edited_at IS NOT NULL`) — тезисы не перезаписываются, только транскрипт; в ответе `summary_status: "skipped_human_edit"`.
2. `source = "desktop-agent"` + валидный секрет → запись помечается доверенной, существующая серверная проверка тезисов пропускается.
3. `user_notes` непустой → промпт генерации строит тезисы вокруг пометок, разворачивая каждую деталями из транскрипта (окно ±2 мин по `ts`). Пустой → обычная структурная суммаризация.
4. Эмбеддятся отдельно: тезисы И транскрипт (чанками). `user_notes` хранятся как поле, не эмбеддятся.
5. После генерации → Telegram-уведомление `owner_telegram_id`: «Тезисы по "{title}" готовы» + кнопка-ссылка `web_url`.

## Версионирование

Поле `agent_version` в каждом запросе. При breaking change контракта — новый путь `/meeting-ingest-v2`, старый живёт до обновления всех агентов.
