# 05 — Веб-вычитка: страница встречи в miniapp

Вычитка и публикация встреч живут в существующем веб-слое Swarm Brain — `miniapp/` (Next.js 16, Tailwind 4, shadcn/Base UI, статический экспорт `output: export` на Cloudflare Pages, домен `swarm-brain.pages.dev`). Это основной «дом» тезисов: рекордер только доставляет аудио, сервер генерит черновик, **человек правит и публикует здесь**.

Один и тот же бандл работает и как обычная веб-версия в браузере, и как Telegram Mini App.

## Архитектура навигации (важно — не как в старой спеке)

miniapp — это **single-page-приложение с навигацией через state**, а не файловые маршруты. Корневой компонент `src/app/page.tsx` держит активный раздел (`section`) и id открытой на вычитку встречи (`reviewId`) в `useState` и рендерит нужный экран.

- **Нет динамического роута `/meetings/[uid]`.** При `output: export` динамические сегменты потребовали бы пререндера всех id на этапе сборки — встречи создаются в рантайме, так что это нереализуемо. Вместо роута — **deep-link через query-параметр** (см. ниже).
- **Нет RLS из Next.js.** RLS в проекте не включён, везде используется `SERVICE_ROLE_KEY`. Доступ к встречам проверяется **в коде swarm-api** (видны записавшим или админу), а не на уровне БД и не на клиенте. Клиентское render-gating только прячет UI, доступ решает сервер.

Раскладка экрана задаётся в `page.tsx`:
- **Десктоп (`lg+`):** боковая панель `Sidebar` слева, контент в колонке справа (`lg:max-w-5xl`).
- **Мобайл:** нижняя навигация `BottomNav` (`lg:hidden`), `Sidebar` скрыт.

## Компоненты

### `MeetingReview` (`src/components/MeetingReview.tsx`)

Страница вычитки одной встречи. Открывается поверх раздела (рендерится вместо контента раздела, когда задан `reviewId`). Пропсы: `{ id, onClose, onChanged? }`.

Данные тянет через `lib/api.ts`:
- `fetchAgentMeeting(id)` → `GET /agent-meetings/:id` — черновик + транскрипт (поле `transcript` приходит только в детальном GET).
- `patchAgentMeetingDraft(id, draft_notes_md)` → `PATCH /agent-meetings/:id` — сохранить правку.
- `publishAgentMeeting(id, base)` → `POST /agent-meetings/:id/publish`.

Состав страницы:

1. **Шапка:** кнопка «Назад» (`onClose`) + название встречи (`meeting.title`).
2. **Мета-строка:** бейдж источника `desktop-agent`, дата (`started_at`, первые 10 символов), статус — «На вычитке» (`awaiting_review`, янтарный) или «В базе» (`in_base`, зелёный), счётчик записавших (`recorders.length`).
3. **Тезисы (главный блок):**
   - Если `draft_notes_md === null` — «Готовим тезисы…» (черновик ещё генерится на сервере).
   - Иначе — просмотр текста (`whitespace-pre-wrap`). Кнопка «Редактировать» (только пока `awaiting_review`) разворачивает `Textarea` с черновиком. «Сохранить» → `PATCH` (сервер проставляет `notes_edited_at`, чем защищает правку от перезаписи последующими `meeting-ingest`). «Отмена» возвращает исходный текст.
4. **Спойлер «Транскрипт»:** read-only, раскрывается по клику, сегменты с таймстампами (`fmtTs` → `MM:SS` из `segment.start`). Заголовок показывает число сегментов. Поиск по странице — Ctrl+F (отдельного поиска в MVP нет).
5. **Публикация (нижняя панель, только пока `awaiting_review` и тезисы готовы):**
   - Переключатель базы: **«В команду»** (`base = "workspace"`) / **«В личное»** (`base = "personal"`).
   - Кнопка публикации: «Сохранить в базу команды» либо «Сохранить в личное». Вызывает `POST /agent-meetings/:id/publish` с выбранной базой → сервер создаёт `entry` с эмбеддингом, привязывает `entry_id`, ставит `status = in_base`, запускает авто-извлечение задач (`createMeetingTasks`). После успеха — `onChanged()` + `onClose()`.
   - Если встреча уже `in_base` — вместо панели публикации текст «Уже в базе. Правки — через раздел „База"».

Ядро (не обсуждается): каждая встреча проходит обязательную вычитку человеком и ручной аппрув с выбором базы команда/личное. До публикации `entry` не существует — черновик живёт только в `meetings.draft_notes_md` и в семантический поиск не попадает.

> **Не реализовано в текущем компоненте (план, не выдумывать как готовое):** список участников (`attendees`), блок привязанных задач встречи с кнопкой повторного прогона экстракции, спойлер «Мои пометки во время встречи» (приватные `user_notes`-записи участника). Кнопки «Перегенерировать тезисы» в текущем UI нет — защита от случайной перезаписи строится на `notes_edited_at`. Добавлять — только синхронно с эндпоинтами swarm-api.

### `AgentReviewQueue` (`src/components/AgentReviewQueue.tsx`)

Очередь черновиков `desktop-agent` «на вычитке». Рендерится в разделе **«Встречи»** над списком встреч (`MeetingsScreen`). Пропс: `{ onOpen: (id) => void }` — клик по карточке открывает `MeetingReview`.

- Тянет `fetchAgentMeetings("awaiting_review")` → `GET /agent-meetings?status=awaiting_review`. Сервер отдаёт только встречи, видимые текущему пользователю (записавшим или админу).
- **Невидима, пока черновиков нет.** Если `items.length === 0` — возвращает `null`. То же при ошибке fetch (например, эндпоинт ещё не задеплоен): `catch` → пустой список → очередь просто не показывается, остальное приложение работает. Это намеренная мягкая деградация.
- Карточка: название + дата (`started_at` или `created_at`), пометка «готовим тезисы…», если `draft_notes_md === null`.

После аппрува встреча уходит из `awaiting_review` у всех записавших разом — при следующей загрузке очереди её там уже нет.

## Deep-link из уведомления «тезисы готовы»

Сервер `meeting-ingest` после генерации черновика шлёт записавшим уведомление с кнопкой «Открыть» (если задан секрет `WEB_BASE_URL=https://swarm-brain.pages.dev`), ведущей на конкретную встречу. Разбор ссылки — `getDeepLinkMeetingId()` в `src/lib/telegram.ts`:

- **Браузер:** `?meeting=<id>` — читается из `window.location.search`.
- **Telegram Mini App:** `startapp=meeting_<id>` приходит как `start_param` в `initDataUnsafe`; функция снимает префикс `meeting_` и возвращает id.

В `page.tsx` при монтировании: если `getDeepLinkMeetingId()` вернул id — переключиться на раздел `meetings` и открыть `MeetingReview`. При закрытии вычитки (`closeReview`) query-параметр стирается через `window.history.replaceState`, чтобы ссылка не открывала встречу повторно.

## Definition of Done (MVP)

- [x] Ссылка из уведомления открывает нужную встречу — и в браузере (`?meeting=`), и в Mini App (`startapp=meeting_`)
- [x] Правка тезисов сохраняется (`PATCH`), после неё повторный `meeting-ingest` тезисы не затирает (`notes_edited_at`)
- [x] Публикация создаёт `entry` с эмбеддингом и выбором базы команда/личное; после неё запускается извлечение задач
- [x] Транскрипт доступен под спойлером, сегменты с таймстампами
- [x] Очередь «на вычитке» видна в разделе «Встречи» и не ломает приложение, когда эндпоинт недоступен
- [x] Работает с телефона в Mini App (адаптив, нижняя панель публикации)
- [ ] Участники, привязанные задачи и приватные пометки участника на странице встречи (план)
