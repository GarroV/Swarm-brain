# Swarm Meetings — обзор проекта

Внутренний инструмент команды (~20 человек): записываем онлайн-звонки, транскрибируем, генерируем тезисы, человек вычитывает и публикует в командную базу знаний Swarm Brain **или** в личное хранилище, из тезисов авто-извлекаются задачи.

Заменяет связку **Read.ai / Granola**. Без подписок: единственные внешние расходы — уже используемый OpenAI API (~$0.36/час встречи на транскрибацию + центы на тезисы).

> Это входная точка пакета. Глубокие детали — в файлах `01`–`07`; решения воркшопа и пересмотренный контракт — в `10-REVISED-DESIGN.md` (источник истины при конфликте со старыми доками).

## Скоуп: только онлайн-звонки

- **Google Meet, Контур.Толк** — браузерные, id комнаты берём из URL активной вкладки.
- **Telegram-звонок** — кнопка резкого старта (сюда же редкие офлайн-записи одним человеком).
- **Zoom — редко, Teams — почти никогда.**

Переговорки и многопользовательский диктофон для комнат **не проектируем**.

## Три компонента

| Компонент | Что это | Где |
|---|---|---|
| **Рекордер** | Своё лёгкое меню-бар приложение для macOS (Swift/AppKit, `LSUIElement`). ScreenCaptureKit пишет системный звук удалённых участников, AVAudioRecorder — микрофон владельца → **две дорожки AAC m4a**. Агент тупой: запись → claim → загрузка аудио, ноль LLM-логики на клиенте | папка `recorder/` |
| **Бэкенд** | Supabase Edge Functions (Deno), задеплоено на прод. Принимает аудио, транскрибирует в облаке через OpenAI (`whisper-1`, `verbose_json`), сводит две дорожки по таймстампам, генерит тезисы GPT-4o, при публикации создаёт `entries` с эмбеддингом и извлекает задачи | `supabase/functions/`, таблица `meetings` |
| **Веб (вычитка)** | Страница вычитки одной встречи и очередь на вычитке в miniapp (Next.js 16 + Tailwind 4 + shadcn/Base UI, static export на Cloudflare Pages, `swarm-brain.pages.dev`) | веб-слой Swarm Brain |

Транскрибация — **в облаке, не локально.** Причина: не тащить тяжёлый локальный ML и GPU на машины пользователей. Шаг транскрибации сменный — при появлении машины с NVIDIA-GPU можно переехать на локальный Whisper без смены контракта, но это лишь возможность, **не текущий план**.

## Сквозной поток

```
1. Записывают ВСЕ участники (две дорожки AAC m4a; N резервных копий, координации не нужно)
2. Перед загрузкой агент делает CLAIM на сервер:
   { identity_kind, identity_key, started_at, ended_at, title?, attendees?, user_notes?, agent_version }
   (личность и group_id — из персонального smcp_-токена, не из payload)
3. Сервер (meeting-claim):
   - ключа ещё нет → создаёт meetings(status=awaiting_review), decision=transcribe
   - ключ уже есть (claim держит другой) → decision=defer, агент аудио НЕ грузит
   - claim берётся по lease с TTL → перехват, если claimer сорвался
   - user_notes сохраняются как приватная entry участника (metadata.meeting_id)
4. claimer заливает аудио в meeting-ingest (multipart: audio + опц. audio_mic)
5. Сервер ОДИН раз: транскрибирует обе дорожки (whisper-1) → сводит сегменты с метками
   «собеседник»/«я» → meetings.transcript → GPT-4o тезисы → draft_notes_md
   → уведомление записавшим (кнопка «Открыть»)
6. Любой из записавших открывает общий черновик → вычитывает / правит тезисы
7. АППРУВ + выбор базы (команда / личное) → status=in_base, публикуется entry с эмбеддингом
   → из «на вычитке» ушло у всех разом → авто-извлечение задач
```

## Ядро (не обсуждается)

Каждая встреча проходит **обязательную предварительную вычитку + ручной аппрув + выбор базы** (команда / личное). Никакой источник не считается доверенным и не минует вычитку. До публикации черновик живёт только в `meetings.draft_notes_md` и в поиск/базу знаний **не попадает** — `entries` (тезисы как искомый артефакт, с эмбеддингом, семантическим поиском, изоляцией по `group_id`, приватностью `is_private`/`owner_id`) создаётся **только при публикации**. Безопасность личного хранилища — приоритет: чужие приватные пометки не отдаются никогда.

## Сосуществование источников (переходный период)

Три источника уживаются в боте, вебе и MCP. `desktop-agent` добавлен в основные выборки встреч: веб `swarm-api` `GET /meetings`, MCP `get_meetings` и список сохранённых в боте (детали и известный пробел покрытия в боте — `01-ARCHITECTURE.md` / `02-API-CONTRACT.md`):

- **Read.ai** — выключаем в конце месяца.
- **Granola** — продолжает работать (заменеджерим, объясним команде), пока не запустим свой софт; потом отключим.
- **desktop-agent** — новый источник.

Кросс-источник (granola) и `manual`-встречи дедуплицируются вручную — «Объединить» в вебе (warn-at-add); авто-схлоп только по точным ключам `calendar`/`room`.
