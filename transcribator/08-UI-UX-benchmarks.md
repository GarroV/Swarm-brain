# Бенчмарки зрелых продуктов — сырьё для дизайн-системы V2

> Выжимки агентов воркфлоу (2026-06-13): Linear, Notion, Granola, Vercel/Geist+Stripe, Raycast/Superhuman.
> Источник решений для transcribator/08-UI-UX-V2.md.


## Linear
Linear выглядит «дорого» не за счёт декора, а за счёт дисциплины: жёсткая 4px-сетка, одна (!) акцентная заливка на экран, остальной цвет — только в статусных значках, вся глубина строится hairline-бордерами и 3-4 ступенями поверхностей вместо теней. Типографика — один variable-шрифт (Inter) с кастомным средним весом 510 и плотным трекингом на крупных кеглях; никакой смены гарнитур ради иерархии. Скорость возведена в дизайн-принцип: оптимистичный UI с откликом 0.1-0.3s, полный паритет клавиатуры и мыши (любое действие доступно и хоткеем, и из контекст-меню, которое заодно обучает хоткеям), и микро-детали вроде треугольной «safe area» под сабменю на 40 строк CSS. Цветовая система в 2025 сведена к трём переменным (base/accent/contrast) в перцептивно-равномерном LCH/OKLCH, что даёт автоматически согласованные темы и high-contrast-режим. Премиальность = рацион цвета + плотность с воздухом в нужных местах + ощущение мгновенности.
- [Цвет / рацион акцента] Linear держит РОВНО ОДНУ акцентную заливку на экран (acid-lime #e4f222 — единственный filled-CTA), весь остальной интерфейс — узкая монохромная шкала холодно-серых; цвет несёт смысл только в статус-иконках. Система сведена к 3 переменным: base, accent, contrast — в перцептивно-равномерном LCH (красный и жёлтый с одинаковым L выглядят одинаково светлыми).
    → У вас уже OKLCH (родственник LCH) и медовый --accent — добейте принцип «один filled на экран»: primary-кнопка (Сохранить тезисы / + Задача) — единственная медовая заливка, всё прочее (фильтры-пилюли, навигация, вторичные действия) — ghost/outline на --surface-sunken. Сейчас риск: активная навигация (accent-soft+полоса), FAB, MainButton и primary-кнопка одновременно медовые на одном экране — это размывает акцент. Введите правило в globals.css комментарием и в ревью-чеклист: filled-accent = только текущее главное действие; навигация и статусы — НЕ заливка, а подложка/точка. Добавьте --contrast как у Linear (отдельная переменная для a11y-режима высокого контраста).
- [Статус-цвет / иконки] Статусы у Linear — не цветные пилюли, а маленькие SVG-иконки-«пончики»: пустой круг (backlog) → штриховой контур (todo) → круг с растущим сектором-заполнением (in progress, реальный % прогресса) → сплошной с галкой (done) → крестик (cancelled). Цвет приглушён (emerald #27a644, crimson #eb5757 — как контурные акценты, не заливки). Иконка читается даже при 14px и в один тон.
    → Замените статус-точки на SVG-прогресс-иконки 14px (компонент StatusIcon с пропом status). Для встреч маппинг идеален: «готовим тезисы» = круг с вращающимся/растущим сектором (--status-progress), «не подтверждена» = контур (--status-pending), «подтверждено» = сплошной+галка (--status-done), «ошибка» = крестик (--status-danger). Один компонент работает на всех трёх поверхностях (веб-строка, drawer, меню-бар агента). Это прямой апгрейд вашего borders-first принципа: статус читается формой, а не только цветом — выживает в монохроме и при цветослепоте. SVG через currentColor + className text-[--status-*].
- [Шкала типографики] Один variable-шрифт Inter с кастомным средним весом 510 (между regular 400 и medium 500) и 590 вместо semibold — иерархия строится тонкими шагами веса, не сменой гарнитур. На крупных кеглях отрицательный трекинг (72px → tracking -1.58px, 48px → -0.624px), на body — нормальный; mono (Berkeley) только 12-14px с letter-spacing -0.015em для метаданных. 14 ступеней размера, base-unit 4px.
    → Golos Text — variable, используйте промежуточные веса как Linear: тело 400, акцент строки 500, заголовки панелей 600 (а не 700) — у вас в шкале уже 500/600/750, но 750 на h1 при 13px-базисе будет тяжёлым; снизьте крупные заголовки до 600-650 и добавьте отрицательный letter-spacing на --text-xl/2xl (-0.02em…-0.03em) — именно это даёт «дорогой» собранный вид крупного текста. JetBrains Mono для метаданных — оставьте 11-12px, добавьте letter-spacing -0.01em (mono по умолчанию разрежен, для таймстампов [12:34] и кодов рынков это смотрится плотнее). В Tailwind4 @theme: --tracking-tight: -0.02em на heading-классы.
- [Плотность / ритм отступов] 4px base-unit, но ритм НЕравномерный по назначению: внутри элемента 8-12px, card padding 24-32px, секции 80-120px. Высокая плотность строк сочетается с щедрым воздухом между зонами — это и есть «instrument-panel density, где каждый пиксель работает», но без клаустрофобии. Border-radius дифференцирован: 2px бейджи, 6px контролы/инпуты/кнопки, 12px карточки, 9999px пилюли — радиус кодирует тип объекта.
    → Ваш план (4/8 внутри строки, 12 между блоками, 24 секции, 32/48 зоны, строка 36px) — точно в духе Linear, держите его. Усильте дифференциацию радиусов как у них: сейчас план «контролы 6 / карточки 8 / поповеры 10» — разрыв слишком мал, глаз не считывает иерархию. Возьмите Linear-разброс: бейджи/статус-пилюли 4px (--radius-sm), контролы/кнопки/строки 6px (--radius), карточки канбана 10-12px (--radius-lg), шиты/модалки/палитра 12-14px. Радиус становится носителем смысла «насколько объект приподнят». В @theme это 4 токена --radius-{sm,DEFAULT,lg,xl}.
- [Поверхности / глубина] Глубина — borders-first и через 3-4 ступени поверхностей (Onyx #08090a canvas → Charcoal #0f1011 nav/card → Obsidian #161718 deep card), бордеры hairline через inset-shadow `inset 0 0 0 1px rgb(35,37,42)` (резче border, не схлопывается). Тени только у плавающих слоёв и многослойные «depth-stack» (4 наложенных полупрозрачных тени дают мягкую реалистичную глубину вместо одной жёсткой).
    → Вы уже выбрали borders-first и --surface/--surface-sunken/--surface-raised — это ровно Linear-подход, отлично. Два усиления: (1) для hairline-бордеров на тёмной теме используйте inset box-shadow вместо border (`inset 0 0 0 1px var(--border)`) — не ест 1px layout и выглядит резче на oklch-фонах; (2) тень поповеров/палитры/шитов сделайте многослойной в стиле Linear depth-stack вместо одной тени: 3-4 наложенных oklch(0 0 0 / 4-8%) на разных blur/y дают «дорогую» мягкость. Ваша текущая ур.2 `0 8px 32px /14%` — замените на стек. В @theme: --shadow-overlay со списком.
- [Командная палитра (⌘K)] ⌘K у Linear — не просто поиск, а единая точка ВСЕХ действий: над выделенными issue открывает контекст-действия (статус, приоритет, исполнитель, цикл, архив — ~15 действий). Палитра одновременно обучает хоткеям (показывает шорткат рядом с каждым действием). Контекстность: содержимое палитры зависит от текущего выделения/экрана, не статичный список.
    → Ваш план cmdk поверх searchEntries — расширьте от «поиск + переходы» до контекстных действий, это то, что отличает «дорогую» палитру. Секции: (1) семантический поиск по базе (существующий endpoint), (2) переходы по разделам, (3) КОНТЕКСТНЫЕ действия над текущим объектом — на странице встречи «Подтвердить», «Перегенерировать», «Удалить»; в задачах над выделенной «Сменить статус», «Назначить». Справа от каждого действия — mono-хоткей (JetBrains Mono 11px, --muted-foreground) — палитра обучает клавиатуре. cmdk группы (Command.Group) + heading-секции. Это закрывает ваш «главный жест скорости» по-настоящему.
- [Клавиатура / паритет мыши] Принцип Linear: ЛЮБОЕ действие доступно без отрыва рук от клавиатуры, и контекст-меню (правый клик) показывает те же действия + их хоткеи — мышь и клавиатура полностью паритетны, меню обучает. Множественный выбор: Shift+↑/↓ расширяет диапазон, Cmd+A — всё, Esc — снять. Навигация по списку ↑↓, Enter — открыть, одна буква — действие (например e — edit).
    → В вашем плане уже есть ↑↓/Enter/e для встреч и c для новой задачи — формализуйте это в единую систему и добавьте контекст-меню (Base UI ContextMenu или shadcn) на строки встреч/задач/базы с дублированием хоткеев справа. Минимум для паритета: на доске задач — выбор строки, j/k навигация, x — выделить, Shift+стрелки — диапазон, контекст-меню со сменой статуса/исполнителя. Каждый пункт меню = `<span>Подтвердить</span><kbd class=mono>⏎</kbd>`. Это дешёвый по коду, но максимально «pro-tool» сигнал — команда из 10-30 человек, которые работают в инструменте каждый день, реально это оценит.
- [Микровзаимодействия / движение] Скорость — главный дизайн-принцип Linear: оптимистичный UI (мгновенно показывает результат до ответа сервера, откатывает при ошибке), отклик 0.1-0.3s, переходы органичные (не linear-easing — он «робот», нужны cubic-bezier с физикой). «Невидимые детали» вроде треугольной safe-area под сабменю (40 строк CSS clip-path), чтобы курсор не терял меню по диагонали — пользователь это не замечает, но «чувствует».
    → Ваши 120-150ms на compositor-friendly свойствах — правильно. Два конкретных переноса: (1) оптимистичные мутации — смена статуса задачи/подтверждение встречи должны менять UI мгновенно с откатом при ошибке (TanStack Query onMutate/onError — у вас server-state, не дублируйте в стор); по вашим же web/patterns это прямое требование. (2) Уберите linear/ease — задайте --ease-out-quart: cubic-bezier(0.25,1,0.5,1) для входов и держите его в @theme как единственный easing UI-уровня. Хаптика на смену статуса в Mini App (уже в плане) — это мобильный аналог Linear-«feel». Никаких scale-подпрыгиваний (у вас уже запрещены) — Linear их тоже не делает.
- [Строки списка / hover] Issue-строка Linear: фиксированная высота, слева статус-иконка, заголовок одной строкой с ellipsis, справа — метаданные (исполнитель-аватар, приоритет, дата) выровнены в колонки. Hover — едва заметная подсветка фона (на 1 ступень светлее) + проявление скрытых до hover контролов (drag-handle, быстрые действия). Selected-строка имеет отдельный тон, не путается с hover. Группировка по статусу/исполнителю/проекту со сворачиваемыми заголовками-секциями и счётчиком.
    → Ваши 36px-строки со статус-точкой и mono-метаданными — основа есть. Перенесите три приёма: (1) скрытые до hover быстрые действия в строке встречи/задачи (иконки «подтвердить», «открыть», «ещё») — appear на group-hover (Tailwind `group` + `opacity-0 group-hover:opacity-100`), не нагромождая строку в покое; (2) РАЗДЕЛИТЕ hover (--surface-sunken) и selected (--accent-soft слабый) — не один тон, иначе при навигации с клавиатуры теряешь, где курсор; (3) сворачиваемые заголовки групп с counter (у вас уже есть группировка встреч по датам — добавьте chevron + счётчик + sticky-заголовок группы). Метаданные строки выровняйте в фиксированные колонки (grid-cols с заданной шириной под аватар/дату), а не flex-gap — Linear-«собранность» именно отсюда.
- [Пустые состояния] Linear (как Notion) использует простые монохромные иллюстрации, которые сливаются с интерфейсом, но дают теплоту и ясность; пустое состояние = не «нет данных», а следующий шаг (CTA на первое действие). Разные типы: first-time (онбординг, объясняет фичу), post-completion («inbox zero» — награда за расчищенный список). Не цветные стоковые картинки, а сдержанный сигнал в палитре системы.
    → Для каждой поверхности — осмысленное пустое состояние в вашей палитре, не «список пуст». Конкретно: Встречи без записей → монохромный глиф-сота (ваш бренд!) + «Пока нет встреч. Агент в меню-баре запишет первую» + ссылка на онбординг агента. Задачи done-колонка пустая → лёгкий post-completion сигнал. База без результатов поиска → «Ничего не нашлось по смыслу» + подсказка переформулировать (ваш поиск семантический — объясните это в пустом состоянии). Иллюстрации — lucide-глиф или ваша сота в --muted-foreground на --surface-sunken, без цвета. Один компонент EmptyState (icon, title, description, action?). Это дёшево и сразу поднимает воспринимаемое качество.
- [Иерархия / редактор] Linear на крупных заголовках даёт expressiveness через Inter Display + отрицательный трекинг, но в плотных списках — тихий, ровный body. Иерархия = контраст масштаба и веса в узком диапазоне, а не множество разных размеров. Max-width контента ограничен (~1200px) даже на широких экранах — текст не растягивается на всю ширину.
    → Ваш редактор тезисов ≤760px (~70ch) — точно правильно, это Linear-дисциплина (не растягивать текст). Усильте контраст масштаба между «документной» центральной колонкой и mono-рельсой метаданных: тело тезисов 15-16/24 нормального веса, заголовок встречи крупно с tight-трекингом, метаданные в рельсе — mono 11-12px uppercase-лейблы с letter-spacing +0.04em (mono uppercase для лейблов «ДАТА / ДЛИТЕЛЬНОСТЬ / ИСТОЧНИК» — характерный Linear-приём для метаданных-подписей). Контраст «крупный tight heading ↔ мелкий разреженный mono-label» = мгновенный сигнал зрелого инструмента. Ваш max-w 1680px для канбана ок, но для текстовых экранов держите узко.

## Notion
Notion ощущается дорого не за счёт декора, а за счёт жёсткой дисциплины «контент важнее хрома»: тёплая серая (не чёрная) типографика на тёплой бумаге, почти невидимые многослойные тени, hairline-границы вместо коробок, и весь интерфейс отступает на второй план, проявляясь только на hover. Премиальность создают четыре вещи: (1) контролируемая длина строки длинного текста + крупный body 16/1.55, делающий чтение спокойным; (2) единая шкала тёплых серых для иерархии текста — заголовок/тело/вторичное/disabled различаются цветом, а не только весом; (3) borders-first глубина и тени уровней 0.04/0.08-альфы, которые «приподнимают», а не «обводят»; (4) прогрессивное раскрытие — drag-handle, +, кнопка Open появляются только при наведении, поэтому в покое экран выглядит как чистый документ. База данных и документ — это один и тот же визуальный язык: строки таблицы по плотности и ритму неотличимы от строк текста, а свойства-теги — единственное цветное пятно, и то приглушённое-пастельное. Это ровно совпадает с нашим направлением «плотный рабочий инструмент», но Notion показывает, как сделать плотность не тесной, а спокойной.
- [типографика длинного текста] Тело документа — 16px / line-height 1.55, weight 400; заголовки идут одной семьёй весом 600 с отрицательным letter-spacing (H1 ~ -0.5px, дисплей до -2px) и убывающим line-height (1.55 body → 1.30 на крупных заголовках). Серифа почти нет — только редкие pull-quote. Иерархия строится цветом тёплых серых, а не сменой гарнитуры.
    → В редакторе тезисов /meetings/[uid] поднять тело с 15/24 до 16/26 (1.55) — у нас iOS-исключение уже 16px, распространить на десктоп-чтение. В @theme добавить --tracking-tight: -0.011em и вешать на --text-lg/xl/2xl (Golos под кириллицу хорошо тянет negative tracking на крупном кегле, на body — НЕ ставить). Заголовки тезисов оставить Golos 600, line-height ужимать к 1.25 от --text-xl и выше. Markdown-просмотр: h1/h2/p получают этот же ритм через prose-класс, а не дефолт shadcn.
- [цвет (тёплая серая шкала текста)] Notion различает 5+ уровней текста тёплыми серыми, не оттенками чистого серого: Charcoal #37352f (основной), Slate #5d5b54 (вторичный), Steel #787671 (третичный/мета), Stone #a4a097 (muted), Muted #bbb8b1 (disabled). Чёрный (#1a1a1a) — только для самого важного. Это и есть «дорогое» ощущение чтения.
    → У нас сейчас только --foreground и --muted-foreground — двух уровней мало для документа. Добавить промежуточные токены: --text-secondary (oklch ~0.42 0.012 90) для подзаголовков/лидов и --text-tertiary (oklch ~0.55 0.012 90) для мета/подписей, между нашими 0.215 и 0.50. Hue держать 90 (тёплый) — это уже совпадает. В редакторе тезисов: тело --foreground, выноски/курсивы --text-secondary, подписи под блоками mono --text-tertiary. Так длинный тезис читается слоями без жирного веса.
- [ритм отступов / плотность] Жёсткий 4px-базис, но рабочий инкремент 8px; крупные пробелы между секциями (48/64px) при тесных внутри блока (4/8/12px). Плотность строки таблицы = плотности строки текста: БД и документ ощущаются одним полотном. Карточки дышат: padding 24–32px внутри при 12px радиусе.
    → Наш ритм (4/8 внутри, 12 связанное, 24 секции, 32/48 зоны) уже notion-совместим — зафиксировать его как токены --space-* в @theme, чтобы не хардкодить. Ключевой перенос: строка Базы знаний (36px) и строка тезиса в редакторе должны жить на ОДНОЙ вертикальной сетке — одинаковый left-padding контента (предлагаю 12px gutter под иконку/handle), чтобы при переходе список→документ глаз не прыгал. Карточкам задач на доске дать внутренний padding 12–16px (не 8) — сейчас канбан рискует быть тесным.
- [строки / hover (прогрессивное раскрытие)] В покое строка таблицы Notion — голый текст на hairline-сетке, ноль кнопок. НЕ растягивать на весь экран, центрировать в контент-зоне с padding 48px. Для пустого семантического поиска — подсказка «поиск понимает смысл» (она уже в спеке) именно как empty-state, а не placeholder.

Активная строка — подложка --accent-soft (не яркий --accent), без рамки. Лейблы-подсказки справа (статус встречи, дата) в mono --text-xs приглушённо. Семантический поиск Базы — отдельная группа «Результаты по смыслу» с пометкой релевантности. Дублировать крупное поле поиска Базы и в ⌘K — как у Notion единый объект.
- [движение / анимация] Движение Notion почти незаметно и служебно: hover-проявление контролов и подложек ~100–150ms ease, открытие поповеров/превью лёгким fade+scale, без подпрыгиваний и bounce. Анимируются opacity/transform, layout не дёргается. Ощущение «отзывчивого, но спокойного».

Page-preview на hover ссылки (как у Notion link-preview) — отложить, но заложить паттерн: fade-in 120ms для будущих превью записей Базы. Уважать prefers-reduced-motion (наш web/performance.md).
- [data-viz / статусы как система] Notion трактует статус/прогресс не как отдельный график, а как часть системы свойств: статус-точки и progress-бары используют ту же приглушённую палитру свойств, единый радиус и плотность. Никаких чужеродных ярких чартов — визуализация наследует токены интерфейса.
    → Наши четыре статус-цвета (done/progress/pending/danger) — уже единая система на 3 поверхности, это правильно. Усилить: progress-индикаторы (обработка тезисов, загрузка STT-модели в агенте) рисовать в --accent (мёд) или статусном цвете с теми же L/C, что пилюли — не вводить новый яркий цвет. Граф знаний/задач: рёбра и узлы красить из той же детерминированной hue-палитры рынков (C ~0.04), фон --surface-sunken — чтобы граф читался как продолжение интерфейса, а не embed сторонней библиотеки. Пульсирующая синяя точка «готовим тезисы» — единственное допустимое «живое» движение, держать его.

## Granola (с дополнениями из Fellow и Amie) — страница встречи / редактор заметок: транскрипт + AI-тезисы + правка
Дорогим Granola делает не декор, а одно радикальное продуктовое решение, доведённое до пиксельного дисциплинированного исполнения: документ-холст вместо «дашборда». Экран встречи — это один чистый текстовый документ как Apple Notes / Google Docs (нулевая кривая обучения), а вся AI-механика спрятана за «невидимым дизайном» (как невидимые перила: их не видно, пока не понадобятся). Ключевой приём — цвет как единственный носитель смысла авторства: пользовательские заметки чёрным, AI-дополнения серым, и каждый AI-буллит несёт ссылку-якорь в точную точку транскрипта (верифицируемость встроена в типографику, а не вынесена в отдельную панель). Спокойствие интерфейса (тёплая, приглушённая зелёная система, слаб-сериф Quadrant для дисплея + нейтральный UI-шрифт Melange, «нарочито несовершенный» рисованный логотип) намеренно контрастирует с гонкой back-to-back встреч — это и есть ощущение зрелого инструмента. Редактирование тезисов идёт разговором (Granola Chat по ⌘J с inline-цитатами обратно в транскрипт), а не модалками и формами.
- [иерархия / авторство через цвет] Главное решение Granola: различие «человек vs AI» кодируется ТОЛЬКО цветом текста внутри одного документа — пользовательские заметки чёрным (foreground), AI-сгенерированные тезисы серым (muted-foreground), без рамок, бейджей и отдельных карточек. Это делает гибридный документ читаемым как единое целое и одновременно честным про происхождение каждой строки.
    → В редакторе /meetings/[uid] не делить тезисы и пометки на разные карточки. Рендерить один markdown-документ: блоки, пришедшие из user_notes — `text-foreground`, AI-тезисы — `text-muted-foreground`. У нас уже есть `--foreground oklch(0.215)` и `--muted-foreground oklch(0.50)` — контраст ~достаточный. Добавить data-атрибут `data-origin="human|ai"` на узлы редактора и в Tailwind `[&[data-origin=ai]]:text-muted-foreground`. Это заменяет идею двух аккордеонов «тезисы отдельно, пометки отдельно» на один связный холст; аккордеон транскрипта оставить ниже.
- [верифицируемость / связь с транскриптом] Каждый AI-буллит несёт inline-якорь (иконка-лупа) → клик прыгает в точную точку транскрипта/сырых заметок, откуда взята мысль. Цитаты в Granola Chat тоже inline-ссылочные, двойной клик ведёт в оригинал. Доверие к AI решается не дисклеймером, а one-click аудитом прямо в строке.
    → К каждому AI-тезису привязать таймстамп-якорь. В конце строки тезиса — тихая mono-кнопка `[12:34]` (JetBrains Mono, text-xs, muted), `opacity-0 group-hover:opacity-100 transition-opacity`. Клик: `scrollIntoView` к сегменту транскрипта (id=`seg-12-34`) + кратковременная подсветка `bg-accent-soft` на 1.2s через `transition-colors`. Поскольку наш транскрипт уже сегментирован с mono-таймстампами `[12:34]` в колонке 64px — якорь у нас естественный, надо только связать id. Это превращает аккордеон «Транскрипт» из мёртвого приложения в навигируемый источник.
- [лейаут / документ-холст] Экран — это документ, а не дашборд: центральная текстовая колонка как Notes/Docs, минимум хрома. Во время встречи — dual-pane (слева блокнот пользователя, справа живой транскрипт); после встречи всё схлопывается в единый enhanced-документ. Управляющие элементы (выбор шаблона ✨ справа-вверху, регенерация 🔁, возврат к сырым заметкам ☰) — мелкие иконки по краям, не панель инструментов.
    → Подтвердить наш план «документ + рельса», но усилить: центральная колонка ≤760px (~70ch) должна выглядеть как чистый документ — убрать любые рамки/карточки вокруг тела тезисов, фон `--surface`, оставить только hairline-разделители секций. Действия (шаблон, перегенерация, режим Правка/Просмотр) — компактным рядом icon-кнопок shadcn `Button variant="ghost" size="icon"` в правом верхнем углу колонки, а не широкой тулбар-полосой. Опасные действия (перегенерировать/удалить) убрать в правую рельсу, как и запланировано.
- [командная палитра / правка разговором] Правка тезисов в Granola — это разговор, а не форма: Granola Chat (⌘J/Ctrl+J) принимает инструкции «сделай раздел next steps детальнее», «переставь хронологически», «Niall пишется Nyal», «£4.5m → £3.5m». Чат живёт как единый объект и над одной встречей, и над папкой/всей библиотекой; ответы с inline-цитатами.
    → У нас уже запланирована ⌘K (cmdk) для поиска/навигации. Добавить второй разговорный режим: ⌘J открывает чат-панель ПОВЕРХ текущей встречи (shadcn Sheet справа на десктопе шириной ~360px / bottom-sheet на мобиле), скоупленный на текущий [uid]. Инструкции редактирования идут на наш GPT-4o-эндпоинт тезисов с контекстом транскрипта. Ответы-цитаты рендерить с теми же mono-якорями `[12:34]`, что и тезисы — переиспользуем компонент якоря из предыдущего пункта. Это снимает потребность в формочках правки и держит «один способ говорить с системой».
- [типографика] Granola намеренно ушла от дефолтного гротеска: дисплей — Quadrant (слегка механический слаб-сериф), UI — Melange (нейтральный, но с характером). Пара «сериф для крупного + нейтральный для тела» даёт редакционную дороговизну, при этом тело остаётся спокойным и читаемым на длинных документах.
    → У нас Golos Text (UI) + JetBrains Mono (мета). Чтобы уйти от «стандартного shadcn-вида» без смены кириллических шрифтов: ввести характерный дисплейный вес/начертание для крупных заголовков (название встречи `--text-xl`, h1 `--text-2xl`) — Golos на 750/800 с чуть отрицательным `letter-spacing: -0.02em` и плотным интерлиньяжем, тело тезисов оставить 15/24 спокойным. Mono уже играет роль «механического акцента» Granola для метаданных. Не добавлять третью гарнитуру — характер берём весом и трекингом, как и заявлено в нашей доке (иерархия весом, не сменой гарнитуры).
- [цвет] «Мы оставили зелёный, но дали ему нормальную систему» — один фирменный hue, систематизированный в шкалу, а не разбросанный. Цвет работает семантически (авторство текста, статус), интерфейс в основном ахроматичен и спокоен; бренд-зелёный — точечный акцент, не заливка.
    → Прямое подтверждение нашей линии: медовый `--accent` только на primary-действиях/активной навигации, всё тело — тёплая ахроматика. Конкретный перенос: на странице встречи НЕ красить тезисы в медовый; медовый зарезервировать под (1) активную подсветку якоря при прыжке в транскрипт (`--accent-soft`), (2) sticky-бар «Сохранить ⌘S». Статус встречи (янтарный→зелёный) — единственная цветная точка в шапке. Это держит документ спокойным, а энергию — «под спудом».
- [плотность / ритм отступов] Спокойствие Granola — это щедрый воздух вокруг текстовой колонки при высокой смысловой плотности самого контента (буллеты по темам, без воды). Density достигается структурой контента (короткие тематические буллиты), а не уплотнением вёрстки. «Calm, but energy underneath».
    → Нюанс к нашей доке «плотный рабочий инструмент»: списки/доски держим плотными (строки 36px), но САМ редактор тезисов должен дышать — это документ для чтения и правки. В центральной колонке увеличить вертикальный ритм: между тематическими секциями тезисов 24px, межстрочный 24px на 15px-теле, маркеры списка тонкие. Плотность переносим на левую панель встреч и правую рельсу метаданных, не на тело документа. Два разных режима плотности на одном экране — это и есть зрелость.
- [дизайн строк / список встреч] Granola авто-организует заметки по отношениям — левый сайдбар группирует по компаниям, людям и командам, а не просто хронологический список файлов. Контекст («с кем встреча») — первичная ось навигации.
    → У нас левая панель 380px группирует по датам. Добавить второй режим группировки (segmented control «По датам · По людям») — группировка по участникам встречи (резолв telegram ID → имя, у нас уже есть хелпер). Строка встречи остаётся плотной: статус-точка + название 13/600 + mono `14:00 · 47 мин · HU RS`. Группировка по людям делает повторяющиеся 1:1 находимыми так же, как у Granola, и переиспользует наш аватар-атом из /users.
- [пустые состояния / состояния обработки] Во время встречи Granola показывает буквально пустой блокнот — никакого бота, никакого AI-шума, только курсор: «invisible design». Enhanced-тезисы появляются ПОСЛЕ, по явному действию «Enhance notes»; до этого AI не маячит. Обработка — спокойный фоновый процесс, а не спиннер во весь экран.
    → Для `summary_status: processing` не делать тяжёлый прелоадер. Показать скелетон строк тезисов цветом `--surface-sunken` + тихую mono-подпись «Готовим тезисы…» с одной пульс-точкой `--status-progress`, авто-поллинг — ровно как в доке, но подчеркнуть СПОКОЙСТВИЕ: никакой прогресс-бар во всю ширину. Пустой редактор (встреча без тезисов/только сырые заметки) — показывать сами user_notes как полноценный документ-холст, а не пустую плашку «нет данных». Кнопка «Сгенерировать тезисы» — ghost, не кричащая.
- [движение] Метафора «невидимых перил»: движение появляется только в момент нужды (прыжок к цитате, появление enhanced-текста), а не как постоянная анимация. AI-текст «проявляется» под пользовательским, переход от блокнота к структурированному виду — мягкий, без резких перестроений.
    → Только compositor-friendly, 120–150ms (как в доке). Конкретно: (1) при прыжке к транскрипту — `transition-colors` подсветка `--accent-soft` затем плавное угасание; (2) при появлении AI-тезисов после генерации — `opacity` + лёгкий `translateY(4px)` fade-in последовательно по секциям (stagger ~40ms), не одномоментный flash; (3) sticky-бар «Сохранить» — `translateY` slide-in только при наличии изменений. `prefers-reduced-motion` отключает всё кроме мгновенной смены состояния.
- [data-viz / структура контента] Granola трактует сам тезис как структуру данных: дефолтно — буллеты по темам (bite-sized), плюс типизированные секции по шаблону (Решения, Задачи с исполнителями, Открытые вопросы, Цитаты). Шаблон под тип встречи (1:1 vs командная vs клиент) — это и есть «data-viz» заметок. tl;dv/Fellow аналогично: summary + suggested action items + decisions как отдельные типизированные блоки.
    → Рендерить тезисы не как сплошной markdown, а по типизированным секциям нашего командного шаблона с лёгкими mono-заголовками секций (uppercase, text-xs, muted, letter-spacing). Секция «Задачи» — каждая строка со статус-точкой + резолв-исполнителем (переиспользуем атом задачи), кнопка «Обновить задачи из тезисов» уже в плане. Раздел тезисов = редактируемый, секция задач = связана с нашей таблицей tasks. Это делает страницу встречи не текстом, а структурированным источником задач/решений — наша киллер-фича поверх Granola, у которой задачи в задачи-трекер не уезжают.
- [режим правки / контроль пользователя] Пользователь полностью владеет документом: «вы контролируете, что остаётся и что удаляется». Регенерация шаблона не трогает другие встречи (каждая обрабатывается независимо/идемпотентно), а ручная правка имеет приоритет — это и UX-, и доверие-решение.
    → Прямо ложится на наш контракт `notes_edited_at != null → сервер не перезаписывает`. UX-перенос: после ручной правки переключать визуальный маркер тезиса с серого (AI) на чёрный (human-owned) — как только человек тронул AI-строку, она становится «его», цвет меняется. Перед «Перегенерировать тезисы» — confirm-поповер «Затрёт текущий текст» (в доке есть). Сегментед-контрол «Правка/Просмотр» (в доке) — оставить, это эквивалент тоггла enhanced/raw у Granola (☰).

## Vercel Dashboard (Geist design system) + Stripe Dashboard (card-less redesign 2025-2026)
Оба продукта читаются «дорого» не из-за украшений, а из-за дисциплины: предельная сдержанность цвета (Geist почти не использует цвет вне нейтралей, акцент — как пунктуация; Stripe держит ровно одну заливную CTA-пилюлю на блок), один-два гарнитуры с табличными цифрами для всех чисел, и хайрлайн-границы вместо теней и «надувных» карточек. Stripe в редизайне сознательно убил карточки: тяжёлые тени и крупные скругления буряли информацию и мешали ставить данные рядом — вместо них пришли жирные секционные заголовки, плотные таблицы и «голые» области, где графики дышат. Vercel строит весь UI на 10-ступенчатой нейтральной шкале с фиксированными ролями ступеней (1-3 фон/hover/active, 4-6 границы, 9-10 текст), что даёт идеально предсказуемую глубину без хаоса теней. Премиальность здесь = математически выверенный ритм отступов на базовой сетке (Stripe: 8px-база, дашборд-паддинги 32-48px против 64-96px на маркетинге), отрицательный трекинг на крупных кеглях, статус, прорастающий до иконки вкладки браузера, и графики/таблицы как часть дизайн-системы, а не довесок.
- [Цвет / дисциплина акцента] Geist почти не выходит за нейтрали; синий #0070f3 = «пунктуация» (одна точка фокуса на экран). Stripe держит ровно ОДНУ заливную CTA-пилюлю (#533afd) на смысловой блок, остальные акцентные цвета (ruby/magenta) живут ТОЛЬКО в графиках и иллюстрациях, не в кнопках. Это и есть «дорого»: глаз сразу видит единственное главное действие.
    → Аудит на правило «один медовый акцент на видимую зону»: --accent (oklch 0.72 0.135 78) только для одной primary-кнопки в хедере и активной навигации. Все вторичные действия — variant="ghost"/"outline" на нейтралях. Статусные цвета (--status-*) НЕ использовать для кнопок — только для точек/бейджей и серий в data-viz. Завести правило в design-quality чек-лист: если на экране >1 заливного акцента — это баг.
- [Поверхности / глубина (borders-first)] Geist кодирует ВСЮ глубину 10-ступенчатой нейтральной шкалой с жёсткими ролями: ступени 1-3 = фон компонента/hover/active, 4-6 = граница/hover-граница/active-граница, 7-8 = high-contrast фон, 9-10 = вторичный/первичный текст. Тени почти не используются. Stripe в редизайне выпилил «heavy shadows and rounded card edges» — глубина теперь через hairline #e3e8ee и группировку, не через тени.
    → У вас уже borders-first (хорошо) — но формализуйте по Geist в @theme: добавить шаговую нейтральную шкалу --gray-1..--gray-10 (oklch, hue 90) и переопределить --surface=gray-1, hover=gray-2, --border=gray-4, --border-strong=gray-5, --muted-foreground=gray-9, --foreground=gray-10. Тогда hover/active/border берутся из шкалы детерминированно, а не подбираются на глаз. Тени оставить ТОЛЬКО на поповерах/шитах/⌘K (ваш ур.2), у карточек и строк — никогда.
- [Карточки → плотные секции (card-less)] Главный вывод редизайна Stripe: карточки «занимают слишком много места, нельзя поставить рядом, важное буряется». Решение — card-less: жирные секционные заголовки + reduced visual noise + области, где графики/таблицы идут встык без рамок. Данные стоят рядом и сравниваются, а не разнесены по «коробкам».
    → Для дашборд-поверхностей (Задачи-обзор, страница встречи правая рельса, Команда) уходить от Card с border+padding к секциям: <section> с заголовком Label-13/600 uppercase tracking, тонкий divider (--border) сверху, контент встык. shadcn Card оставить только для реально автономных сущностей (карточка задачи в канбане). В метаданных встречи (рельса 280px) — не оборачивать каждую группу в Card, а делать definition-list с hairline-разделителями.
- [Типографика / шкала] Оба используют 1 UI-гарнитуру + mono, иерархию задают весом и РАЗМЕРОМ, не сменой шрифта. Geist: токены названы по px (Heading 14-72, Copy 13-24, Label 12-20). Stripe: отрицательный трекинг — фирменный приём, масштабируется от -1.4px@56px до -0.2px@20px; на крупных заголовках тонкий вес 300. Числа везде — табличные (tnum).
    → Ваша шкала --text-xs..2xl уже плотная и правильная. Два дополнения из Stripe: (1) добавить отрицательный letter-spacing на крупные кегли — --text-xl/2xl: tracking ≈ -0.01em..-0.02em (Golos на больших размерах станет «дороже», собраннее); базис 13px оставить tracking 0. (2) Включить font-feature-settings: 'tnum' 1 на ВСЕХ числовых местах через класс на JetBrains Mono (даты, длительности, счётчики, дедлайны) — добавить utility .nums { font-variant-numeric: tabular-nums }. Это «тихий финансовый сигнал» Stripe, ровные колонки цифр в списках.
- [Ритм отступов] Stripe: база 8px, но дашборд-плотность отдельно от маркетинга — секционные паддинги 32-48px на дашборде против 64-96px на лендинге. Шкала 2/4/8/12/16/24/32/64. Неравномерный ритм: внутри строки тесно, между секциями просторно — это и создаёт сканируемость.
    → У вас уже описан неравномерный ритм 4/8/12/24/32-48 — выдержать его буквально через токены, а не ad-hoc Tailwind-классы. В @theme задать --space-section: 24px (между секциями внутри панели), --space-zone: 32px (между зонами экрана), --space-inline: 8px. Запретить себе p-6/gap-6 «на глаз»: внутристрочные отступы 4/8, между связанными блоками 12, между секциями 24. Контент-зона ≤1680px (у вас есть) с горизонтальным паддингом 32px на десктопе.
- [Дизайн строк / таблиц] Премиум-таблица Stripe: 14px tnum с трекингом -0.42px, hairline-разделители, никаких зебра-полос и рамок ячеек. Vercel: строка деплоя = иконка статуса + название + mono-метаданные + действие справа, hover поднимает фон на одну ступень (gray-2). Плотность высокая, но за счёт воздуха в типографике не давит.
    → Строки списков (Встречи, База, задачи в рельсе): фиксированная высота 36px desktop, grid с выровненными колонками, hover = --surface-sunken (одна ступень), разделители — никаких, либо только hairline снизу. Числовые/mono-колонки (время, длительность, дедлайн) — табличные цифры + выравнивание по правому краю, чтобы колонка читалась вертикально. Статус-точка слева 6-8px как первый якорь сканирования. Действие (e/Enter) — появляется по hover справа, не висит постоянно.
- [Пустые состояния] У зрелых дашбордов пустое состояние — спроектированный экран, а не «нет данных»: иконка/иллюстрация в нейтралях, короткий заголовок, одно предложение пользы, ОДНА primary-кнопка действия. Vercel в пустом проекте сразу даёт next-step (подключить repo). Никаких центрированных серых заглушек.
    → Сделать переиспользуемый <EmptyState icon title description action />: lucide-иконка 32px в --muted-foreground, заголовок Label-13/600, описание --text-sm/muted, одна медовая кнопка. Конкретно: Встречи пусто → «Записей пока нет» + «Агент запишет первую встречу автоматически». База пусто по фильтру → «Ничего не найдено» + кнопка «Сбросить фильтры». Задачи-колонка пусто → тонкая пунктирная зона с «Перетащите сюда». Ни одного голого «No data».
- [Loading-состояния] Премиум-ощущение даёт скелетон, повторяющий РЕАЛЬНУЮ геометрию контента (та же высота строки, та же сетка колонок), а не спиннер по центру. Stripe/Vercel показывают каркас списка/графика мгновенно, данные доезжают на месте — нет layout shift (CLS≈0).
    → Сделать Skeleton-варианты под каждую поверхность с точной геометрией: список встреч = 6 строк по 36px со скелетон-блоками на месте точки/названия/mono-строки; страница встречи processing = уже есть «Готовим тезисы…» с пульс-точкой — расширить на скелетон абзацев центральной колонки ≤760px. Skeleton через CSS-анимацию opacity/background (compositor-friendly), без JS-спиннеров. Резервировать высоту, чтобы не было сдвига при загрузке.
- [App-shell / сайдбар] Vercel-редизайн: резайзный сайдбар, сворачивается чтобы любой вид шёл на весь экран; единая навигация с одинаковыми пунктами на уровне команды и проекта; на мобиле — плавающий нижний бар для одной руки. Статус деплоя пробрасывается аж в favicon вкладки (queued/building/error/ready).
    → Ваш каркас (сайдбар 240px → рельса 56px, нижний таб-бар на мобиле) точно совпадает с направлением Vercel — это валидирует выбор. Добавить из Vercel: (1) статус в title/favicon вкладки — когда встреча в обработке, менять favicon на «обрабатывается» (у вас уже есть состояния агента сота→галка, перенести в веб-favicon). (2) Сворачивание сайдбара должно отдавать ширину контенту мгновенно (CSS-переход grid-template-columns, не ремоунт). (3) Счётчик непросмотренных у «Встречи» — как у Vercel бейджи в навигации, на --accent.
- [Командная палитра ⌘K] Для dev-аудитории ⌘K — главный сигнал «инструмент, а не сайт». Vercel/Linear-школа: палитра объединяет поиск + навигацию + действия, mono-хоткеи показаны прямо в строках меню, недавнее наверху. Скорость клавиатуры = ощущение мощного продукта.
    → У вас ⌘K на cmdk запланирован — сделать его first-class: секции «Перейти» (роуты), «Действия» («Новая задача» c, «Подтвердить встречу»), «Поиск по базе» (ваш семантический endpoint, debounce). Справа в каждой строке — mono-хоткей в стиле --text-xs. Открытие — мгновенное (предзагрузить cmdk). Дублировать туда крупное поле поиска базы знаний. Это закрывает «главный жест скорости» из вашей же доки и ровно повторяет Vercel/Stripe-паттерн.

    → Зафиксировать в токенах: --duration-fast: 120ms, --duration: 160ms, --ease: cubic-bezier(0.16,1,0.3,1). Анимировать только переход статус-точки (color/opacity), раскрытие drawer/sheet (transform: translateX/Y), hover строк (background). Запретить scale на hover карточек и кнопок. prefers-reduced-motion → мгновенно. Пульс «готовим тезисы» — только opacity-анимация точки.
- [Data-viz как часть системы] Stripe: «layouts that let charts shine», числа всегда с контекстом (не «$2100», а источники+тренд); акцентные цвета зарезервированы под серии графиков. Графики — не довесок, а спроектированы в той же палитре/сетке. Geist даёт под это отдельные цветовые шкалы (blue/amber/green/teal/purple/pink).
    → Для Задач-обзора/Спринта и статистики базы: строить мини-charts (Recharts или чистый SVG) строго на --status-* и нейтралях, сетка/оси — --border, подписи — JetBrains Mono табличные. Никаких градиентов и 3D. Каждое число давать с контекстом: «12 открытых» + дельта/спарклайн, а не голая цифра. Цвета серий брать из детерминированной палитры рынков (ваш hash(code)%360) — тогда HU/RS/ME в графике совпадают по цвету со своими пилюлями в списках. Это и есть «единая система», а не случайные цвета чартов.

## Raycast + Superhuman (этос внутреннего инструмента: скорость, клавиатура, ⌘K, плотный-но-спокойный UI)
«Дорогими» эти два продукта делает не декор, а инженерия восприятия скорости и дисциплина в мелочах. Superhuman продаёт не функции, а отклик: внутренний бюджет 50-60мс на любое действие, оптимистичный UI (действие визуально завершается ДО ответа сервера, undo вместо спиннеров), вим-навигация (J/K вверх-вниз, E/R/C/Z действия) и ⌘K, который намеренно «выпускает» пользователя — показывает хоткей при каждом вызове, пока не сформируется мышечная память. Raycast — это абсолютная типографическая и тональная дисциплина: ОДИН шрифт (Inter+ss03) от 11 до 64px, отрицательный трекинг на крупном и положительный на мелком (метаданные читаемы при 11px), глубина строится ТОЛЬКО лестницей поверхностей и hairline-бордерами 1px (ноль drop-shadow на хроме), белая «таблетка» зарезервирована под единственное primary-действие, а цвет-акцент живёт только в иллюстрациях, не на интерфейсе. Оба продукта спокойны при высокой плотности: непрочитанное — это 3px левый бордер, а не заливка фона; ряд = жёсткая иерархия веса (отправитель 600 / тема 500 / превью muted / таймстамп mono). Воспроизводимо у нас почти полностью — это вопрос токенов и дисциплины, а не сложного кода.
- [командная палитра ⌘K] Raycast/Superhuman: палитра намеренно «visually imposing» — по центру, перекрывает значимую часть экрана; ряд команды = иконка слева + название + matching-alias в скобках + keycap-хинт хоткея справа; последний видимый ряд НАМЕРЕННО обрезан, чтобы намекнуть «есть ещё ниже». Ранжирование: fuzzy-score 0..1 с порогом отсечки (~0.0015), у каждой команды базовый score (важные подсвечены, редкие = 0) + scale-множитель + контекст-буст (в открытой встрече подняты «Подтвердить/Перегенерировать»).
    → В нашем cmdk-диалоге (шаг 6 миграции): CommandDialog ширина max-w-[640px], по центру, overlay bg-black/40. Ряд CommandItem h-44px, px-3, grid [auto_1fr_auto]: lucide-иконка 16px (muted-foreground) — текст-команда text-base/13px — справа keycap-хинт. Keycap-компонент по спеку Raycast: bg-surface-card (var --surface-raised), 1px border, radius-4px (--radius-sm), px-1.5 h-5, font JetBrains Mono 11px. Высоту списка задать так, чтобы 5-й ряд обрезался (max-h ~= 5.5*44px overflow-hidden). Секции через CommandGroup: «Недавнее» сверху (последние 3 действия из localStorage), «Переход», «Действия», «Поиск по базе» (наш searchEntries с debounce). Контекст-буст: на /meetings/[uid] подмешивать команды «Подтвердить встречу», «Перегенерировать тезисы» с приоритетом.
- [перцептивная скорость / оптимистичный UI] Superhuman: бюджет 50-60мс на отклик; действие завершается визуально ДО ответа сервера, фокус сразу уходит на следующий элемент, фоновый sync асинхронно; спиннеров/диалогов подтверждения нет — страховка через undo (Z) с тостом и 5-сек обратным отсчётом. Архив = строка уезжает вправо 150мс, следующая всплывает на её место. Анимация НЕ блокирует — это пост-действенный визуальный «доводчик».
