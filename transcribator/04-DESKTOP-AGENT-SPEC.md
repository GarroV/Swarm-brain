# 04 — Desktop Agent: форк anarlog

База: `github.com/fastrepl/anarlog` (MIT). Tauri-приложение, Rust + TypeScript монорепо, модульная плагинная архитектура. Документация по коду: deepwiki.com/fastrepl/anarlog.

## 0. Первый шаг — разведка (до любого кода)

1. Склонировать, собрать как есть (`pnpm install`, цепочка сборки по их README), запустить.
2. Провести тестовый созвон на русском с дефолтными настройками → оценить качество транскрипта.
3. Проверить и зафиксировать в `RECON.md` ответы на вопросы:
   - Какая STT-модель дефолтная? Есть ли пикер моделей? Как указать свою (URL/файл GGUF)?
   - Умеет ли пайплайн режим «запись в файл → batch-транскрибация после» или только стриминг? (смотреть plugin-local-stt, listener store, hypr-audio)
   - Где событие «встреча закончилась» (детект по календарю/аудиоактивности)?
   - Где в коде заметка финализируется (точка для POST в рой)?
   - Какие плагины регистрируются в `apps/desktop/src-tauri/src/lib.rs` — что можно не подключать?
   - Формат хранения: где лежат markdown/SQLite, как достать сегменты с таймстампами?
   - Как у них устроены пометки во время встречи — есть ли таймстампы строк?

## 1. Что оставляем / что выпиливаем

| Оставить | Выпилить / не регистрировать |
|---|---|
| plugin-calendar (детект встреч) | Chat & AI Task System |
| Захват аудио (hypr-audio, system+mic) | plugin-local-llm (LLM на клиенте не нужен) |
| plugin-local-stt + модель large-v3-turbo q5 | Полнотекстовый поиск (tantivy) — поиск живёт в рое |
| Окно быстрых пометок во время встречи | Templates & Contacts |
| plugin-notification | Облачные STT-провайдеры (owhisper-client) — опционально оставить как fallback |
| Onboarding (разрешения macOS) | Большой редактор сессий (правка — в вебе) |
| **plugin-swarm (пишем сами)** | Sidebar/табы — упростить до минимума |

Принцип выпиливания: в первую очередь НЕ регистрировать плагины в bootstrap, а не удалять код — меньше конфликтов при ребейзе на апстрим.

## 2. Наш плагин: plugin-swarm

Rust Tauri-плагин + минимальный TS-фасад. Обязанности:

1. Подписка на событие «заметка финализирована / встреча закончилась + транскрипт готов».
2. Сборка payload по `02-API-CONTRACT.md`: meeting_id (uuid при старте записи), метаданные из календаря, segments с таймстампами, user_notes с ts.
3. POST с Bearer-секретом из конфига.
4. Локальная очередь (SQLite-таблица или JSON-файл): статусы pending/sent/failed, retry с бэкоффом (1м, 5м, 15м, 1ч, 6ч), переживает перезапуск.
5. По успеху → нотификация «Тезисы готовы» с deep link на `web_url` из ответа.
6. Меню-бар: индикатор статуса (записываю / транскрибирую / отправлено / ошибка), кнопка «переотправить последнюю».

## 3. Режим записи (ключевое требование)

- Во время встречи: ТОЛЬКО запись аудио в файл (WAV/FLAC) + окно пометок. Никакой транскрибации в реалтайме (экономия RAM на M1/8ГБ — во время звонка свободной памяти мало).
- По окончании: запуск Whisper по файлу. Если в anarlog batch-режим есть — используем; если только стрим — патчим: писать файл, по событию конца скармливать его plugin-local-stt.
- Аудиофайлы: `~/Library/Application Support/SwarmAgent/recordings/`, ротация — автоудаление старше 7 дней.

## 4. Конфиг (запекается в pkg)

```jsonc
// ~/Library/Application Support/SwarmAgent/config.json (кладётся postinstall-скриптом pkg)
{
  "ingest_url": "https://<ref>.supabase.co/functions/v1/meeting-ingest",
  "agent_secret": "<SWARM_AGENT_SECRET>",
  "web_base_url": "https://<webapp>",
  "stt_model": "large-v3-turbo-q5",
  "language": "ru",
  "recordings_retention_days": 7,
  "owner_telegram_id": null   // null → агент спросит при первом запуске (поле ввода)
}
```

Пользователь настройки не трогает. Единственный ввод при онбординге — свой Telegram ID (или выбор себя из списка команды, который агент тянет с сервера).

## 5. STT-модель

- Дефолт: `whisper large-v3-turbo`, квант q5 (~600 МБ файл, ~1 ГБ RAM, Metal на Apple Silicon).
- Скачивается при первом запуске (показывать прогресс в онбординге).
- Если качество русского недостаточно по итогам разведки — заложить в конфиг возможность указать альтернативный файл модели (русские файнтюны large-v3 с HuggingFace).
- На часовую встречу на M1 ожидаем единицы минут транскрибации. Если сильно дольше — проверить, что включён Metal, и что квант не f16.

## 6. Окно пометок

- Появляется при детекте начала встречи (вместе с началом записи), компактное, поверх окон, сворачивается в меню-бар.
- Plain text, каждая строка получает timestamp (секунды от начала записи) в момент начала ввода строки.
- Если в anarlog уже есть такие пометки с таймстампами — переиспользовать; наша задача только сериализовать их в `user_notes`.

## 7. Стратегия форка

- Форк → ветка `swarm`, пин на стабильный коммит апстрима, зафиксировать SHA в README форка.
- Все наши изменения: новый `plugins/swarm/` + правки bootstrap (регистрация плагинов) + конфиг. Чужие файлы трогаем по минимуму.
- Апстрим подтягиваем только ради: фиксов захвата звука под новые macOS, обновлений STT-движка. Ожидаемая частота — 1–2 раза в год.

## 8. Definition of Done агента (MVP)

- [ ] Встреча из календаря детектится, запись стартует сама, окно пометок появляется
- [ ] Во время часового звонка: RAM агента < 300 МБ, CPU незаметен
- [ ] После встречи: транскрипт (русский, приемлемое качество) готов ≤ 5 мин на M1
- [ ] POST доходит, при выключенном Wi-Fi — уходит после восстановления сети
- [ ] Нотификация со ссылкой открывает заметку в вебе
- [ ] Перезапуск агента не теряет неотправленные встречи
- [ ] Записи старше 7 дней удаляются
